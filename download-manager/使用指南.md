# 统一下载管理器 使用指南

把三个独立下载器（`e-download` / `fetech_xs` / `m3u-get-down`）统一到一个网页界面里管理：
在浏览器里填参数、看实时输出、查下载列表、校验与重下失败项。

**典型用法**：后端跑在 Mac 上，用 Windows（或手机）的浏览器通过局域网访问控制。

---

## 一、目录怎么放（重要）

四个目录**必须平级**放在同一个父目录下，管理器的配置里用的是相对路径（`../e-download` 这种），
这样 Windows 开发、Mac 部署都不用改配置。

```
Vibe_Coding/                 ← 父目录，名字随意
├─ download-manager/         ← 管理器
├─ e-download/
├─ fetech_xs/
└─ m3u-get-down/
```

> **关于 `m3u-get-down` 这个名字**
> 它原来的目录名是 `m3u-get&down`，`&` 在 shell 里是「后台执行」符号，
> `cd`、启动脚本、定时任务里都要额外转义，是个持续的踩坑源，**已在仓库里改名为 `m3u-get-down`**。
> 改名只影响目录名：代码内部用的包名是 `m3u_down`，项目根目录是用
> `Path(__file__).resolve().parent.parent` 自定位的，所以**改目录名不影响任何功能**。
> 管理器的默认配置（`backend/config.py`）与 `config.json` 也都已指向新名字。

## 二、部署到 Mac（从现有 Windows 环境迁移）

### 第 1 步：代码走 git，不要手工拷贝

在 Mac 上：

```bash
cd ~
git clone <你的仓库地址> Vibe_Coding
cd Vibe_Coding
```

目录名已经是 `m3u-get-down`，不需要再改名。

### 第 2 步：数据单独传输（不要进 git）

下载产物体积大（e-download 有几百 MB），**不要提交到仓库**。用 U 盘、网盘或
`scp`/`rsync` 单独搬这两个目录：

```bash
# 在 Windows 上把这两个目录传到 Mac（示例，按实际路径改）
scp -r "H:\Sharing\Vibe_Coding\Vibe_Coding\e-download\Download"  mac:~//Vibe_Coding/e-download/
scp -r "H:\Sharing\Vibe_Coding\Vibe_Coding\fetech_xs\Download"   mac:~/Vibe_Coding/fetech_xs/
```

搬完后目录结构应该是：

```
~/Vibe_Coding/
├─ download-manager/
├─ e-download/
│   └─ Download/            ← 24 个画廊搬到这里
├─ fetech_xs/
│   └─ Download/            ← 5 本书搬到这里
└─ m3u-get-down/
    └─ Download/            ← 视频产物（原本没有就新建）
```

> 不必搬 e-download 项目根目录下那 2 个画廊和旧的 `Download/` ——
> 管理器的扫描会**同时看**项目根目录与 `Download/` 两处，所以就算放在原处也能在列表里看到。
> 但为整齐起见，建议统一放进 `Download/`。

### 第 3 步：确认 Python

管理器零依赖，只要 Python 3.9+。你用 python.org 安装包装的 3.14.5 完全够用：

```bash
python3 --version        # 应显示 3.14.x
```

### 第 4 步：给三个下载器装依赖（它们各自需要）

```bash
python3 -m pip install requests beautifulsoup4 lxml ebooklib playwright pycryptodome pysocks yt-dlp
python3 -m playwright install chromium     # 视频下载器必需（嗅探/播放/批量）
brew install ffmpeg                        # 视频合并切片必需
brew install node                          # 仅 YouTube 需要（yt-dlp 的 JS 运行时）
```

> `yt-dlp` 仅「yt-dlp 下载」方式（B站 / YouTube 等）需要，但**建议直接装上**。
> 装完可在管理器的依赖自检里看到它。各下载器的依赖细节、以及“哪些东西要重装 /
> 哪些会自动重建”，见 `m3u-get-down/使用指南.md` §10「换机器 / 搬家清单」。

### 第 5 步：启动

见下面「三、怎么启动服务」的 Mac 部分（要点：`chmod +x start_server.command` 一次，之后 `./start_server.command` 或双击）。

启动后终端会打印访问地址，形如：

```
  访问令牌 : aLWlYGSLcA_7aAq8aNCWfTQmlnPouD-v

  浏览器打开下列任一地址（首次会带上令牌，前端会记住，之后直接输地址即可）：
    http://192.168.1.23:8765/?token=aLWlYGSLcA_7aAq8aNCWfTQmlnPouD-v
    http://127.0.0.1:8765/?token=aLWlYGSLcA_7aAq8aNCWfTQmlnPouD-v   (本机)
```

### 第 6 步：在 Windows 上访问

把上面那个 `http://192.168.1.23:8765/?token=...` 复制到 Windows 浏览器打开。
前端会把令牌存进 localStorage，**之后直接输 `http://192.168.1.23:8765` 即可，不会过期**。

**如果打不开**，按顺序排查：

1. Mac 和 Windows 是否在同一局域网；
2. macOS 防火墙：`系统设置 → 网络 → 防火墙`，允许 Python 接受传入连接
   （首次启动时系统一般会弹窗询问，选「允许」）；
3. 确认 Mac 的局域网 IP 确实是终端打印的那个：`ipconfig getifaddr en0`；
4. 端口被占用：终端会明确报错，用 `./start_server.command --port 9000` 换端口。

## 三、怎么启动服务

三种方式任选，**服务都在前台运行**：关掉那个终端窗口（或按 Ctrl+C）即停止服务。

### Windows

| 方式 | 怎么做 | 说明 |
|---|---|---|
| **推荐**：双击 | 在文件资源管理器里双击 `start_server.bat` | 最简单，不用敲命令 |
| 命令行 | `cd` 到 `download-manager` 后执行 `.\start_server.bat` | 注意前面的 `.\` 和 `.bat` 都不能省 |
| 直接用 Python | `py -3 -X utf8 server.py` | 跳过脚本，等价效果 |

> **为什么不能只敲 `start`？**
> 在 PowerShell 里 `start` 是内置命令 `Start-Process` 的**别名**，优先级高于同目录下的文件；
> PowerShell 也不会像 cmd 那样自动补全 `.bat` 扩展名。所以只敲 `start` 会被 PowerShell 抢走，
> 提示 `cmdlet Start-Process ... 请提供以下参数的值: FilePath:`，而不是运行 `start_server.bat`。
> **正确写法：`.\start_server.bat`**（`.\` 表示"当前目录"，`.bat` 也不能省）。
>
> 双击 `start_server.bat` 会打开一个控制台窗口并在其中运行服务。

### macOS

```bash
cd ~/Vibe_Coding/download-manager
chmod +x start_server.command      # 只需要执行一次（从 git 克隆时若已带执行位可跳过）
./start_server.command             # 或者直接在访达里双击 start_server.command
```

### 可用的启动参数

三个平台通用（`start_server.bat` / `start_server.command` / `server.py` 都支持）：

| 参数 | 作用 |
|---|---|
| `--port 9000` | 临时换端口（不改配置文件） |
| `--host 127.0.0.1` | 只允许本机访问，禁止局域网访问 |
| `--open` / `--web` | 启动后**自动在默认浏览器打开管理器**（地址已带令牌） |
| `--no-sleep-guard` | 本次不阻止系统休眠 |
| `--force` | 跳过「单实例检查」（仅供测试等特殊场景） |

例子：`.\start_server.bat --port 9000`、`.\start_server.bat --open`、`./start_server.command --no-sleep-guard`。

> `--open` 会在服务真正开始监听之后才打开浏览器，所以不会出现"浏览器先连、显示无法访问"。
> 它打开的固定是本机地址 `http://127.0.0.1:<端口>/?token=<令牌>`；无默认浏览器时只提示、不影响服务。

### 同一时间只能开一个管理器（单实例保护）

启动时会写一个锁文件 `data/server.lock`（记录 PID、端口、启动时间）。
**如果已经有一个管理器在跑，第二个会直接拒绝启动**并打印是谁占着：

```
[错误] 已有一个管理器在运行：PID 12345（0.0.0.0:8765，启动于 2026-09-24 23:10:02）
```

这不是多余的谨慎：两个实例各自维护内存任务表、却共享同一份 `data/tasks.json`，
**谁后存盘谁就把对方的记录覆盖掉**——实测丢过一个正在下载的任务记录，
界面上连「续跑」按钮都没了。所以：

- **想换端口再开一个？不行。** 端口不同也照样会被锁拦住（状态文件还是那一份）。
- **上次是崩溃/强杀结束的**（锁文件里那个 PID 已经不存在）：会自动判定为陈旧锁并接管，
  不用手工处理。
- **确实需要强行启动**（例如锁记录被误判）：删掉 `data/server.lock`，或加 `--force`。

### 停止服务

- 在运行服务的那个终端窗口按 **Ctrl+C**；或直接关闭该窗口。
- 正在下载的任务**不会被自动杀掉**：下次启动时管理器会提示存在遗留进程并可续跑
  （详见「七、自检与排查」里的相关问答）。

## 四、日常使用

> 也可以在网页上直接提交任务，不用切回这个页面 —— 见「**八、从网页一键提交任务（油猴脚本）**」。

### 三个标签页

| 标签页 | 用途 | 阶段 |
|---|---|---|
| 电子书（fetech_xs） | 下载小说 → 生成 EPUB | 两条命令一步到位 |
| E-Hentai 画廊 | 下载画廊图片 | 支持页码范围 |
| 视频（m3u-get-down） | 下载 m3u8 视频；**B站 / YouTube 等由 yt-dlp 自动接管**（v0.3.0） | 见下面「视频下载的各种方式」 |

每个标签页布局（v0.2.0 起，参考 qBittorrent / FDM）：

- **顶部粘性区**：顶栏（系统/依赖状态 + 配置/通知/退出）+ 标签栏 + 磁盘速度条，
  向下滚动时保持 pinned，不会消失。
- **左栏（主视觉）**：**任务与队列**（限高、可「展开」）+ **已下载的产物**（限高、可「展开」）。
- **右栏**：**新建任务**（参数 + 开始下载，常驻，最常用）+ **下载器配置** / **打开下载目录** 按钮 + 依赖自检。
- **下载器配置改为弹窗**：不再占页面空间；顶栏「⚙ 配置」或右栏按钮都能打开。

### 输出坞（底部实时输出）

页面底部固定一个输出坞（SSE 推送，不用刷新），**不遮挡上面的内容**：

- 默认是「小」高度（约 6 行）；点「展开输出」变「大」（约 55vh），再点收起。
- 发起任务时会自动切到该任务的页签并保持小高度，所以**开始下载后立刻就能看到有没有成功启动**。
- 每个任务一个页签，**最新的任务排在最左**（不用横向滚动就能看到、关掉最新那个）；
  **关闭页签的 `×` 在最左边**（v0.4.3），标签过长会用省略号截断（悬停看全文）。
  支持：跟随滚动（可暂停）、清屏、下载日志文件。
- **「关闭已完成」**（v0.4.2）：一键关掉所有**已结束**任务的页签（已完成 / 部分失败 / 失败 /
  已停止…）；**正在运行或排队中的页签不会被关闭**，状态未知的也不会。
  按钮上会显示可关数量（`关闭已完成 (3)`），没有可关的就置灰。
  关页签**不会影响任务本身**，日志仍留在 `data/logs/<任务ID>.log`，之后点任务的「日志」还能再打开。
  > 注意：它作用于**已打开的页签**。打开已结束任务的「日志」时按钮会**立即**变可用
  > （v0.4.3 起不再等 SSE 状态帧）；若一个页签都没开，按钮自然是灰的。
- `\r` 刷新的进度条会**原地覆盖一行**，不会把你的输出刷成几千行。

### 任务队列

- 每种下载器**同时只跑一个**任务（三个下载器之间可并行）。
- 正在下载时再提交，会**排队**并在列表里显示「排队中 · 第 N 位」；
  上一个任务完全结束后**自动开始下一个**。
- 开始下一个任务前，管理器会先回收上一个任务可能留下的子进程（浏览器 / ffmpeg），
  长时间运行也不会越积越多。排队中的任务可点「取消排队」。

### 下载列表

- **点「刷新产物」才会去读下载目录**（不轮询，避免频繁 IO）。
- 「任务与队列」表：状态、进度条、失败数、说明；可看日志、停止 / 取消排队、续跑、移除。
- 「已下载的产物」表：扫描输出目录得到的实际内容，含进度、大小、修改时间。
- 对产物可以执行：**校验(check)**、**重下失败项(rd)**、**生成 EPUB**、**续跑**。
- 有失败项时会显示「查看失败(N)」，点开列出具体是哪些页 / 哪几章 / 哪几集。
- **「📂 打开下载目录 / 打开」按钮**：只有「浏览器所在系统」与「后端所在系统」相同时才出现，
  点击后会在**后端机器**上打开文件管理器（Windows 用 explorer，macOS 用 open）。
  「打开下载目录」打开当前下载器的输出根；产物行的「打开」直接打开**该产物自己的目录**，
  文件类产物则打开它所在的目录并选中该文件。

### 通知

任务结束时：页面标题闪烁 + 角标 + 可选桌面通知与提示音
（点右上角「通知」开关控制；浏览器首次会询问通知权限）。

### 磁盘与速度

顶栏下面显示各输出盘的剩余空间（低于 5 GB 高亮），右侧显示运行中任务的实时速度
（按产物目录大小差分估算，三个下载器通用）。

## 五、视频下载的各种方式（重要限制）

| 方式 | 网页端支持 | 说明 |
|---|---|---|
| **直接下载**（m3u8 直链） | ✅ 完全支持，推荐 | 需要你先在浏览器 F12 → 网络里复制 m3u8 地址；防盗链站点还要填 Referer / Cookie |
| **yt-dlp 下载**（单个视频 / 合集页） | ✅ 完全支持（v0.3.0） | 粘一个 **B站、YouTube 等**视频页地址就能入队自动化下载——**不开浏览器、不需点播放**。之前只能自己复制 m3u8，现在直接可用。B站单视频实测通过；合集/番剧只会下第一个，整季请用「批量下载」 |
| **yt-dlp 音频**（只下音频） | ✅ 完全支持（v0.6.0） | 音乐视频只要音频时选它：**只下音频流、不下视频字节**（真省流量），成品 `<标题>.m4a`（可选 mp3/opus/flac），并写入标签、内嵌封面。**仅单集**；整张歌单暂不支持 |
| **批量下载**（列表页整季） | ✅ 可全自动 | 会自动解析剧集表、跳过已完成集、失败换线路重试；可指定「线路」，多候选时靠「每集选第 N 个候选」决定。B站番剧/合集也可以走这个方式（yt-dlp 自动接管） |
| **嗅探仅列候选** | ⚠️ 半自动 | 会**在本机弹出浏览器窗口**，你需要在那个窗口里点一下播放；管理器只能显示日志，点不到那个窗口 |
| **嗅探后下载 / 通过缓存下载** | ❌ 需本机操作 | 同样依赖屏幕前的浏览器窗口，请在本机终端里直接用 `py -m m3u_down sniff` / `play` |

**为什么有些不能支持**：`m3u-get-down` 的嗅探与播放器模式依赖一个有头浏览器窗口里真实的播放行为，
网页前端既点不到那个窗口里的按钮，也看不到它的候选列表。

**yt-dlp 下载为什么可以**（v0.3.0 新增）：下载器 v0.7.0 起内置了 yt-dlp 引擎，B站/YouTube 等
站点的视频是**纯 HTTP 拉流**（DASH 音视频分离后用 ffmpeg 合并），不必开浏览器、不必人工点播放，
所以第一次能把它当作普通任务入队。支持的站点、清晰度与 cookie 说明见下载方式旁的 **?** 气泡。

### yt-dlp 下载：清晰度与 cookie

- **清晰度**默认「优先 ≤720P，没有 720P 就取能下到的最清晰」；**高清/会员/番剧需要登录 cookie**。
  两项都在 `m3u-get-down/ytdlp_sites.json` 里改（该文件不在管理器 UI 里）。
- ⚠️ **别指望「读浏览器 cookie」**：新版 Edge/Chrome 的 cookie 改用 App-Bound 加密（v20），
  yt-dlp 读不到（issue #10927）。可行做法：
  ① 装个 Firefox 登录一次，把 `cookies_from_browser` 改成 `firefox`（最省事；
  Mac 上一样可行，没加密）；
  ② 用扩展 `Get cookies.txt LOCALLY` 导出 cookies.txt，把路径填到 `cookies_file`。
  （读不到时下载器会警告一次并自动降级，不会卡住任务。）
- **YouTube**：除 cookie 外还需**两道**技术关卡（JS 运行时 + EJS 挑战脚本）——
  两者已在 `ytdlp_sites.json` 默认预置，不用你装 deno；但 **cookie 必须自己弄**
  （否则报 `Sign in to confirm you're not a bot`）。实测：Firefox cookie 可行
  （`cookies_from_browser: "firefox"`），或导出 `cookies.txt` 填 `cookies_file`。
- **小红书**：网址必须带 `xsec_token`（浏览器打开笔记后从地址栏复制整条 URL，
  含 `&xsec_source=…`）；App 分享的 `xhslink.com` 短链不支持。
- **B站**：直接粘视频页地址即可，不需要 cookie（登录只是为高清/会员内容）。

> 以上只是提醒。**完整说明（cookies.txt 导出步骤、各站实测记录、命令行用法）请直接看
> `m3u-get-down/使用指南.md`**（§5.5「yt-dlp 引擎」）—— 那是这块知识的唯一出处，
> 下载器升级后以它为准。
>
> **换机器 / 搬家**（含 Windows 与 macOS 的装机命令对照、哪些东西要重装、
> 哪些东西会自动重建）也在这份指南的 §10「换机器 / 搬家清单」。

### yt-dlp 音频：只下音频（音乐视频，v0.6.0）

「下载方式」选 **yt-dlp 音频**，粘视频页地址即可；音频格式下拉选 `m4a`（默认）/`mp3`/`opus`/`flac`。
它只取音频流（**不下视频字节**），转封装后存成 `输出根/标题.<格式>`，并写入标题等标签、内嵌封面。

- 与「yt-dlp 下载」同源，所以**支持的站点、cookie/清晰度要求完全一样**（见上一节）。
- **只支持单集**：整张歌单/合集的批量音频暂未支持（选它 + 合集地址只会下第一个）。
- **自研引擎站点不适用**：直接下载 / 批量 / 嗅探的切片多为音视频混合，没有音频模式；
  若地址最终走自研引擎，下载器会打印提示并忽略音频参数。
- `opus`/`flac` 内嵌封面在部分播放器不显示（yt-dlp 只告警，不影响音频本身）。

### 批量下载的两个易混参数：线路 vs 候选

批量下载（`batch`）表单里有两个容易混淆的输入框，它们控制的**不是同一件事**：

| 输入框 | 命令行参数 | 作用 | 什么时候有用 |
|---|---|---|---|
| **线路** | `--line` | 指定**主线路（线路源）**，用序号（如 `1`）或名称（如 `FLV 22 推薦31`） | 仅**内嵌播放器站点**（如 mvffm，页面 JS 里直接写着“线路×剧集”直链）。其余线路会自动作为备用，主线路失败时换线重试 |
| **每集选第 N 个候选** | `--pick` | 每集嗅探时，页面可能捕获到**多个 m3u8**（广告/不同清晰度/音轨等），指定自动取捕获顺序里的第 N 个，默认 1 | 仅**非内嵌站点**（需开浏览器嗅探）。**它不选线路** |

> 一句话：**选哪个源 → 用「线路」；嗅探到多个流时取第几个 → 用「每集选第 N 个候选」。**
> 两个都留空也能跑（用默认值：主线路第 1 条、候选第 1 个）；选错了就换个数重跑，已完成的集会自动跳过。
>
> 表单里「下载方式 / 线路 / 每集选第 N 个候选」这几处的详细说明收在标签旁的 **?** 小图标里：
> 点一下弹出浮动说明（点面板外、按 Esc、或点右上角 × 都能关闭），这样表单不会被长文本撑高。

## 六、管理器配置（`download-manager/config.json`）

首次启动自动生成，含访问令牌。

| 字段 | 默认 | 说明 |
|---|---|---|
| `server.host` | `0.0.0.0` | 监听地址。改成 `127.0.0.1` 就只允许本机访问 |
| `server.port` | `8765` | 端口。可在启动时用 `--port` 临时覆盖 |
| `server.access_token` | 自动生成 | 访问令牌，可随时更换（换完所有浏览器都要重新用带令牌的地址打开） |
| `server.allowed_cidrs` | `[]` | IP 白名单，如 `["192.168.1.0/24"]`；留空=不限制 |
| `python.python_exe` | `""` | 运行下载器的解释器。留空=自动探测（见下） |
| `projects.<类型>.dir` | 见文件 | 三个下载器的项目目录（相对 download-manager/ 解析） |
| `projects.<类型>.output_dir` | `""` | 留空=用下载器自己 config.json 里的 `output_dir` |
| `log.mem_lines` | 2000 | 内存里保留的日志行数（完整日志始终落盘） |
| `log.max_mb` / `keep_days` | 20 / 14 | 单个日志超过 20MB 截断、超过 14 天清理 |
| `notify.desktop` / `sound` | true / false | 浏览器桌面通知 / 提示音 |
| `sleep_guard.enabled` | true | 阻止系统休眠（macOS 用 caffeinate，Windows 用 SetThreadExecutionState） |

### 运行下载器用哪个 Python（重要）

`python.python_exe` 留空时，管理器按下列顺序自动选解释器：

1. `python.python_exe`（显式配置优先，永远不被自动规则覆盖）；
2. 否则用管理器自己的解释器——但有一个**重要例外**：
   如果管理器自己跑在 **free-threading 构建**（如 **Python 3.14t**，即 `python3.14t.exe`）上，
   而本机又装了**同版本号的普通（GIL）构建**，则**自动改用普通构建**运行下载器。
3. 再不行才回退到 PATH 里的 `py` / `python3` / `python`。

**为什么要这个例外**：Playwright 的**同步 API**（`sync_playwright`）在 free-threading 构建上
会**直接段错误（segfault）**，而视频下载器的嗅探 / 批量 / 播放三种模式都用它
（`get` 直链下载不用 Playwright，不受影响）。异步 API 在 free-threading 上正常，但改造成本高，
所以直接用 GIL 构建更稳。

- 顶栏系统信息里会显示实际选中的解释器与原因，例如：
  `自动选用普通(GIL)构建 Python 3.14.0：管理器同环境是 free-threading 构建，会让 Playwright 崩溃`。
- **依赖要装在“实际被选中的那个”解释器里**：上例中，`pip install` 与
  `py -m playwright install chromium` 要装到**普通 3.14**（`py -3.14`），而不是 3.14t。
  实在分不清时，就在配置里把 `python.python_exe` 写死成那个能跑的解释器的完整路径。
- 手动直跑视频下载器时同理：请用 `py -3.14 -m m3u_down ...` 而不是 `py -m m3u_down ...`。
- **启动脚本也走这套逻辑**：`start_server.bat` 会先调 `pick_python.py` 选出解释器再启动，
  所以双击 / `.\start_server.bat` 启动的管理器**自身也跑在 GIL 构建上**；
  想固定某个解释器，就在配置里写 `python.python_exe`。
- （小知识）`start_server.bat` 的所有 `rem` 注释都是英文：`cmd.exe` 按本地代码页（cp936）
  解析 .bat，UTF-8 中文注释会被撕成命令；中文只留在 `echo` 提示行。

### 下载器配置

每个标签页的「下载器配置」区**直接读写该下载器自己目录下的 `config.json`** ——
和你在命令行里直接跑脚本用的是同一份，不存在两份配置不一致的问题。

- 保存前会自动备份为 `config.json.bak.<时间戳>`，可一键「恢复最近备份」。
- 未知字段（如 `_readme`）会原样保留，不会被表单覆盖掉。
- **敏感字段**（`cookies`、`Authorization` 头）**不回传明文**，
  只显示「已设置」；留空提交表示不修改。
- **代理 `proxy` 不是敏感字段**（按大家的惯例它就是个普通配置）：明文回传，
  **留空并保存 = 真的清空**。但要记住清空 ≠ 直连——三个下载器的 `requests`
  在没有显式代理时会自动改用**操作系统代理**（Windows 注册表 Internet 设置 /
  macOS 网络设置）。
- 跨机用代理（例如 Mac 上的下载器走 Windows 上的代理）时，填代理所在机器的
  **局域网地址**（如 `http://192.168.2.100:10808`），并且代理软件要开启
  「允许局域网连接 / Allow LAN」——只监听 `127.0.0.1` 的代理外部机器连不上。

## 七、自检与排查

### 管理器自带的测试脚本

```bash
cd download-manager

# 1. 单元级：适配器、配置读写、命令构造（不需要服务在跑）
py -3 -X utf8 tests/smoke.py

# 2. 子进程输出必须实时到达（不是攒够缓冲区才喷出来）
py -3 -X utf8 tests/stream_test.py

# 2b. 任务队列严格串行 + 残留子进程会被回收（v0.2.0 新增）
py -3 -X utf8 tests/queue_test.py

# 3. 单实例保护：端口探测 + 锁文件
py -3 -X utf8 tests/instance_test.py

# 4. 端到端：对着运行中的服务发 HTTP 请求（需要先启动服务）
py -3 tests/api_test.py

# 5. 进程树终止：确认不会留下孤儿浏览器/ffmpeg
py -3 tests/killtree_test.py

# 6. 服务重启后的遗留进程回收
py -3 tests/recovery_test.py

# 7. 项目目录改名的遗留引用核对（需要服务在跑）
py -3 -X utf8 tests/verify_rename.py

# 8. 前端输出坞页签逻辑（v0.4.2）：页签顺序 + 一键关闭已完成（node，不需要服务）
node tests/logview_test.mjs

# 辅助：看当前任务状态
py -3 tests/show_tasks.py
py -3 tests/show_state.py      # 服务没在跑时也能看（直接读 tasks.json）
```

> ⚠️ **第 6 条 `recovery_test.py` 有下载在跑时会被拒绝执行。**
> 它读真实的 `data/tasks.json`、塞进一条伪造的"运行中"记录，然后**再起一个服务实例**；
> 那个实例启动时会把所有 `running` 任务当"遗留进程"强制回收（这正是它要测的功能），
> 也就是会**杀掉你正在跑的下载**。所以脚本会先检查有没有运行中/排队的任务，
> 有就直接拒绝执行（返回码 2）并列出是哪些任务。
> 第 1~5 条不碰 `tasks.json`，任何时候都能跑。

### 顶栏的自检信息

顶栏的 ✓/✗ 标记与鼠标悬停提示会告诉你缺什么：

- **✗ playwright** → 视频下载器不可用（它是顶层依赖，缺了连直链下载都会失败）：
  `py -3 -m pip install playwright && py -3 -m playwright install chromium`
- **✗ ffmpeg** → 视频合并切片会失败：`brew install ffmpeg`（Mac）
- 项目目录不存在 → 检查 `config.json` 里的 `projects.<类型>.dir`

### 常见问题

**Q：任务状态显示「已完成(未核实)」是什么意思？**
进程正常退出，但没找到产物目录可以核对。常见于下载器提前退出（如某本书已全部下载完、
参数不合法等）。看日志能确认原因；如果确实是正常提前退出，这个状态是正常的。

**Q：显示「部分失败」怎么办？**
点该产物行的「重下失败项」，或点「查看失败(N)」看是哪些页/章/集。
e-download 与 fetech_xs 都支持只重试失败项。

**Q：显示「异常中断」怎么办？**
fetech_xs 遇到单章请求超时时会让整个进程崩溃（它内部没有兜底），
此时已下载的章节不会丢，直接点「续跑」即可继续。

**Q：停了服务，正在下载的任务会怎样？**
下次启动时管理器会发现那个进程已脱离管理，**强制回收**它（否则你永远停不掉、也看不到它的输出），
并把任务标记为「服务重启中断」，界面上点「续跑」即可继续（三个下载器都支持断点续传，不会白下）。

**Q：同一时间能跑几个任务？**
每种下载器各一个（可以同时下电子书 + 画廊 + 视频）；同一类型的第二个任务会**排队**，
前一个结束后自动开始。原因是三个下载器都写同一份进度文件，同类型并发会互相覆盖。

**Q：跑长任务时 Mac 会休眠吗？**
不会。启动时默认开启防休眠（`caffeinate`）。想临时关掉：`./start_server.command --no-sleep-guard`。

**Q：令牌忘了 / 想换一个？**
看 `download-manager/config.json` 的 `server.access_token`；
删掉它的值再重启会自动生成新的（所有浏览器需重新用带令牌的地址打开一次）。

## 八、从网页一键提交任务（油猴脚本）

> 完整说明见 **`userscript/使用说明.md`**；设计见 `Design/项目设计文档.md` §23。
> 脚本只用管理器**现有**接口（`POST /api/tasks` 等），所以**后端没有为它改过一行**。

- **位置**：`userscript/download-to-manager.user.js`（Tampermonkey「添加新脚本」粘贴即可）。
- **入口**：油猴**原生菜单**——图标上的数字表示本页有可用脚本，点开后选本脚本，
  菜单三项：「下载到管理器…」「管理器设置（地址/令牌）」「打开管理器页面」。
  **不做**页面常驻悬浮球。
- **能提交三类任务**：电子书（fetech_xs）、E-Hentai 画廊、视频
  （批量 batch / yt-dlp / m3u8 直链 get）。
- **必做一次配置**：菜单「管理器设置」里填管理器地址（默认 `http://127.0.0.1:8765`）
  与访问令牌（`config.json` 的 `server.access_token`），点「测试连接」确认。
- **batch 的参数**：集数用「**快捷芯片 + 文本框**」（`[全部][1-6][1-12][1-24]` 只是快速填充，
  最终以文本框为准，留空=全部）；**线路 / 每集候选按站点自动切换**——
  内嵌播放器站点（mvffm、ikanbot）显示「线路」下拉（默认自动探活），其它站点显示「每集取第 N 个候选」。
- **提交行为**：只提示「✓ 已加入任务 #id（排队中/运行中）」，**不打开任何页面**、不轮询进度；
  面板保持打开、表单保留，可以连续提交多个任务。要看进度请点菜单里的「打开管理器页面」。
- **排错**：提示"连不上管理器"= 没启动 / 地址错 / 没给脚本加 `@connect`；
  提示"令牌无效"= 重填 `server.access_token`。
- **自检**：`node userscript/test_core.mjs`（无需浏览器与运行中的管理器）。
