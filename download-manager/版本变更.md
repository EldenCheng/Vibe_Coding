## v0.5.1

> 主题：**视频产物「续跑」不再报"缺少地址"** —— 地址从产物目录回填，
> 续跑自动带回 `--line/--pick`。需配合 m3u-get-down v0.11.0 使用
> （旧版下载器写出的进度没有 `list_url`，走简介反查兜底；裸 m3u8 续跑
> 需要新版下载器的 batch 单集模式）。

### 修复（用户实测驱动）

- **batch 产物按「续跑」报"缺少地址，无法续跑"**：`scan()` 给产物条目写死
  `extra={"url": ""}`（其它三个适配器都会从各自进度文件回填，只有 m3u 没做）。
  现新增 `_source_url_of_dir()` 三级回填：批量进度 `list_url` →
  简介.md「来源列表页」行 → 单集 `progress.json` 的 `playlist_url`；
  实在没有（如已完成的散文件）留空，由前端直接提示、不调后端。
- **单集中断目录此前不可见**：`is_item_dir` 只认 `批量进度.json`/mp4，
  get/sniff 中断残留的目录（progress.json + segments）扫不出来。
  现含 `progress.json` 的目录同样列出（根目录散落的中断现场仍不列，
  那不是"一项产物"，重提表单即可）。

### 变更（只动 m3u 适配器 + 一处通用前端）

- **`build_action` resume 按产物类型分两支**：
  - 裸 m3u8 + 本目录 progress 正是该直链残留 → `get <url> -o <本目录>` 原地续传；
  - 其余一律 `batch <url> --yes`，并按 `resume_hint` 回填 `--line`（非空才补）、
    `--pick`（≠1 才补）。**不带回的后果**：内嵌站点重跑时重新探活可能换线，
    触发下载器"线路变化→重下"，把整季已完成集全部重下（约 10GB）。
  - 两种分支在配置了 insecure 时都带 `--insecure`（原来续跑没带）。
- **前端 `runAction` 加通用守门**：无 url 且无 book 标识 → 直接 toast
  （"该产物没有可恢复的下载地址…"），不调后端。四个下载器都受益。
- `progress_of_dir` 的 batch/单集分支同步带出 `list_url`（API 可观察）。

### 验证

- 新增 `tests/resume_test.py`（纯本机 18 项全过）：四类目录回填、hint 回填与
  缺省、原地 get 分支、m3u8 走 batch 分支、无 url 仍抛"缺少地址"。
- `tests/api_test.py` 在本环境无法执行（仓库无 `config.json`，运行时生成），
  与本次改动无关。
- 设计见《Design/项目设计文档.md》§27。

### 边界（明确不动）

- 当初带 Referer/Cookie 的单集：续跑时鉴权参数已丢失（cookie 记盘有泄漏风险，
  不记），可能 403 —— 仍需在标签页手动重提。这是已知限制，已写入下载器使用指南。
- `play` 模式不在管理器菜单里，不纳入续跑链路。

## v0.5.0

> 主题：**新增第四个下载器「HTTP 直链」（http-download）**——通用单文件直链下载，
> 支持断点续传、多线程分块、限速、SHA256/MD5 校验。生效需重启服务。

### 新增

- **新适配器 `http`（`backend/adapters/http_download.py`）**，对接平级新项目 `../http-download`：
  - 任务表单：直链 URL（必填）/ 保存文件名（可选）/ 校验值（可选，64 位 hex=SHA256、32 位 hex=MD5）；
  - 配置表单：输出目录、代理（留空=读操作系统代理，沿用「proxy 不遮罩」约定）、请求头 JSON
    （Authorization/Cookie 遮罩）、分块并发数、分块最小文件、限速 KB/s、超时、重试三件套、
    重名处理（rename/overwrite/skip）、自动读同名 `.sha256` 校验；
  - 产物是**平铺文件**：点刷新列出 `Download/` 下的文件，自动跳过 `.part/.seg/.corrupt/.sha256` 等工作文件；
  - 完成判定：下载器 stdout 锚点行（「文件保存到: …」「进度文件: …」）+ `.progress/` sidecar，
    退出码只作失败依据（延续「不以退出码判成功」原则）；
  - 列表动作：「续传/重下」= 重跑同一 URL，`.part` 与分块残留自动续传。
- **`DownloadItem` 支持文件型条目**（`backend/adapters/base.py`）：原先 `to_dict()` 只会统计目录大小，
  单文件条目一律显示 0 B；现在文件条目直接取 `st_size`。
- **产物 detail 接口支持 `http` 类型**（`backend/app.py`）：从 sidecar 返回字节数、SHA256、状态与错误原因。
- **任务名**：`直链 · <URL 尾段>`（`backend/task_manager.py`）。

### 变更

- `backend/config.py` 默认 `projects` 增加 `"http": {"dir": "../http-download", "output_dir": ""}`；
  管理器 `config.json` 同步。
- `VERSION` 0.4.3 → 0.5.0（v0.4.4 的变更当时忘了同步 VERSION，此处一并对齐）。
- **前端零改动**：标签页/表单/列表全部由 `/api/adapters` 数据驱动，第四个下载器自动出现。

### 备注

- http-download 项目自身的设计与版本记录见 `../http-download/项目设计文档.md`、`../http-download/版本变更.md`。
- `tests/smoke.py` 已覆盖：注册自检、真实 `Download/` 扫描、命令构造、非法输入拒绝、finalize 三态判定。

## v0.4.3

> 主题：**启动即开浏览器**（`--open`/`--web`）、**修复「打开」按钮跑去「文档」**、
> 输出坞页签的 `×` 移到最左 + 「关闭已完成」不再一直是灰的。

### 需求（用户原话，四项）

1. 启动脚本加一个类似 `web` 的参数，启动后自动在浏览器打开管理器（地址带令牌）；
2. 「打开」按钮点下去打开的是**用户-文档**，不是对应下载物的目录；
3. 关闭页签的 `×` 在右边，希望**移到左边**；「关闭已完成」似乎一直是灰的；
4. 油猴脚本支持网站散落多处，想要更简单的维护方式（→ 方案 A：`SITES` 单表）。

### 新增

- **`server.py --open`（别名 `--web`）**：启动后在默认浏览器打开
  `http://127.0.0.1:<port>/?token=<token>`；默认不开，`start_server.bat --open` 即可。
  打开时机在**套接字 listen 之后**（给 `App.serve_forever` 加了 `on_ready` 回调），
  避免浏览器先连、看到「无法访问」。无默认浏览器时只提示、不影响服务。

### 修复

- **「📂 打开」跑去「用户-文档」**（`backend/fso.py`）：
  `subprocess.Popen(["explorer", "/select," + path])` 会被 subprocess 把整段参数再加一层引号
  （`explorer "/select,路径"`），explorer 解析失败后**回退到「文档」**。
  改为：目录直接 `os.startfile`；文件用 `ShellExecuteW(..., '/select,"路径"')` 原样传参。
- **「关闭已完成」按钮曾经一直是灰的**：它只作用于**已打开的页签**，而页签状态原先只在
  SSE 的 `status` 帧到达后才写入；SSE 没连上/帧没到时状态永远是空串。
  现改为开页签时就把**任务列表里已知的状态**传进去（`LogView.open(..., {status})`），
  已结束的任务一打开页签按钮**立即**可用。

### 变更

- **输出坞页签 `×` 移到最左**：子元素顺序 `[×] [运行点] [标签]`（原来 `[运行点] [标签] [×]`）。
- **页签标签截断**：新增 `.tab-label`（`max-width:340px` + 省略号，`title` 保留全文），
  长 URL 不再把页签撑满整条坞。
- **油猴脚本（1.0.1 → 1.0.2）站点维护收敛为 `SITES` 单表**（方案 A）：
  `PRESETS` / `EMBEDDED_SITES` / `CAUTION_SITES` 全由 `SITES` 派生；加站 = 改 1 行 + 补
  文件顶部 `@match`（运行时无法生成的一处，手动）。顺带补上原来漏掉的 `acg.tv` 匹配。
  `test_core.mjs` 新增 §1b：双向比对 `@match` 与 `SITES`，漏改直接报错。

### 验证

- `py -m py_compile` + `node --check` 全通过。
- `--open`：`on_ready` 钩子单测触发；`BROWSER=echo server.py --port 8798 --open`
  时 `echo` 收到带令牌 URL，证明 `webbrowser.open` 被调用。
- 打开目录：用 `Shell.Application` 枚举资源管理器窗口，目录能被正确打开、不再跑「文档」。
- 输出坞：无头 Chromium 验证 `×` 在最前、标签 340px 截断、开页签立即计数、点 `×` 关闭。
- 油猴脚本：`node userscript/test_core.mjs` 全通过（含新增的 `@match` ↔ `SITES` 一致性检查）。

### 边界（明确不动）

- 打开目录的**可信路径校验**不变（仍限下载器输出/扫描根内）。
- `--open` 默认关闭；不改 `start_server.bat` 的默认行为。
- 油猴脚本仍只对 `@match` 白名单里的站点生效；`@match` 无法运行时生成，必须手动补。

## v0.4.2

> 主题：底部输出坞的**页签交互** —— 最新在左 + 一键关闭已完成（用户提出"新页签在最右边，
> 想关它很麻烦"）。

### 需求（用户原话）

> "下载管理器最下面那个输出控制台信息的那个区域，有一个进程标签栏的，现在那个标签栏好像是
> 最新的控制台消息标签入在右边，但这样放的话，如果我要关闭标签栏就很麻烦了，你帮我改两个东西：
> 1. 最新的标签放左边（就是最近新开始的任务的标签）
> 2. 增加一键关闭已完成（或者已停止的任务）的所有标签的功能"

### 变更（只动前端）

- **页签最新在左**：`renderTabs()` 按 `orderedIds()`（Map 插入顺序反转）渲染。
  页签栏本身是横向滚动的，所以最新那个页签**永远在最左边、不用横向滚动就能点到并关闭**
  —— 正是用户提的痛点。只反转渲染顺序，不重排、不跳动（收状态也不换位置）。
- **新增「关闭已完成」按钮**（输出坞右侧动作区）：关掉所有**已结束**任务的页签 ——
  `completed` / `completed_unverified` / `partial_failed` / `failed` / `crashed` / `stopped`
  / `interrupted`；`running` / `queued` **一个都不关**；状态还没回来的（`''`）也不关，
  等状态到了自然可关。按钮上带数量（`关闭已完成 (3)`），没有可关的置灰，点完 toast 提示。
- 当前页签也被关掉时，选**顶替它原来那一格**的页签（视觉顺序里的同一下标，越界取最后一个），
  比"固定跳到第一个"更符合直觉。
- 选中页签时只做**水平**滚动把它带进视野（直接改 `log-tabs.scrollLeft`），
  不用 `scrollIntoView()`，免得连带把页面纵向滚走。
- 内部拆成 `dropTab()`（只关流+删记录）/ `closeTab()`（单个）/ `closeFinished()`（批量）三个函数，
  避免为"批量关闭"再写一遍选中逻辑。
- 兜底：`index.html` 若被浏览器缓存成旧版（没有这个按钮），新 JS 只是没有按钮可用，
  **不会让输出坞的初始化崩掉**。

### 验证

- **新增无头桩测试 `tests/logview_test.mjs`**（`node tests/logview_test.mjs`，不需要浏览器、
  不需要服务在跑）：12 项全过 —— 页签最新在左、重复 open 不跳位、状态更新不换位、
  按钮计数（只数已结束的）、状态未知的不算可关闭、一键关闭只关已结束的、点击发 toast、
  被关页签的 SSE 流确实 close、当前页签被关后选中顺位页签、全关完的空态与置灰、
  单个 × 关闭仍可用、关完再开新任务仍排最左。
- 真机：浏览器刷新后逐项手测（见《Design/项目设计文档.md》§25.5）。
- 设计见《Design/项目设计文档.md》§25。

## v0.4.1

> 主题：修复视频批量任务的 **"已完成(未核实)"** —— 产物目录定位链路断在 `finalize`。

### 修复（真机实测驱动）

真机跑 `ikanbot play/432956` 批量第2-3集（往**已存在**的番剧目录续跑），两集都下好了，
管理器却报 `completed_unverified`。查证发现根因比"目录已存在"更深：

1. `Adapter.detect_target_dir(plan, bus)` 的第一优先级是"日志里的明确路径"
   （`locate_from_log(bus)`）；
2. 但 `finalize()` 里调用的 `self.detect_target_dir(plan)` **没传 bus**
   （`task_manager._on_exit` 给 `finalize` 的是 `log_text` 字符串）；
3. 于是三个适配器里的 `locate_from_log()` **全是死代码**；
   `Adapter.locate_target()`（唯一会传 bus 的方法）**全项目无人调用**；
4. 实际只剩"目录快照差集"可用 —— 对**已存在的产物目录**（续跑、补集）必然落空，
   落到单文件成品差集也找不到（batch 产物在子目录里）→ `completed_unverified`。

### 变更（只动 m3u 适配器）

- **`locate_from_text(log_text)`（新增）**：从 `finalize` 已经拿到的日志文本里解析
  `[批量] 已选 N 集，输出目录: <路径>`（batch 与 yt-dlp 批量都会打印这行，进下载循环前就打），
  路径存在即采用 —— 与目录快照无关，续跑/补集/服务重启后都有效。
  契约方法 `locate_from_log(bus)` 改为复用同一套正则，不再各写一份。
- **`find_by_identity(plan)`（新增兜底）**：`log_text` 只取日志尾部 200KB，超长批量的那行可能
  被截掉；此时扫输出根下各子目录的 `简介.md`，谁写着 `> 来源列表页：<本任务 URL>` 就是它。
- 定位优先级变为：**日志文本 → 简介.md 反查 → 目录快照差集 → 单文件成品差集**。

### 验证

- 单元（临时脚本）：`locate_from_text()` 命中真实格式、路径不存在时返回 None、
  无相关日志返回 None；`find_by_identity()` 按 简介.md 反查成功、URL 不匹配时返回 None；
  `detect_target_dir()` 在快照为空时也能靠反查定位。
- 跨项目真机：同一天用 m3u-get-down v0.8.0 的纳管功能实跑了 `Download/牙狼garo`
  （23 集，含 17 个 IDM 命名文件），产物目录定位与状态判定按本节逻辑。
- **管理器自身流程复测（重启后，v0.4.1 已加载）**：重启服务（`/api/health` 报 0.4.1）→
  对 `牙狼garo` 提交批量任务（25 集全选）：
  - 1-23 集全部跳过（日志逐条注明是哪个文件满足的，含 IDM 命名的那 17 个）；
  - 实下第24、25集；
  - **最终状态 `completed` / 消息「25/25 集完成」/ `target_dir` 正确指向番剧目录**，
    不再是 `completed_unverified` —— 修复在真机流程上确认生效。
    （此前的同目录任务正是 `completed_unverified`，对照组明确。）

### 边界（明确不动）

- `e_download` / `fetch_xs` 的 `locate_from_log()` 同样是死代码，但它们的产品目录多是本次新建的、
  差集可用，**本次不改**（不在未实测的路径上改行为）。若同样出现"未核实"，照本节接 `log_text`。
- 基类 `Adapter.locate_target()` 的契约不动（风险面覆盖三个下载器）。

## v0.4.0

> 主题：配套**油猴脚本**——在网页上把任务直接交给管理器（电子书 / E-Hentai / 视频），自动入队下载。
> **后端与前端零改动**：脚本只用现有接口。

### 新增

- **`userscript/download-to-manager.user.js`**：油猴脚本（单文件自包含）。
  - **入口是油猴原生菜单**（图标数字 → 选中本脚本 → 菜单项），**没有**页面常驻悬浮球；
    三项：`下载到管理器…`（主入口）、`管理器设置（地址/令牌）`、`打开管理器页面`。
  - 面板（Shadow DOM，隔离站点样式）里选下载器与方式：**电子书 / E-Hentai 画廊 /
    视频（批量 batch · yt-dlp · m3u8 直链 get）**，地址自动预填当前页。
  - **提交只报「✓ 已加入任务 #id（排队中/运行中）」**：不轮询进度、**不打开任何页面**、
    面板不关闭、表单保留 —— 可以连续提交多个任务；想看进度点菜单或结果条里的链接。
- **`userscript/使用说明.md`**：安装、令牌怎么填、各参数速查、常见问题。
- **`userscript/test_core.mjs`**：Node 桩测试（无需浏览器、无需管理器运行），
  覆盖域名预选 / 范围校验 / 请求体字段与后端 `form_schema` 对齐。

### batch 参数在网页上怎么给（用户提出的问题）

这两项在下载器里**互斥**，过去在管理器网页上靠两个输入框 + `?` 气泡解释，容易填错：

- `--line`（选线路）**只对"内嵌播放器"站点有效**（mvffm / ikanbot，播放页 JS 里直接写着
  线路×剧集直链；下载器默认还会**探活**第一条存活线路、失败自动换线，所以多数时候不用指定）；
- `--pick`（每集取第 N 个候选）**只对需要嗅探的站点有效**（eacg、youknow 等）。

油猴面板的做法（用户选定"方案 A"）：

1. **集数 = 快捷芯片 + 文本框**：`[全部] [1-6] [1-12] [1-24]` 只负责快速填充，
   文本框是唯一数据源（支持 `1-12,15`，留空=全部），提交前校验格式与语义
   （`0`、`5-3`、`12-`、`abc` 一律拦下），坏参数不会送到下载器。
2. **线路 / 每集候选由脚本按站点自动切换**：域名命中内嵌播放器站点表 → 显示「线路」下拉
   （默认「自动（探活第一条存活线路）」，可选「自定义…」填 `22` 或 `FLV 22 推薦31`）；
   其它站点 → 显示「每集候选」（默认 1）。用户不需要自己判断站点类型。
3. `javdock.com`（下载器标记 `unsupported`，滑动窗口 HLS 防下载）在面板里给醒目警示，但不禁用。

### 实现要点

- **必须用 `GM_xmlhttpRequest`**：管理器是纯标准库 HTTP 服务，响应**没有 CORS 头**，
  第三方页面上 `fetch('http://127.0.0.1:8765/...')` 会被浏览器拦掉；
  脚本头部声明 `@connect 127.0.0.1` / `@connect localhost`（跨机使用需自行补 LAN IP）。
- **令牌**：`X-Auth-Token` 头，存 `GM_setValue`，填一次长期有效；「测试连接」用
  `GET /api/health` + `GET /api/tasks`（只读且需鉴权）同时验证连通与令牌，不会产生任务。
- **按域名预选**（见设计文档 §23.5）：e-hentai/exhentai → 画廊；`*.als1004.space` → 电子书；
  B站/YouTube 系 → 视频 yt-dlp；`sites/*.json` 的五个站 → 视频 batch；
  地址本身是 `.m3u8` → 视频 get；其余 → 视频 batch 兜底。
- **生效范围**：`@match` 只列已知站点（油猴图标只在这些站亮数字）；
  想在别的站用，取消脚本里注释掉的 `@match *://*/*` 或自行加用户匹配。
- 错误分类提示：没配令牌→直接切设置视图；401→"令牌无效"；连不上→提示启动
  `start_server.bat` 并给重试；400 `invalid_form`→原样展示后端中文错误。

### 明确不做（边界）

- **不提供 `sniff` / `play`**：这两种模式必须有人在桌面上点播放，从网页触发没有意义。
- **不做页面 DOM 解析选集**：那等于在 JS 里重抄一份 batch 的解析逻辑，站点改版要维护两处，
  且结果可能与下载器实际解析的不一致。真正的"解析后勾选"列为二期
  （需要 `m3u_down batch --list-json` + 管理器预览接口，见设计文档 §23.10）。
- 面板内进度轮询 / SSE：不做（用户选择只报"已加入"）。

### 验证

### 新增

- **任务队列更稳、上一个任务的进程必定关掉**（用户诉求 1）：
  - 修掉 `_pump` 的并发竞态：原来 `create_task` 与 `_on_exit` 可能同时看到「无运行中进程」，

## v0.1.5

### 变更

- **单实例保护（用户拍板 A+B）**：修掉「两个管理器实例能同时监听同一端口」——
  它已经造成实际数据丢失（一个正在下载的任务记录被覆盖掉）。
  - **端口占用检查重写**：Windows 的 `SO_REUSEADDR` 语义允许绑定一个**已被别人监听**的
    端口（接近 Unix 的 `SO_REUSEPORT`），而原 `check_port()` 正是用
    `bind + SO_REUSEADDR` 探测的，所以探测永远成功、第二个实例照常启动。
    现在先做**连接探测**（能连上即判定占用），再用**独占方式**试绑
    （Windows 不设 `SO_REUSEADDR` 并加 `SO_EXCLUSIVEADDRUSE`；POSIX 保留它以避免 TIME_WAIT 误报）。
  - **监听套接字禁止复用**：`_ThreadedHTTPServer.allow_reuse_address = (os.name != "nt")`，
    并在 Windows 上覆写 `server_bind()` 设置 `SO_EXCLUSIVEADDRUSE`。
  - **新增 `backend/instance_lock.py` + `data/server.lock`**：同一时间只允许一个实例，
    即使有人用 `--port 9000` 另起一个也拦得住（那才是真正会互相覆盖 `tasks.json` 的场景）。
    记录 `{pid, host, port, started_at, python}`；PID 仍存活则拒绝启动并打印占用者；
    PID 已消失视为陈旧锁自动接管。

## v0.1.4

### 修复

- **下载器输出长时间不显示（严重，用户实测反馈）**：用户下载 E-Hentai 画廊时，
  Download 目录里图片在正常下载，但页面输出区**只有管理器自己那 4 行 [sys] 提示**，
  下载器的真实输出一行都没有。
  - **根因**：`RunningProcess._pump` 用 `stream.read(4096)` 读管道，而 `Popen` 默认
    （bufsize=-1）给的是 `BufferedReader`，它的 `read(n)` 会**阻塞到凑满 n 字节或 EOF**
    才返回。下载器每 1~2 秒才打印一行（约几十字节），于是要攒够 **4KB** 才喷一次。
    管理器自己的 `[sys]` 行是直接 append 的，所以不受影响——这就造成了
    「有任务启动信息、却没有下载器输出」的假象。
  - **实测对照**（子进程每秒一行、共 6 行）：`read(4096)` → 6.03 秒才收到 48 字节
    （等于等进程退出）；`read1(4096)` → 0.03/1.03/2.03… 秒逐行到达。
  - **现场证据**：用户那个任务启动于 22:31:32，其 131 行输出里 **127 行的时间戳全是
    22:37:18**（同一毫秒批次），即攒满 4KB 才一次性到达。
  - **修复**：改用 `read1(4096)`（有多少返回多少，半行交给 `LineAssembler` 拼接）；
    对不支持 `read1` 的流回退到 `read`。
- **新增 `tests/stream_test.py`**：回归测试，断言「第一行在 1.5 秒内到达」、
  「至少 4 行是在进程仍运行时收到的」、「各行到达时间被拉开（≈0.5s）」。
  修好前这三条都会失败（所有行挤在进程退出那一刻），修好后到达时间为
  `[0.03, 0.53, 1.03, 1.53, 2.03, 2.53]`。

## v0.1.0

第一个可用版本：三个下载器的统一 Web 管理器，零第三方依赖。

### 新增

**管理器本体**

- 纯标准库后端（`http.server` + 有界线程池 + 自写极简路由/JSON/静态文件/SSE 框架），
  前端为原生 HTML/CSS/JS 单页，无构建工具链。
- 三个标签页对应三个下载器（电子书 / E-Hentai 画廊 / 视频），每个标签页含：
  参数表单、可折叠的下载器配置区、下载列表。
- **实时输出区**：SSE 推送，每任务一个页签，`\r` 进度条原地覆盖、跟随滚动可暂停、
  可清屏、可下载完整日志。
- **下载列表**：点「刷新」才扫描输出目录；同时列出任务（状态/进度/失败数）与产物
  （进度/大小/修改时间）；支持校验(check)、重下失败项(rd)、生成 EPUB、续跑、查看失败明细。
- **每类型单任务 + FIFO 队列**：同一下载器同时只跑一个任务（三个下载器之间可并行），
  后续任务排队并在前一个结束后自动开始。
- **完成判定以进度文件为准**（不看退出码）：状态分
  `completed / partial_failed / failed / crashed / stopped / interrupted / completed_unverified`。
  三个下载器都存在「部分失败仍返回 0」的情况，只看退出码会误报成功。
- **访问保护**：URL 令牌 + localStorage 永久有效，支持局域网访问；
  可选 IP 白名单（`server.allowed_cidrs`）。
- **长期运行保障**：
  - 停止任务时终止**整棵进程树**（Playwright 浏览器、ffmpeg 都是子进程，只杀父进程会留孤儿）；
  - 服务重启时自动**强制回收**遗留进程并标记 `interrupted`（输出管道已断，留着无法管理）；
  - 日志内存环形缓冲（可配行数）+ 完整落盘 + 超限截断 + 过期清理；
  - 后台线程统一异常兜底，单任务出错不影响服务。
- **防休眠**：macOS 用 `caffeinate`，Windows 用 `SetThreadExecutionState`，默认开启。
- **环境自检**：顶栏显示平台、Python、各下载器项目目录是否就绪，以及 ffmpeg / playwright
  缺失提示（缺 playwright 时视频下载器连直链下载都会失败）。
- **磁盘与速度**：各输出盘剩余空间（低阈值高亮）+ 运行中任务实时速度（按产物目录大小差分估算）。
- **任务完成通知**：标题闪烁 + 角标 + 可选桌面通知与提示音。

**下载器改动（保持向后兼容，默认行为按用户要求调整）**

- `e-download`：新增 `output_dir` 配置项与 `--output-dir` 参数，默认 `Download/`；
  读 config.json 时不再丢弃未知字段。
- `fetech_xs`：`download_novel.py` 与 `build_epub.py` 均新增 `output_dir` / `--output-dir`，
  默认 `Download/`（与磁盘上现有 5 本书的位置对齐，可直接续传）；同样不再丢弃未知字段。
- `m3u-get-down`：`output_dir` 默认值改为 `Download`，并**修正相对路径基准**
  （原来相对当前工作目录，改为相对项目根目录），从任意 cwd 启动产物都落在同一处。

### 修复（开发期发现的问题）

- **敏感配置不再泄漏**：早期实现只遮罩已声明字段，未在表单里声明的敏感字段
  （如 `cookies`）会经「未声明字段」原样回传，等于泄漏登录态。
  现改为遮罩整棵子树（连键名都不回传）并递归处理未声明字段。
- **Windows 进程终止**：部分环境下 `taskkill /T /F` 会被拒绝（Access denied），
  导致「停止任务」失效。改用 Win32 `CreateToolhelp32Snapshot` 枚举进程树 +
  `TerminateProcess` 逐个终止，**先叶子后根**（父进程先死会让子进程被重新挂到别的父进程而找不到）。
- **已存在产物的定位**：重跑一个已下载完的书/画廊时不会产生新目录，
  最初只用目录快照差集会定位失败并误判成「无法核实」。
  改为三级策略：日志路径 → 目录快照差集 → **按身份反查**（画廊按 `gid`、电子书按 `book_id`）。
- **日志编码**：强制 `errors="replace"` + `PYTHONIOENCODING=utf-8` + `python -u`，
  避免中文与 `✓/✗` 在 Windows 控制台编码下崩溃，也保证输出实时可见。

### 已知限制

- 视频下载器的**嗅探后下载**与**通过缓存下载**两种方式无法在网页端完成
  （需要 Mac 屏幕前的有头浏览器窗口），网页端只支持：直链下载、批量下载、嗅探仅列候选。
  深度支持需给 `m3u-get-down` 加 HTTP API，列为二期。
- `build_epub.py` 依赖 `ebooklib`，未安装时生成 EPUB 会失败（顶栏自检会提示安装命令）。
- 目前无多用户与权限区分（单人使用，明确的非目标）。
