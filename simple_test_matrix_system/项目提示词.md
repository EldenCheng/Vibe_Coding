## 总体设计

1. 这是一个简单的网页服务, 给用户通过上传一个spec文件, 最终生成一个test matrix

2. 在根目录下维护一个test_matrix.json文件, 用于存储已生成的test matrix的信息, 或者你可以推荐一个更加好的存放办法

3. 用户打开页面时, 先扫描所有文件夹, 找出所有excel格式的test matrix, 然后按时间顺序显示在test matrix列表中让用户看到, 用户点列表中任意一个test matrix就可以下载test matrix, 点击test matrix旁边的x(叉)就可以删除

4. 用户上传的文件, 先放在temp文件夹中

5. 在用户点击生成后, 在后台建立一个以用户输入的项目名称命名的文件夹, 把用户上传的文件从temp文件夹转移到项目文件夹中

6. 如果点击生成, 准备建立项目文件夹时, 发现项目文件夹已经建立, 则把判断项目文件夹里是否已经有新上传的文件, 如果文件名称, 大小一致, 则弹窗询问用户是否需要重新生成, 如果用户选是, 就需要把项目文件夹里outputs子文件夹清空

7. 后台调用scripts里的main.py脚本, 把项目文件夹里用户上传的文件的文件路径, 用户输入的临时提示词(如果有的话)作为参数传给脚本

8. 捕捉main.py脚本的输出, 实时更新页面的消息显示

## 界面设计

1. 界面设计可以参考"index_demo2.html", 但要注意demo中为了展示效果. 所以上传文件与已生成Test Matrix列表有dummy数据, 但在真实系统中, 已上传文件与已生成Test Matrix列表一开始是空的, 要根据实际内容显示.

2. 有一个文本框, 可以让用户输入项目名称

3. 有一个上传文件对话框, 可以让用户直接输入文件路径, 或者点击框旁边的"...", 打开文件浏览器来选择一个文件, 有一个"上传"按键, 也有一个"取消"按键

4. 上传文件对话框下面有一个位置可以用来显示用户上传的文件名称, 如果未上传, 是空的, 如果已上传, 就显示文件名, 后面有一个"X"(叉)图标, 让用户可以删除这个已经上传好的文件

5. 有一个起码5行的多行文本框, 可以让用户输入临时提示词. 里面有提示写着:
   
   "请简单介绍一下项目的基本情况, 能让AI更好地理解spec的内容, 比如:&#13;&#10; 1. Spec里包含有多少个Mode, Mode的名称是什么(4个Mode, Mode A, Mode B...). &#13;&#10; 2. Spec里有多少个Input, input的名字是什么(有2个Input, Head Button, Chest Button...).&#13;&#10; 3. Spec里有什么特别的标记方法吗? 比如方框的颜色这些(蓝色=Animation 橙色=Global interrupt...)"

6. 在多行文本框下面, 有几个Button, 一个Button是生成, 另一个Button是取消

7. 最下面是消息显示位置, 用于显示后台运行信息, 平时是空白的, 有信息时才滚动更新, 只显示最后一个后台信息, 之前的信息会被新的信息替换

8. 还需要在页面上简单管理已生成的test matrix, 包括有一个列表, 可以让用户见到最新生成的(最新生成的可以有一个标志表示这是最新的), 以前生成的, 点击列表里对应的test matrix可以下载, 同时test matrix旁边也有一个x(叉)让用户可以删除不再需要的test matrix

## 目录

1. 系统入口index.html在根目录

2. 后台脚本存放在scripts子目录, 注意因为目录存放位置有改变, 所有py脚本里使用到的路径必须更新

3. config子目录存放auth.json, prompts_mapping.json
   
   1. auth.json存放scripts子目录中api_client.py里使用到的BaseURL与API_KEY
   
   2. prompts_mapping.json存放scripts子目录中analysis_processor.py用到的可选提示词的mapping, 不过json文件里的相对路径要根据新的目录更新一下

4. prompts里存放scripts子目录里所有py脚本用到的提示词
