# ftech_xs 使用指南

## 一、简介

ftech_xs 是一个小说下载与 EPUB 生成工具（**多站点**），支持：

| 站点 | 类型 | 入口 |
|------|------|------|
| 爱丽丝书屋 als1004.space | 常规小说站 | 章节列表 URL 或 book_id |
| cool18.com | 论坛型小说站 | 帖子 URL 或 搜索结果 URL |

**核心功能：**
- 自动解析章节列表，提取书名、作者、全部章节
- 逐章下载章节内容（HTML 格式，保留段落结构）
- 内置反爬应对策略（延迟、重试、断点续传）
- 支持 `--rd` 重试失败章节、`--check` 校验文件状态并发现最新章节
- 下载完成后一键生成带章节号的 EPUB 目录
- 站点适配器架构：新站只需在 `sites/` 下加一个适配器

## 二、环境准备

### 2.1 安装 Python

确保系统已安装 Python 3.13+。验证方式：

```powershell
py -3 --version
```

如果显示 `Python 3.13.5` 或类似版本，说明环境就绪。
如果提示找不到 `py`，请先安装 Python：https://www.python.org/downloads/

### 2.2 安装依赖

在 `fetech_xs/` 目录下运行：

```powershell
py -3 -m pip install -r requirements.txt
```

该命令会自动安装以下依赖：
| 包名 | 用途 |
|------|------|
| requests | HTTP请求与Session管理 |
| beautifulsoup4 | HTML解析 |
| lxml | 解析引擎加速 |
| ebooklib | EPUB电子书生成 |

## 三、快速开始

### 3.1 下载小说

```powershell
# 进入脚本目录
cd fetech_xs

# 方式一：用 book_id 下载（推荐）
$env:PYTHONIOENCODING='utf-8'; py -3 download_novel.py 32157

# 方式二：用完整URL下载（适用于其他小说）
$env:PYTHONIOENCODING='utf-8'; py -3 download_novel.py "https://xn--1jqx9a.als1004.space/other/chapters/id/32157.html"
```

**book_id 如何获取？**
打开你想下载的小说的"章节目录"页面，URL 末尾的数字就是 book_id。例如：
```
.../other/chapters/id/32157.html   ← 32157 就是 book_id
```

**书籍存放位置**:默认放在 `<脚本目录>/Download/<书名>/`，
可在 `config.json` 的 `output_dir` 里更改，或用命令行 `--output-dir` 临时覆盖：

```powershell
# 下载到指定根目录(本次运行生效,不改配置文件)
$env:PYTHONIOENCODING='utf-8'; py -3 download_novel.py --output-dir "D:\Novels" 32157
```

> 相对路径按**脚本所在目录**解析(不是当前工作目录)，所以从任意目录启动结果一致。
> `build_epub.py` 复用同一份 `config.json`，两者输出目录始终一致。

### 3.2 下载 cool18 论坛小说（v2.0 新增）

cool18 是论坛型站点，章节以「帖子」形式发布，有 4 种形态，脚本都会自动识别：

1. **作者在第一章正文里维护了后续章节列表** → 给第一章的帖子 URL 即可
2. **后续章节发布在跟贴里** → 给主贴 URL 即可（脚本自动调 `achildlist` 接口取跟贴）
3. **只有单贴** → 给该帖 URL 即可
4. **作者没维护列表** → 用**搜索结果页 URL** 作为入口，脚本会聚合所有匹配帖子

```powershell
# 方式一：帖子 URL（作者列表 / 跟贴发布 / 单帖，自动识别）
$env:PYTHONIOENCODING='utf-8'; py -3 download_novel.py "https://www.cool18.com/bbs4/index.php?app=forum&act=threadview&tid=14625600"

# 方式二：搜索结果 URL（站内搜索框搜书名后复制地址栏）
# 两种搜索结果地址都支持：
#   bbs4/index.php?...act=threadsearch&keywords=…   （站内搜索）
#   /search.php?keyword=…&sa=…                      （全站搜索）
# 若关键词命中多本书（混入别本书），可在 URL 末尾拼 &author=作者名 精确锁定：
# …&keywords=xxx&author=张三&p=1
# 注意：同一作者有时名字宽度不一致（如「坚持不懈Ａ」全角 vs「坚持不懈A」半角，A 不是同一个字符），
# 搜索会把它们分成两组。主线（正文用第X章标记）和早期外传署名全角，新外传署名半角；
# 两组分开下载即可——外传帖（标题范围含「外传」）会整帖作为一章，排在主线之后
$env:PYTHONIOENCODING='utf-8'; py -3 download_novel.py "https://www.cool18.com/bbs4/index.php?action=search&bbsdr=bbs4&act=threadsearch&app=forum&keywords=%E6%88%91%E7%9A%84...&submit=%E6%9F%A5%E8%AF%A2&p=1"
```

**cool18 必须走代理**（实测直连连不上）。在 `config.json` 里设置全局 `proxy`，或只给 cool18 单独设置：

```json
"sites": {
    "cool18": {
        "proxy": "http://127.0.0.1:10808",
        "request_delay": { "min": 8, "max": 12 }
    }
}
```

**章节切分与去重**（脚本自动处理）：一个帖子里含多章（`第X章`标记 / 裸数字 / `　　0073标题`（全角空格+4位补零数字，无“第X章”） / `　　1、标题`（全角空格+数字+顿号，可被 `<strong>` 包裹） / 特殊章名 `序章/幕间/终章` / 番外）；
同一章有多版本时保留正文最完整的版本（例如被截断的预告会自动丢弃、取单独发布的完整版）；
番外紧跟所属章节；书名新旧不一致（改名）会按“关键词+作者”聚合成一本。

**章节顺序按“发布时间”排**：cool18 作者的章节号经常随心所欲（例如编号 12-13 之后
突然变成 2.1-2.3，或跨卷重号），按编号排会前后错位。脚本改用**帖子发布时间**
（tid 升序）作为章节顺序，生成的 0000、0001、0002… 就是真实阅读顺序。带卷号的
标题范围（如 `2.1-2.3`）会给正文里的“第1/2/3章”自动补成“第2.1/2.2/2.3章”。

**注意**：用「帖子 URL」入口时，若作者列表里指向的某些帖子只有**截断预告**而完整版在
单独帖里（该帖不在作者列表），可改用「搜索结果 URL」入口，结果更完整。

### 3.3 追更（--check 检测最新章节）

这些小说大多未完结，作者会更新。`--check` 每次都会**重新抓取入口 URL 的最新章节表**，
与磁盘上的实际文件对比——**入口 URL 下新增的章节会被自动识别为缺失**并写入 `failed`：

```powershell
# 1. 检查网站是否有更新（发现新章节 → 进 failed）
$env:PYTHONIOENCODING='utf-8'; py -3 download_novel.py --check <入口URL或book_id>

# 2. 下载新章节
$env:PYTHONIOENCODING='utf-8'; py -3 download_novel.py --rd <入口URL或book_id>
```

cool18 的 `--check` 会重新抓取全部帖子（为拿到准确章节表），耗时比直连式站点长，属正常。

### 3.4 生成 EPUB

下载完成后，运行：

```powershell
$env:PYTHONIOENCODING='utf-8'; py -3 build_epub.py 召唤圣剑

# 书籍在自定义根目录时，给 build_epub.py 传同一个 --output-dir
$env:PYTHONIOENCODING='utf-8'; py -3 build_epub.py --output-dir "D:\Novels" 召唤圣剑
```

其中"召唤圣剑"是脚本自动创建的小说目录名（与小说网页上的书名一致）。
生成的文件在 `fetech_xs/Download/召唤圣剑/召唤圣剑.epub`（`output_dir` 改过时以实际配置为准）。

生成的 EPUB 目录中会显示完整的章节名称，例如：
```
第一章 新的旅程
第二章 圣剑套牌
第三章 遇袭
```

## 四、重试失败章节（--rd 选项）

如果在下载过程中某些章节因为网络原因失败，它们会被记录在 `progress.json` 的 `failed` 列表中。下载状态变为 `complete` 后，可通过 `--rd` 选项重新下载这些失败章节：

```powershell
$env:PYTHONIOENCODING='utf-8'; py -3 download_novel.py --rd 32157
```

**运行逻辑：**
1. 读取 `progress.json` 中的 `failed` 列表
2. 从 `failed` 中移除待重试章节，立即保存状态（防止中途崩溃丢失记录）
3. 仅下载这些失败章节
4. 下载成功的章节加入 `downloaded`，失败的重新加入 `failed`
5. 如果所有失败章节都重试成功，状态恢复为 `complete`

**查看当前是否有失败章节：** 直接运行 `download_novel.py 32157`，如果状态为 `complete`，会提示"如需重试失败章节，请添加 --rd 参数运行"。

## 五、检查实际文件状态（--check 选项）

如果 `progress.json` 中的记录与 `chapters/` 目录里的实际文件不一致（例如手动删除了某些文件、脚本崩溃导致状态错乱），可以使用 `--check` 选项修复：

```powershell
$env:PYTHONIOENCODING='utf-8'; py -3 download_novel.py --check 32157
```

**运行逻辑：**
1. 从网页抓取所有章节标题，预填到 `chapter_titles`
2. 扫描 `chapters/` 目录，检查哪些章节文件实际存在
3. 将 `downloaded` 和 `failed` 列表重置为实际文件状态
4. 缺失章节自动加入 `failed` 列表，便于后续用 `--rd` 重试

**典型场景：**
- 之前下载因崩溃中断，`failed` 列表不准 → 用 `--check` 修复后再 `--rd`
- 手动删除某些章节文件后需要重新下载 → 用 `--check` 自动发现缺失
- 怀疑 `progress.json` 状态有误 → 用 `--check` 一键校正
- **小说更新了** → `--check` 会重新抓取最新章节表，新增章节自动进 `failed`，再 `--rd` 即可追更（见 §3.3）

## 六、下载流程详解

### 6.1 第一步：解析章节列表

脚本访问章节列表页面，自动提取：
- **书名**：从 `<h1>《书名》</h1>` 中提取
- **作者**：从 `作者：<a>` 中提取
- **章节列表**：从 `<ul class="mulu_list">` 中提取所有含"章"的链接

### 6.2 第二步：初始化

```
1. 从网页抓取所有章节标题，预填到 progress.json 的 chapter_titles
   （确保 chapter_titles 始终完整准确，不再逐章追加）
2. 加载断点续传进度，跳过已下载章节
```

### 6.3 第三步：逐章下载

```
每章循环：
  1. 随机等待 15~30 秒（模拟人工阅读，减轻服务器压力）
  2. 优先访问 HTML 页面下载内容
  3. 如果HTML返回空内容 → 自动切换到 AJAX API 接口重试
  4. 如果仍失败 → 按指数退避等待（30s, 60s, 120s, 240s, 480s）后重试
  5. 成功后保存为 <序号>_<标题>.html
  6. 立即更新 progress.json（断点续传依据）
```

### 6.4 第四步：生成 EPUB

脚本读取 `chapters/` 目录下的所有 HTML 文件，按序号排序后：
1. 从 `progress.json` 的 `chapter_titles` 读取完整标题（含"第X章"）
2. 创建 EpubBook 对象，设置书名、作者、语言
3. 为每章生成 EpubHtml（含章节标题样式 + 内容）
4. 自动生成目录（TOC），显示完整章节名，兼容 EPUB2 和 EPUB3 阅读器
5. 输出 `.epub` 文件

## 七、断点续传

任何时候中断下载（按 Ctrl+C 或关机），重新运行相同的命令即可自动继续：

```powershell
# 重新运行，会从上次中断处继续
$env:PYTHONIOENCODING='utf-8'; py -3 download_novel.py 32157
```

**原理：** 每成功下载一章后，都写入 `progress.json` 记录已下载的章节索引。下次启动时跳过这些章节。

## 八、下载多本小说

多次运行脚本即可，每本小说的章节会独立存放在各自的书名目录下：

```
fetech_xs/
├── Download/
│   ├── 召唤圣剑/         ← 第一本书
│   │   ├── chapters/
│   │   └── progress.json
│   └── 另一本小说/       ← 第二本书
│       ├── chapters/
│       └── progress.json
├── config.json
└── download_novel.py
```

```powershell
py -3 download_novel.py 32157                         # 下载《召唤圣剑》
py -3 download_novel.py <另一本书的ID>                # 下载另一本书
py -3 build_epub.py 召唤圣剑                          # 生成第一本的EPUB
py -3 build_epub.py 另一本小说                        # 生成第二本的EPUB
```

## 九、配置文件说明

`config.json` 位于 `fetech_xs/` 根目录，可以通过修改它来调整脚本行为：

```json
{
    "output_dir": "Download",   // 书籍输出根目录(相对路径按脚本目录解析)
    "proxy": "",                // 代理,如 http://127.0.0.1:10808;留空=不设显式代理(≠直连,见下)
    "request_delay": {
        "min": 15,    // 每章最小等待时间（秒）
        "max": 30     // 每章最大等待时间（秒）
    },
    "retry": {
        "max_attempts": 5,       // 单章最大重试次数
        "backoff_base": 30,       // 首次重试等待时间（秒）
        "backoff_multiplier": 2   // 每次重试乘数（30→60→120→240→480）
    },
    "headers": {
        "User-Agent": "...",      // 浏览器标识
        "Accept": "...",          // HTTP请求头
        "Accept-Language": "zh-CN,zh;q=0.9",
        "Accept-Encoding": "gzip, deflate",
        "Connection": "keep-alive",
        "Cache-Control": "no-cache"
    },
    // v2.0 新增：按站点覆盖（可选）。键名为站点适配器的 site_key
    "sites": {
        "cool18": {
            "proxy": "",               // 覆盖全局代理（cool18 常需代理）
            "request_delay": { "min": 8, "max": 12 }
        }
    }
}
```

**重要提醒：** 请合理设置 `request_delay` 的值，不要设置过小，避免给服务器造成过大负担。默认的15~30秒是安全合理的间隔。

`output_dir` 说明：

| 取值 | 结果 |
|------|------|
| `"Download"`（默认） | `<脚本目录>/Download/<书名>/` |
| `"D:/Novels"` | 绝对路径，原样使用 |
| `"."` | `<脚本目录>/<书名>/`（旧版本行为，脚本目录下已有书时用它续传） |

`proxy` 说明：

| 取值 | 结果 |
|------|------|
| `""`（默认） | 不设置显式代理。**这不等于直连**：`requests` 会转而读取操作系统代理（Windows 注册表 Internet 设置 / macOS 网络设置） |
| `"http://127.0.0.1:10808"` | 所有请求走该代理（装了 `pysocks` 时也支持 `socks5://`） |
| `"http://192.168.2.100:10808"` | 走另一台机器上的代理。对方代理软件必须开启"允许局域网连接 / Allow LAN"，只监听 `127.0.0.1` 时外部机器连不上 |

## 十、进度文件说明（progress.json）

```json
{
    "book_name": "召唤圣剑",
    "author": "西贝猫",
    "chapters_url": "https://...",
    "total": 679,
    "downloaded": [0, 1, 2],
    "failed": [5, 12],
    "last_index": 2,
    "status": "in_progress",
    "chapter_titles": {
        "0": "第一章 新的旅程",
        "1": "第二章 圣剑套牌",
        "2": "第三章 遇袭"
    }
}
```

| 字段 | 说明 |
|------|------|
| `chapter_titles` | 完整章节标题映射（含"第X章"），**下载初始化时即从网页预填所有章节**，用于EPUB生成准确目录 |
| `downloaded` | 已成功下载的章节索引列表 |
| `failed` | 下载失败的章节索引列表 |
| `status` | `in_progress` 进行中 / `complete` 已完成 |

> **注意：** 从 v1.3 开始，`chapter_titles` 在下载初始化时即从网页抓取所有章节并一次性写入，不再逐章追加。这意味着即使下载因故中断，`chapter_titles` 也保证完整。

## 十一、常见问题

### Q1: 下载中途中断了怎么办？
直接重新运行相同的命令，脚本会从上次中断处自动继续。

### Q2: 有章节下载失败了怎么办？
运行完成后查看提示的失败索引。使用 `--rd` 选项重新下载失败章节：
```powershell
py -3 download_novel.py --rd 32157
```

### Q3: 重试后仍然失败怎么办？
个别章节可能因服务器问题持续无法访问。可稍后再试，或手动检查该章节在浏览器中能否打开。如果网站正常运行而脚本仍然失败，可以调整 config.json 中的重试参数（增加 `max_attempts` 或 `backoff_base`）。

### Q4: 生成EPUB时报错"未找到章节目录"
请先运行 `download_novel.py` 完成下载，再运行 `build_epub.py`。

### Q5: 生成EPUB时中文显示乱码
EPUB 文件本身使用 UTF-8 编码，大多数现代阅读器（如 Calibre、Kobo、Kindle）都支持。如果遇到乱码，请检查阅读器的编码设置。

### Q6: 如何更改下载延迟？
编辑 `config.json` 中的 `request_delay.min` 和 `request_delay.max` 为你想要的秒数。

### Q7: 如何用代理运行脚本？
```powershell
# 设置环境变量
$env:HTTP_PROXY="http://127.0.0.1:7890"
$env:HTTPS_PROXY="http://127.0.0.1:7890"
```

### Q8: 如何删除下载进度重新下载？
删除对应小说目录下的 `progress.json` 文件和 `chapters/` 文件夹，重新运行下载命令。

### Q9: 下载 cool18 的小说报连不上？
cool18 实测必须走代理（直连连不上）。在 `config.json` 设置全局 `proxy`，
或只给 cool18 单独设置 `sites.cool18.proxy`（见 §3.2）。若代理软件只监听
`127.0.0.1`，跨机使用时要开启“允许局域网连接”。

## 十三、完整示例

以下是一次完整的下载+生成流程：

```powershell
# 1. 安装依赖（仅首次需要）
cd C:\Users\automation\Vibe_Coding\fetech_xs
py -3 -m pip install -r requirements.txt

# 2. 下载所有章节（预计耗时 8~10 小时）
$env:PYTHONIOENCODING='utf-8'; py -3 download_novel.py 32157

# 3. （可选）如果怀疑状态不一致，先检查修复
$env:PYTHONIOENCODING='utf-8'; py -3 download_novel.py --check 32157

# 4. （可选）如果某些章节失败，重试
$env:PYTHONIOENCODING='utf-8'; py -3 download_novel.py --rd 32157

# 5. 生成 EPUB 电子书
$env:PYTHONIOENCODING='utf-8'; py -3 build_epub.py 召唤圣剑

# 6. 找到生成的 EPUB 文件
#    在 fetech_xs/Download/召唤圣剑/召唤圣剑.epub
```
