# 计划书 - ftech_xs 小说下载与EPUB生成工具

## 一、项目概述

| 项目 | 说明 |
|------|------|
| 项目名称 | ftech_xs - 多站点小说下载与EPUB生成工具 |
| 已支持站点 | ① 爱丽丝书屋 `xn--1jqx9a.als1004.space` ② cool18 `www.cool18.com`（论坛型） |
| 运行环境 | Python 3.13.5, 命令: `py -3` |
| 包管理 | `py -3 -m pip install -r requirements.txt` |

**设计原则**: 只需提供一个章节列表入口 URL（或 book_id），脚本自动完成一切——提取书名、作者、章节链接、下载、生成EPUB。入口签名保持稳定，供「统一下载管理器」继续调用。

## 二、架构（v2.0 起多站点）

### 2.1 站点适配器模式

```
fetech_xs/
├── 计划书.md
├── 版本变更.md
├── requirements.txt
├── config.json                    # 全局配置 + 可选 sites.<站点> 覆盖
├── download_novel.py              # 入口（签名不变），内部按 URL 域名分发
├── build_epub.py                  # EPUB 生成（站点无关，不变）
├── sites/
│   ├── __init__.py                # 注册表：按 URL/book_id 分发到适配器
│   ├── base.py                    # SiteAdapter 抽象基类 + 共享工具
│   ├── alice_book.py              # 爱丽丝书屋（原 download_novel.py 逻辑迁入，行为不变）
│   └── cool18.py                  # cool18（论坛型，4 种章节来源）
└── Download/                      # 默认输出根目录（<书名>/chapters/ + progress.json + epub）
```

**为什么用适配器而非"一套脚本 + 每站配置"**：als1004 与 cool18 的差异不是"选择器不同"，
而是**工作流完全不同**（一个"目录页 → 逐章页面"，另一个"帖子列表 → 每帖多章 → 切章去重"）。
用配置文件表达这种差异会变成"规则即程序"，难维护、难单站调试；适配器把公共部分
（进度断点续传、重试退避、请求延迟、文件保存、EPUB）只写一次，每站只实现
「怎么拿章节表」和「怎么拿章节正文」，扩展新站 = 新增一个 `sites/xxx.py` + 注册。

### 2.2 SiteAdapter 接口（sites/base.py）

```python
class SiteAdapter:
    type_id = ""        # 站点标识（日志/分发用）
    domains = []        # 匹配的 host 片段
    site_key = ""       # config.json 里 sites.<site_key> 覆盖段的键名

    def site_config(self) -> dict:
        """全局配置 + sites.<site_key> 覆盖合并（proxy/delay/headers 等）"""

    def resolve_entry(self, session, entry, config) -> str:
        """把 book_id / URL 规整成入口 URL（book_id → 完整 URL）"""

    def fetch_book_info(self, session, entry_url, config) -> dict:
        """返回 {book_name, author, chapters: [{index,title,num?,url,tid?,...}]}
        实现方负责把需要的正文抓全并切好（cool18 在这里抓全部帖子并缓存切章结果）"""

    def download_chapter(self, session, chapter, config, referer="") -> tuple:
        """返回 (ok, html, title, fetched)
        fetched=True 表示真正发了网络请求 → 入口据此决定是否 sleep 礼貌延迟
        （als1004 逐章请求返回 True；cool18 从缓存取返回 False）"""
```

### 2.3 入口分发（download_novel.py）

- 纯数字参数 → 视为 als1004 的 book_id（向后兼容）
- 含 URL → 按域名匹配适配器，默认回落 als1004
- 入口签名、`--rd`/`--check`/`--output-dir` 语义完全不变
- 站点配置覆盖后创建 session（cool18 需要独立代理时可在此生效）

## 三、配置文件设计

### 3.1 全局配置 `config.json`

```jsonc
{
    "output_dir": "Download",
    "proxy": "",                    // 全局代理；留空=不设显式代理（requests 读系统代理）
    "request_delay": { "min": 10, "max": 15 },
    "retry": { "max_attempts": 5, "backoff_base": 30, "backoff_multiplier": 2 },
    "headers": { "User-Agent": "...", ... },
    // v2.0 新增：按站点覆盖（可选）
    "sites": {
        "cool18": {
            "proxy": "",             // 覆盖全局 proxy（cool18 常需代理）
            "request_delay": { "min": 8, "max": 12 }
        }
    }
}
```

`site_config()` 合并规则：`sites.<site_key>` 中 dict 字段与全局 dict 浅层合并，
标量字段直接覆盖；未配置的站点用全局默认。

**不需要** 每本书单独建 config.json。小说名、作者等信息全部从入口页自动提取。

## 四、爱丽丝书屋适配器（sites/alice_book.py）

> 由原 `download_novel.py` 逻辑迁入，行为保持不变，仅封装为适配器。

- 域名：`als1004.space`（含 punycode `xn--1jqx9a`）
- `resolve_entry`：纯数字 → `https://xn--1jqx9a.als1004.space/other/chapters/id/{id}.html`
- `fetch_book_info`：解析 `div.mu_h1 h1` 书名（去《》）、`span:has(a[href*='/search/'])` 作者、
  `/id/(\d+)` book_id、首个 `ul.mulu_list li a` 的 `/book/(\d+)/` source_id、
  `ul.mulu_list li a` 全部章节（过滤卷标 `^第[^章]+[部卷篇集]`）
- `download_chapter`：HTML 方式取 `div.read-content.j_readContent` → 失败切 AJAX
  `GET /home/chapter/info?id=&key=` → 仍失败返回 False（由入口统一退避重试）
- `fetched=True`（每章一个请求，入口在章节间 sleep 礼貌延迟）

## 五、cool18 适配器（sites/cool18.py）

论坛型站点：一个帖子（threadview）正文里含一批章节；后续章节可能以多种方式发布。

### 5.1 四种章节来源（统一归并为"帖子源"集合）

| 模式 | 触发 | 章节来源 |
|---|---|---|
| A. 作者在正文里维护列表 | threadview 入口，正文开头有 `<B><font size=4>` 链接块 | 主贴正文 + 列表链接的帖子 |
| B. 章节放跟贴 | threadview 入口，调 `achildlist` 接口 | 主贴正文 + 章节型跟贴 |
| C. 单帖 | 以上都没有 | 仅主贴正文 |
| D. 搜索页 | threadsearch 入口 | 搜索结果的帖子 |

**关键点（用户实测反馈）**：无论 A/B/C，帖子链接**本身就是正文**——每个源帖子
都会被抓取正文并切章，链接不只是目录。跟贴列表静态 HTML 为空，需调 AJAX 接口：

```
GET index.php?app=forum&act=achildlist&tid=<root tid>   →  JSON 数组
每项: {tid, uptid, subject, uid, username, dateline, size}
```
跟贴需按 subject 过滤（必须是 `【书名】（范围）作者` 格式才算章节帖；
"点赞支持"之类回复要剔除）。搜索页**不能用** `first=1`（只看主贴会漏掉用跟贴发布的章节）。

### 5.2 章节切分规则（sites/cool18.py `_split_content`）

正文 `<div class="content-section"><pre>` 内按以下标记切章：

| 标记形态 | 示例 | 章节标题 |
|---|---|---|
| `第X章 + 小标题` | `第四章 搞错了人  <br />` | `第4章 搞错了人` |
| `第X章 + 【字数】` | `　　第五十四章【字数：9535】<p></p>` | `第54章` |
| `第X章`（中文/阿拉伯） | `　　第35章<br />`、`　　第四十章<p></p>` | `第35章` / `第40章` |
| 裸数字段落 | `    5<p></p>`、`　6<p></p>`、`----10` | `第5章` / `第6章` / `第10章` |
| 全角空格 + 4 位补零数字 + 紧跟标题 | `　　` `0073她成为监视养父的帮凶……【微H】<p></p>` | `第73章 她成为监视养父的帮凶……【微H】` |
| 全角空格 + 数字 + 「、」 + 标题（可被 `<strong>` 包裹） | `　　<strong>1、十事神谕</strong>`、`　　35、归心<p></p>` | `第1章 十事神谕` / `第35章 归心` |
| `<strong>/<b>` 包裹的章标记 / 标题后直接换行 | `　　<strong>第一章 召唤与结果</strong><p></p>`、`第1章 标题\n正文` | `第1章 召唤与结果` |
| 特殊章名（无编号，可带「第X卷」前缀） | `　　序章<p></p>`、`<strong>幕间</strong>`、`第一卷 终章` | `序章` / `幕间` / `终章`（不做「第N章」包装） |
| 英文 Chapter 标记（可拼错/大小写不一） | `Chapter1 钟楼俱乐部`、`chater16 暴雨将至`、`chapter22 别骗自己的心`、`Chapter44、欲（…）` | `第1章 钟楼俱乐部` / `第44章 欲（…）` |
| 被（括号）包裹的章标记 | `（第47章 池中鸳鸯） （中）`、`（第52章 禁欲的终结）` | `第47章 池中鸳鸯（中）` / `第52章 禁欲的终结` |
| 标题行标记（书名/标签在前，章号在行尾） | `凌辱之一生性奴（校园，凌辱，痴女，女主视觉） 第十七章`（书名还可能被截断） | `第17章` |
| 尾部无编号番外/特供章 | `番外：新春快乐`、`七夕特供礼物（上）`、`七夕特供礼物（下）` | 独立「番外/特供（上）」章 |
| 外传帖（标题范围含「外传」） | `【柔情肆水】（外传 神奇药膏）作者` | 整帖一章「外传 神奇药膏」（不按内部标记切） |

处理细节：
- 章节号中文/阿拉伯/全角数字（`０８４`）统一转阿拉伯数字（**所有**标记正则都含 `０-９`，
  `第１７章` 也能识别；小数卷章号 `２.１` 归一为 `2.1`）
- 标题噪声清理：`第四十三章 我的校花女友苏浅柔被寝取成精瘾反差婊 43【字数：7124】`
  → 用书名剔除重复 + 去掉纯数字残留 → `第43章`
- 裸数字只接受"标题区间内"或"连续递增段"的数字，防止正文孤立数字误判
- 4 位补零标记要求**前导 0**（如 `0073`），避开正文里的年份（`2025`）等普通数字
- 「数字+、」标记用顿号（`、`）与正文里的枚举列表（常用句点 `1.`/`2.`）区分
- 切章前先去掉行内 `<strong>`/`<b>` 标签，否则被它们包住的章标记识别不到
- 特殊章名（序章/序幕/幕间/终章/尾声）单独成章，不套「第N章」（同号会跨卷重复，靠 tid 排序保持顺序）
- **范围帖前缀拯救**：帖子声明 (N-M) 但第一个标记的章节号 > N（开头章节作者没写标记直接贴正文）→
  把第一个标记前的正文按 N 兜底成缺失的开头章节（剥掉头部作者信息；无实质正文则不兜底）。
  适用于像《柔情肆水》(45-46)/(53-54)/(57-58) 这种前章无标记的帖子
- **标题行标记**：作者把「第X章」写在标题行末尾（行首是书名+标签，如
  `凌辱之一生性奴（校园，凌辱，痴女，女主视觉） 第十七章`），普通正则的行首边界对不上；
  用补充扫描识别（第X章前 ≤45 字、章号在行尾、行内含（、【或已知书名才认，避免正文误判）。
  书名还可能被截断（如少个「凌」字）。作者常把「标题行 第X章」和独立「第X章」两连发：
  紧邻时保留后一个（正文起点干净），相隔远时后一个在前一章正文范围内（重复标记）→ 丢弃，
  这样像「第一章标题行 + 契子 + 重复的第一章」能保住契子
- **跟贴宽松判定**：跟贴标题常见三种形态——①`【书名】（范围）作者：xx`（旧判定）、
  ②无作者后缀（如 `【书名】（1-3）`、`（16-19）全文终`）、③裸范围（如 `01-24`、`159-171（终）`）。
  `_fetch_replies` 用 `_LIST_CHAPTER_RE` + `_BARE_RANGE_RE` 双判定，评分/灌水噪声不含该格式会被过滤。
  `_parse_title` 同步支持 `《书名》（全）` 主贴和裸范围标题（无书名时返回 (None, 范围)）；
  注意作者标题范围可能写得偏宽（如标题 24-47 但正文从 25 开始，上一帖末尾已有 24）
- **卷/节结构帖（老帖）**：主贴只有简介，章节在跟贴里，跟贴标题「第X节　标题（N-M）」
  （括号内是该节内的小节号，非全局章号；还有 `第五节　１－２` 无标题形态）。
  帖内用同形标题行「第X节　标题（N）/（N上/下）/（上/下）」分小节，每个小节一章
  （全半角数字、空格随意；标题可能与上一段粘在一起，不要求行首边界）。
  章节号用帖内顺序，全局排序靠 tid+帖内顺序；作者重复粘贴的同名小节去重（保长版），
  同名但内容不同（标题贴错的续段）保留不丢内容；卷分隔帖「第X卷」无正文，不抓
- **老帖噪声清理**：6park 水印（`<font>`包裹及裸文本）、版主编辑记录，在段落化时剥除；
  帖子开头可能残留「第二卷 XXX」「第五章」等孤立行，在首个小节标题行前会被自然丢弃
- **外传帖整章**：标题范围含「外传」的帖子不再按内部标记切章，整帖作为一章（标题用外传名，
  去「完」后缀）。原因：外传短篇通常没有「第X章」标记，且内部章节号常与主线撞号
  （如外传「表妹的口交养成1」里的第7/8章会跟主线第7/8章混在一起）。
  外传单章在最终列表里排在主线之后（按各自 tid 排序）
- 标题范围兼容「完/完结」后缀（`60完`、`59-60完结` → 60 / [59,60]），单章帖可整篇兜底
- 兜底/外传/前缀拯救生成的章节正文会剥离帖子头部（【书名】（范围）作者：…日期…），避免头部噪声进正文
- **书名目录名**会做 Windows 非法字符替换（`\ / : * ? " < > |` → 全角），
  否则像《阴胎真经:奼女孕奴录》（半角冒号）会直接 `mkdir` 失败（download_novel / build_epub 两处一致）
- 作者名优先取 h1 的`…作者：xx`，h1 未写时回退到正文头部的`作者：xx`
  （例如“认贼作父的我被戴上项圈”h1 只写“迪斯马的头”，正文头才是完整的“迪斯马的头颅”）
- `=====` 分隔线从正文中清除
- 带番外名的正式章节（`第四十五章 番外五：…`）就是普通章节，不拆；`35+番外`
  这种**无编号**的番外拆成独立章节并紧跟在所属章之后

### 5.3 抓取与去重（fetch_book_info）

1. thread 模式：抓主贴（取书名/作者/正文/内部列表）→ 抓内部列表链接的帖子 →
   调 `achildlist` 抓章节型跟贴 → 每个帖子抓正文并切章（带礼貌延迟，缓存到 `_split_cache[tid]`）
2. 搜索模式：从入口页起逐页抓结果列表（跟随"下一页"，空页停止）→ 按关键词 + 章节格式过滤
   → **按作者分组选书** → 抓正文切章。支持两种搜索入口：
   - `bbs4/index.php?...threadsearch&keywords=…`：`ul.post-list.thread-list li`（纯文本标题）
   - `search.php?keyword=…&sa=…`（全站搜索）：`div.search-content ul li`，每个 `<a>` 第一行是
     版块名（如【禁忌书屋】）、第二行才是【书名】（范围）作者——取最后一行跳过版块名；
     关键词命中字被 `<b>` 包裹，`get_text("")` 取文（不带空格）；帖子链接是绝对 URL，直接拿来抓帖
   - 分页：threadsearch 用 `a.next`；search.php 用数字分页（`?p=N`，取最大页码逐页跟进）
   选书规则（避免搜索结果混入别本书时下错书）：
   - URL 带可选 `&author=作者名` → 只取该作者的帖子（匹配不到则报错并列出实际作者）；
   - 不带时若只有一个作者组 → 直接下载（旧行为）；
   - 不带时若有多个作者组 → **打印候选清单（编号/作者/帖数/代表标题）并停止**，
     提示用户把作者名拼到 URL 的 `&author=` 后重跑，绝不静默取最大组
3. **章节号容忍**：作者编号常常随心所欲（如 12-13 之后是 2.1-2.3、跨卷重号），因此：
   - 正文切章时若来源帖标题范围带同卷号（如 `2.1-2.3`），自动给正文里的"第1/2/3章"
     补上卷前缀 → `第2.1章`…；跨卷合集（如 `1.0-2.3`）不补
   - 正文只取 `div.content-section > pre`，避开 `</pre>` 之后的广告位/AI标记/内联脚本
     （否则这些杂项会被当成最后一章正文）
4. **去重**：同一章节号出现多版本时，仅当内容高度相似（节选/预告/极短占位如
   "【未完待续】"/近乎重发）才保留最完整版本；卷号不同的同号章节（第2.1章 vs 第1章）
   视为不同章，都保留
5. **排序**：按"帖子发布时间"（tid 升序 + 帖内顺序）编 0 基索引——**不按章节号排序**，
   因为编号不可靠。文件 `{序号:04d}_标题.html`，EPUB 按序号排序，前后衔接不会乱
6. `download_chapter` 从 `_split_cache` 提取（`fetched=False`，不重复请求）

### 5.4 正文转 HTML

`<br />`、`<p></p>` 段落分隔 → `<p>…</p>`；去掉 `　　` 段首缩进（交给 EPUB 的
`p{text-indent:2em}` 处理）；图片文件名（如 `ezgif-...gif`）以文本保留（本期不抓图）。

## 六、入口主流程（download_novel.py）

```
parse_args() → (retry_failed, check_mode, output_dir, positional)
  - 解析 --rd/--check/--output-dir 和位置参数（与原版一致）

main():
  1. 加载全局 config.json → 按入口分发站点适配器 → adapter.site_config()
  2. 用站点配置创建 requests.Session（headers/proxy）
  3. adapter.resolve_entry() → 入口 URL
  4. adapter.fetch_book_info() → {book_name, author, chapters[]}
     - cool18 在此抓全所有帖子并缓存切章结果（含礼貌延迟）
  5. 创建 <book_name>/ 与 chapters/，加载/创建 progress.json
  6. 预填 chapter_titles（本次抓取的完整标题，含小标题）

  情况C — check_mode=True:
    7c. 按「期望文件名」（索引 + 清洗后的标题）扫描 chapters/ → 得 ready / missing / stale
        （章节表更新后旧文件名不再匹配 → 视为 missing；旧文件归 stale 并删除）
    8c. 用 ready/missing 重置 downloaded / failed
        （新增章节不在磁盘 → 自动进 failed → 可用 --rd 补下）
    9c. 保存并打印

  情况A — retry_failed=True:
    7a. 从 failed 移除待重试章节并立即保存
    8a. 仅下载这些章节（成功→downloaded，失败→重新 failed）
    9a. 更新 status

  情况B — 正常下载:
    7b. 同样按「期望文件名」核对磁盘 → ready / missing / stale
        （不再单凭 progress.status==complete 就退出——旧进度可能与新章节表不符）
        先删除 stale 旧文件；missing 为空才标记 complete 并退出
    8b. for each missing chapter:
          download_with_retry(adapter.download_chapter)
          成功 → save_chapter + 更新进度
          失败 → 加入 failed
          fetched=True 时 sleep(随机延迟)（cool18 缓存命中不 sleep）
    9b. 排序 downloaded/failed 后写盘；打印统计
```

**进度文件 progress.json**（字段与 v1 一致，管理器无需改动）：
```jsonc
{
  "book_name": "…", "author": "…", "chapters_url": "<入口URL>",
  "total": 56, "downloaded": [0,1,…], "failed": [],
  "last_index": 55, "status": "complete",
  "chapter_titles": { "0": "第1章 冯莹莹", "54": "第55章 …" }
}
```

**关于更新（--check 检测最新章节）**：`--check` 每次都重新抓取入口 URL 重建章节表
（cool18 会重新抓主贴 + achildlist + 各帖子），与磁盘对比——**能发现同一入口下新增的章节**，
写入 failed 后再 `--rd` 下载。这是断点续传之外的另一层"追更"机制。

**关键点：磁盘核对以「期望文件名」为准**（`{index:04d}_{清洗后标题}.html`），
而不是只看索引是否存在。否则当章节表整体变化（如识别修复后章数从 3 变 17）时，
旧文件恰好占用了同样的索引，会被误判为“已下载”；旧版还会因 `status==complete`
而直接退出，导致新章节永远下不下来。

## 七、错误处理

| 错误 | 处理 |
|------|------|
| config.json 缺失 | 使用内置默认值 |
| 入口页 GET 失败 | 按 retry 配置退避重试，仍失败则报错退出 |
| cool18 单帖抓取失败 | 该帖章节标记失败（可 --rd 重试） |
| 章节正文为空/无标记 | 返回失败，入口统一退避重试 |
| cool18 章节不在缓存中 | 下载返回失败并标记（异常情况） |
| chapters 目录无文件 | build_epub 报错退出 |
| `--rd` 但 failed 为空 | 提示无需重试，退出 |
| `--check` 但书目录不存在 | 提示先下载，退出 |

## 九、已知边界与限制

- cool18 必须走代理（实测直连失败，代理 `127.0.0.1:10808` 返回 200）——通过
  `config.json` 的全局 `proxy` 或 `sites.cool18.proxy` 配置
- 图片只保留文件名文本，不抓图（本期范围外）
- thread 模式（作者列表/跟贴）只覆盖"主贴 + 列表链接 + 一级跟贴"；若某章节以
  更深层嵌套回复发布，可能漏——此时改用搜索模式（搜索结果包含所有帖子）
- 搜索模式依赖站点搜索索引；刚发布的跟贴章节可能暂时搜不到（稍后重试即可）
- `--check` 在 cool18 上会重新抓取全部帖子（为获取准确章节表与标题），耗时较
  直连式站点长，属正常现象
