# 版本变更记录

## v0.12.0 — 2026-07-03

### 变更内容

#### 高级模式字母无限使用（修复）

**问题**
- 高级模式真实字母使用次数有限（如某字母出现2次则remaining=2），用完后变灰
- 变灰会暗示用户"这个字母不需要了"，降低了高级难度

**解决方案**
- `render()` 中高级模式真实字母的 `count` 从实际次数改为 `Infinity`
- 点击后 `remaining` 仍为 Infinity，永不归零，不会加 `used` class
- `restoreLetter()` 中 `isFinite()` 检查自动跳过 Infinity，无需额外修改

**代码变更**

| 文件 | 变更 |
|------|------|
| `js/letter-selection-panel.js` | `render()` 第68-70行：`count` 改为 `difficulty === 'hard' ? Infinity : count` |

---

#### 跨关卡单词去重

**问题**
- 生成的 PuzzleSet 中，不同关卡之间存在单词重复（如 `head` 出现在第1关和第2关）
- 无法覆盖所有单词：451个单词中仅覆盖309个（68.5%）

**解决方案**
- `buildPuzzleSet()` 新增 `usedWords` 参数，在采样前过滤掉已使用的单词
- `generatePuzzleSets()` 维护并传递 `usedWords` Set，每生成一个成功 puzzle 后将其单词加入集合
- 每个 puzzle 包含 3-5 个单词（不再固定4个），便于灵活覆盖剩余单词
- 当可用单词不足 3 个时停止生成

**代码变更**

| 文件 | 变更 |
|------|------|
| `scripts/puzzle-generator.js` | `DIFFICULTY_CONFIG` 改为 `{ minWords: 3, maxWords: 5 }`；`buildPuzzleSet()` 新增 `usedWords` 参数并过滤单词池；`generatePuzzleSets()` 维护 `usedWords` Set 并在成功后添加 |
| `scripts/generate.js` | 目标数量改为 `ceil(单词数 / 4)`；传递 `usedWords` Set；新增跨关卡重复检测统计 |

**生成结果**
- 111 组 PuzzleSet（目标 113 组）
- 覆盖 448 / 451 个单词（99.3%）
- 无跨关卡单词重复

## v0.11.0 — 2026-07-03

### 变更内容

#### 高级模式提示策略改为按长度随机选位

**问题**
- 高级模式强制以首字母为提示，配合 1~2 个随机非首字母格
- 3 字母单词首字母被硬编码为提示格，增加了被交叉单词覆盖导致自动填满的风险
- 首字母固定提示让用户知道从哪个字母开始，降低了高级难度

**新策略**
- 不再强制包含首字母，所有提示格从全部字母位置中随机选取
- 提示数量按单词长度决定：
  - 3 字母单词：1 个提示

## v0.10.0 — 2026-06-30

### 变更内容

#### 新关卡/取消后自动聚焦第一个空格

**问题**
- 玩完一关进入下一关时，焦点停留在旧位置或没有焦点
- 点击取消清除所有输入后，焦点没有回到第一个空格

**解决方案**
- PuzzleBoard 新增公开方法 `focusFirstEmptyCell()`：找到当前单词的第一个空格并调用 `.focus()`
- `loadLevel()`：render 后调用 `focusFirstEmptyCell()`
- `handleCancel()`：clearValues + render 后调用 `focusFirstEmptyCell()`

#### 删除格子字母后恢复字母按钮状态

**问题**
- 用户点击已填的格子清除字母后，字母面板上对应的按钮没有恢复可用状态
- 初级模式：字母按钮一直保持灰色，无法再次使用该字母

**解决方案**
- PuzzleBoard 新增回调机制：`#onLetterRemoved` + `setOnLetterRemoved(callback)`
- `#setupCell` 清空格子时触发回调，传递被清除的字母
- LetterSelectionPanel 新增 `restoreLetter(letter)`：找到对应 tile 的 `remaining++` 并移除 `used` class
- GameController init 中连接回调：`puzzleBoard.setOnLetterRemoved(letter => letterPanel.restoreLetter(letter))`
- `clearValues()`（取消时调用）不会触发此回调，因为取消后会完整重绘字母面板

#### 字母面板去重（按物理格子而非按单词迭代）

**问题**
- 字母面板遍历单词列表时，共享格被两个单词各计一次
- 例如 HEAD 与 EAST 在字母 A 处关联，A 被推入字母池两次，面板上出现两个 A 按钮
- 初级与中级模式下这提供了多余字母，降低了难度准确性

**解决方案**
- Easy 和 Medium 的字母池构建循环中增加 `seenCells` Set
- 以 `"${row},${col}"` 为 key 去重，同一个物理格子只允许向字母池贡献一次字母
- 共享格（属于两个单词）只计入一次，字母数量与棋盘实际空格数完全一致

#### 自动填满的单词处理（3 字母单词中间格被交叉单词首尾格覆盖）

**问题**
- 初级模式首尾格为提示格，如果 3 字母单词的中间格恰好是另一个单词的首字母或尾字母，则该格也被标记为提示格
- 导致整个单词无需用户输入即自动填满（如 `zoo` + `orange` 交叉）
- 自动填满的单词之后，焦点不会跳到下一个有空格可填的单词

**解决方案**
- **运行时**：`focusFirstEmptyCell()` 增加兜底逻辑，当前单词无空格时自动跳转到 `#findNextIncompleteWord()` 找到的下一个未完成单词
- **生成器**：新增 `hasAutoCompleteWord()` 校验函数，在 `buildPuzzleSet()` 验收条件中与 `isConnected`、`hasAnyParallelAdjacency` 并列检查，避免生成此类题目

#### 代码变更

| 文件 | 变更 |
|------|------|
| `js/puzzle-board.js` | 新增 `#onLetterRemoved` 字段、`setOnLetterRemoved()`、`focusFirstEmptyCell()`（含兜底跳转）；`#setupCell` 清空时触发回调 |
| `js/letter-selection-panel.js` | 新增 `restoreLetter()` 公开方法；Easy/Medium 循环增加 `seenCells` 去重 |
| `js/game-controller.js` | `init()` 连接 `setOnLetterRemoved` 回调；`loadLevel()` 和 `handleCancel()` 调用 `focusFirstEmptyCell()` |
| `scripts/puzzle-generator.js` | 新增 `hasAutoCompleteWord()` 函数；在 `buildPuzzleSet()` 验收条件中增加 `&& !hasAutoCompleteWord(placedWords)` |
| `css/game.css` | 移除 `.letter-tile[data-decoy]` 样式，干扰字母不再视觉可区分 |
| `js/letter-selection-panel.js` | 移除 `dataset.decoy` 赋值（删除冗余标记） |

- `design.md` Section 2.9：LetterSelectionPanel 新增 `restoreLetter()` 职责 + 去重算法更新

## v0.9.1 — 2026-06-29

### 变更内容

#### 修复字母点击不填入棋盘的 Bug

**问题**
- 点击字母面板的字母按钮时，控制台抛出 `TypeError: Cannot read properties of undefined (reading 'classList')`
- 由于该错误发生在 `#handleTileClick` 中，后续的 `fillCurrentCell()` 从未被调用，字母始终无法填入棋盘空格

**根因**
- `letter-selection-panel.js:93` 使用 `tile.element.classList.contains('used')`
- `tile` 是 DOM 元素（`<button>`），没有 `.element` 属性，导致 `tile.element` 为 `undefined`
- 正确写法应为 `tile.classList.contains('used')`（直接对 DOM 元素检查 class），或用 `tileData.element.classList.contains('used')`

**修复**
- `tile.element.classList.contains('used')` → `tile.classList.contains('used')`

#### 代码变更

| 文件 | 变更 |
|------|------|
| `js/letter-selection-panel.js` | `#handleTileClick()` 中 `tile.element` → `tile.classList` |

## v0.9.0 — 2026-06-26

### 变更内容

#### 棋盘输入格从 `<input>` 改为 `<div>`（彻底阻止系统键盘）

**问题**
- 所有输入格使用 `<input type="text">`，在移动设备上点击会弹出系统键盘
- 即使使用字母面板输入，用户仍可能意外触发键盘，遮挡棋盘和字母面板

**解决方案**
- 将所有 `<input>` 改为 `<div class="cell-input" tabIndex="-1">`
- 值通过 `textContent` 读写，完全消除键盘触发
- `#setupInput()` → `#setupCell()`，移除 `scrollIntoView`（不再需要处理键盘遮挡）
- 所有 `.value` → `.textContent`，所有 `.readOnly` → `classList.contains('hint-cell')`
- 提示格同时标记父级 `.cell` 元素（`cell.classList.add('hint-cell')`），便于 CSS 背景样式控制

#### fillCurrentCell() 兜底逻辑（无焦点格自动填入）

**问题**
- `fillCurrentCell()` 依赖 `#focusedCell`，用户点击字母面板前必须先点击一个格子
- 用户期望直接点字母就能填入

**解决方案**
- `fillCurrentCell()` 新增兜底：无焦点格时 → `#findFirstEmptyInWord(currentWordIndex)` → 没找到则 `#findNextIncompleteWord`
- 用户点击字母面板按钮时，即使没点格子，字母也会自动填入当前单词的第一个空格

#### 泡泡糖果风棋盘重设计

**问题**
- 棋盘背景 `#333` 深灰色与整体粉色可爱风不协调
- 暗格使用相同深灰色，视觉上沉重

**解决方案**
- Board 背景：极浅粉色 `rgba(255, 240, 245, 0.5)`，圆角 12px
- 暗格：`transparent`（完全融入 background，不可见）
- 输入格：白色圆角卡片（`border-radius: 6px`）+ 浅粉边框 `#FFD1DC` + 柔和阴影
- 焦点格：粉色边框 `#FF69B4` + glow 光晕
- 提示格：粉色调（`#FFF0F5` 背景 + `#C71585` 文字），替代原来的绿色调

## v0.7.0 — 2026-06-26

### 变更内容

#### 布局重构（移动端适配）

**问题**
- header 和 hints 部分在某些情况下不固定
- hints 区域占据过多空间，按钮位置不稳定

**解决方案**

  - `game-main`：`flex: 1` + `overflow: hidden`
  - `board-container`：`overflow-y: auto` + `-webkit-overflow-scrolling: touch`
  - `game-footer`：`flex-direction: row`，hints（flex: 1，可滚动）和按钮（flex-shrink: 0）并排

#### 格子尺寸固定为32px

**问题**
- 格子尺寸在手机端过大，导致9列棋盘无法在375px屏幕上完整显示

**解决方案**
- `#calculateCellSize()` 移除参数，固定返回 `this.#cellSize = 32`
- 字体：input 14px，cell-number 8px
- 验证：9列 = 304px，10列 = 338px，均可在375px屏幕上显示

#### 平行相邻约束算法

**问题**
- 原有的逐格子检查过于严格（禁止任何相邻），导致无法生成任何有效的PuzzleSet

**解决方案**
- 新算法：在所有单词放置完成后，检查任意两个**同方向**的单词是否存在格子相邻（共享边）
- 同方向单词相邻且不共享格子 → 视觉上误导用户（看起来像同一单词的一部分）
- 异方向单词交叉共享格子 → 允许（正常的填字游戏交叉）

**算法**
```js
// 收集 w1 的所有格子坐标
const w1Cells = new Set();
for (let i = 0; i < w1.word.length; i++) {
  const r = w1.direction === 'across' ? w1.row : w1.row + i;
  const c = w1.direction === 'across' ? w1.col + i : w1.col;
  w1Cells.add(`${r},${c}`);
}

// 检查 w2 的每个格子是否与 w1 的格子相邻
for (let i = 0; i < w2.word.length; i++) {
  const r = w2.direction === 'across' ? w2.row : w2.row + i;
  const c = w2.direction === 'across' ? w2.col + i : w2.col;
  const neighbors = [[r-1,c],[r+1,c],[r,c-1],[r,c+1]];
  for (const [nr, nc] of neighbors) {
    if (w1Cells.has(`${nr},${nc}`)) return true; // 违规
  }
}
```

#### 每组单词数从5改为4

**原因**
- 4词更容易生成有效的平行相邻无违规PuzzleSet
- 棋盘更紧凑，手机端显示更好

## v0.6.0 — 2026-06-25

### 变更内容

#### 焦点导航优化（按单词顺序跳转）

**问题**
- 原有焦点导航按阅读顺序（从左到右、从上到下）跳转，导致竖向单词的字母顺序被打乱
- 填完一个单词后不会按单词编号顺序跳转到下一个单词

**解决方案**
- 焦点导航改为按单词顺序：填完当前单词的字母后，自动跳到下一个未完成单词的第一个空格
- 处理共享格：如果共享格已被前一个单词填入，后续单词导航时自动跳过
- 点击切换：用户点击某个格子时，在该格子所属的单词中找第一个未完成的，设为当前单词

**算法**
1. 构建导航数据结构：`#wordCellMap`（每个单词的格子列表）、`#cellToWords`（格子→单词映射）
2. 输入字母后，在当前单词中找下一个空格
3. 当前单词完成则跳到下一个未完成单词的第一个空格
4. 点击格子时切换当前单词（选第一个未完成的）

**示例**
```
单词1: CAT (横向) → (0,0)C (0,1)A (0,2)T
单词2: CAR (纵向) → (0,0)C (1,0)A (2,0)R

流程：
  填单词1: C→A→T  ✓
  切到单词2: 跳过已填的C → A→R  ✓
```
