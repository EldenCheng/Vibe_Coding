# HTTP 直链下载器 (http-download) 项目设计文档

> 版本：v0.1.0
> 创建时间：2026-10-08
> 定位：通用 **HTTP(S) 直链文件下载器**，作为统一下载管理器的第四个适配对象，
> 与 `e-download`、`fetech_xs`、`m3u-get-down` 平级、独立可用。
> 起因：下载 GitHub release 大文件（如 kvmem-llama.cpp 运行包）时，wget 不走系统代理、
> 直连 TLS 握手被掐断，需要一个稳定支持代理、断点续传与校验的下载工具。

---

## 1. 项目概述

输入一个 HTTP(S) 直链 URL，把文件下载到 `Download/` 目录（默认），
支持：断点续传、多线程分块、限速、SHA256/MD5 校验、代理、自定义请求头、重名处理。

**不做什么**（一期明确不做）：

- 不做页面抓取/嗅探（那是 m3u-get-down 的事）
- 不做批量 URL 列表（用户确认一期不做）
- 不做 FTP / BT / metalink
- 不做独立进度条 UI，进度通过 `progress.json` + stdout 交给管理器展示

## 2. 需求与设计决策记录

| 编号 | 事项 | 结论 | 来源 |
| --- | --- | --- | --- |
| D1 | 功能范围 | 基础功能（续传/重试/代理/自定义头/重名处理）+ 多线程分块 + 哈希校验 + 限速；批量列表与 insecure 一期不做 | 用户确认 (2026-10-08) |
| D2 | 项目名 | `http-download`，与兄弟项目命名风格一致 | 用户确认 |
| D3 | 配置存储 | 与其它下载器一致：读**脚本自身目录**下的 `config.json`（基于 `__file__`，与 cwd 无关）；管理器直接读写这一份 | 沿用管理器决策 D3 |
| D4 | 输出布局 | 文件**平铺**在 `<output_dir>/` 下；断点文件 `<名>.part`；进度 sidecar 集中放 `<output_dir>/.progress/`（扫描时跳过） | 用户要求"读取目录里的文件然后列出来" |
| D5 | 代理语义 | `proxy` 留空 **≠ 直连**：requests 转而读取操作系统代理（Windows 注册表 / macOS 网络设置）；填了才显式指定 —— 与另外三个下载器语义完全一致 | 沿用既有约定 |
| D6 | proxy 字段 | 刻意**不作为敏感字段**遮罩（否则"留空=不修改"会导致代理永远无法清空） | 沿用 e-download 决策 |
| D7 | 依赖 | 仅 `requests`（管理器环境已装），标准库兜底 | 与兄弟项目一致 |
| D8 | 完成判定 | 提供 `progress.json`（status/bytes_done/bytes_total/actual_sha256），供管理器在不看退出码的前提下判定状态 | 管理器契约 |
| D9 | stdout 协议 | 成功时打印固定格式行 `文件保存到: <绝对路径>` 与 `进度文件: <绝对路径>`，供适配器从日志精确定位产物 | 沿用 e-download 的 "图片保存在:" 模式 |
| D10 | 分块并发默认值 | `concurrency=4`，且文件 ≥ `min_split_mb`(8MB) 才分块；服务器未声明 `Accept-Ranges: bytes` 时自动退回单流 | 设计权衡 |

## 3. 总体架构与文件清单

```
http-download/
├─ http_download.py          CLI 入口：参数解析 → 设置装载 → 调引擎 → 退出码
├─ config.json               配置（管理器直接读写这一份，写前由管理器自动备份）
├─ requirements.txt          requests
├─ 项目设计文档.md            本文件
├─ 版本变更.md
├─ http_down/
│  ├─ __init__.py
│  ├─ settings.py            默认值 + config.json 装载 + 类型校验 + CLI 覆盖合并
│  ├─ utils.py               文件名解析(Content-Disposition/URL)、安全化、重名处理、哈希
│  ├─ progress.py            progress.json 原子读写（sidecar，供管理器与续传判断）
│  └─ engine.py              下载引擎：探测 → 单流/分块 → 限速 → 重试 → 组装 → 校验
└─ Download/                 默认输出目录（运行时创建；产物平铺）
```

模块依赖单向：`http_download.py → engine → (progress, utils, settings)`。

## 4. 配置项（config.json）

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `output_dir` | str | `"Download"` | 输出根目录；相对路径按**项目目录**解析 |
| `proxy` | str | `""` | 如 `http://127.0.0.1:10808`；**留空=读操作系统代理（非直连）** |
| `headers` | object | `{}` | 附加请求头（合并到每个请求；Authorization/Cookie 属敏感字段，管理器里遮罩） |
| `concurrency` | int | `4` | 分块并发数；`1`=单流；上限 16 |
| `min_split_mb` | int | `8` | 文件小于该值不分块（直接单流） |
| `speed_limit_kb` | int | `0` | 全局限速 KB/s；`0`=不限（多线程共享一个令牌桶） |
| `timeout` | int | `30` | 连接/读取超时（秒） |
| `retry.max_attempts` | int | `5` | 单请求最大尝试次数 |
| `retry.backoff_base` | float | `2` | 退避基数（秒） |
| `retry.backoff_multiplier` | float | `2` | 退避倍率（指数） |
| `overwrite` | str | `"rename"` | 重名处理：`rename`（自动加序号）/ `overwrite` / `skip` |
| `auto_verify` | bool | `true` | 若输出目录存在 `<文件名>.sha256`（sha256sum 格式）则自动校验 |

CLI 参数可临时覆盖：`--output-dir --proxy --filename --sha256 --concurrency
--speed-limit --overwrite --header(K:V,可重复) --max-attempts`。

## 5. 下载引擎关键设计

### 5.1 流程

```
解析设置 → 重名/续传预判 → 探测(GET, 拿最终URL/Content-Length/Accept-Ranges/Content-Disposition)
  ├─ .part 存在 → 带 Range 请求：206=续传追加；200=服务器不支持，截断重下；416=先核对大小
  └─ 全新下载 → 若 (concurrency>1 且 大小已知 ≥ min_split_mb 且 Accept-Ranges: bytes)
        → 分 N 段，每段独立连接 + 独立 .part.seg<i> 文件
     否则 → 单流下载 .part
→ (分块时) 拼接段文件 → .part
→ 整文件流式计算 SHA256(+MD5) → 与期望值核对(命令行 --sha256 / sidecar .sha256)
→ 通过: os.replace 为最终文件名, 打印「文件保存到: …」
→ 失败: .part 改名为 <名>.corrupt, 状态 failed（防止坏数据被反复续传）
```

### 5.2 断点续传

- 单流：`<名>.part` 追加写，重启后 `Range: bytes=<已有字节数>-`。
- 分块：段边界由 `(bytes_total, concurrency, min_split_mb)` **确定性推导**；
  每段 `<名>.part.seg<i>` 追加写、断点为该段文件当前大小；`bytes_total` 变了（服务器上文件更新）
  → 全部段文件作废重下，progress 里记录旧 total 以便核对。
- 期望哈希校验失败 → 数据本身就是坏的，续传无意义 → 改名 `.corrupt` 而不是保留 `.part`。

### 5.3 限速与并发

- 全局 `TokenBucket`（线程安全），所有 worker 每读一块先取令牌；
  多线程共享同一个桶，`speed_limit_kb` 是总口径。
- worker 用 `ThreadPoolExecutor(concurrency)`；主线程轮询 futures，每 2 秒把聚合字节数写进 progress.json。

### 5.4 重试

- 粒度是"请求"而非"整个任务"：连接被掐/超时/5xx/429 → 按指数退避重试，
  续传点 = `.part(.seg<i>)` 当前大小，天然断点续传。
- 4xx（除 416/429）直接失败不重试（重试也不会好）。

### 5.5 文件名解析与重名处理

优先级：CLI `--filename` > `Content-Disposition`（RFC 5987 `filename*` 优先）> URL basename（unquote）>
`download_<时间戳>.bin`。统一做 Windows 安全化（去 `<>:"/\|?*` 与控制符、去尾部点空格、限长 200）。

重名（最终文件已存在且无对应 .part）：按 `overwrite` 配置处理；
有 `.part` 视为同一次下载的续传，不走重名逻辑。

### 5.6 校验

- `--sha256` 传 64 位 hex → SHA256；32 位 hex → MD5；其它长度报参数错误。
- `auto_verify=true` 且存在 `<文件名>.sha256` → 按 sha256sum 格式解析首列哈希校验。
- 无论是否提供期望值，完成后都计算并记录 `actual_sha256`（管理器列表可见）。

## 6. progress.json（sidecar）协议

位置：`<output_dir>/.progress/<安全文件名>.<url-md5前8位>.json`，原子写（tmp+replace）。

```json
{
  "url": "…", "file": "kvmem-….zip", "path": "H:\\…\\Download\\kvmem-….zip",
  "status": "downloading",          // downloading | complete | failed
  "bytes_done": 123456, "bytes_total": 683600000,
  "concurrency": 4, "resumable": true,
  "expected_hash": "…", "hash_algo": "sha256", "actual_sha256": "…",
  "error": "", "note": "",
  "started_at": "…", "updated_at": "…", "finished_at": ""
}
```

## 7. stdout 输出协议（供适配器解析）

| 行 | 含义 |
| --- | --- |
| `任务开始: <url>` | 任务起点 |
| `进度文件: <绝对路径>` | sidecar 位置（适配器兜底定位） |
| `保存文件名: <名>` / `文件大小: …` / `断点续传: 是/否` / `分块数: N` | 探测结论 |
| `下载中: x MB / y MB (z MB/s)` | 每 5 秒 |
| `文件保存到: <绝对路径>` | **成功锚点**，适配器最可靠的定位依据 |
| `SHA256: <hash>` / `SHA256 校验通过/失败: …` | 校验结论 |
| `文件已存在，跳过: …` / `已改名为: …` | 重名处理结果 |

退出码：`0`=全部成功；`1`=失败（含校验失败、参数错误）。

## 8. 与统一下载管理器的集成

- 管理器侧新增 `backend/adapters/http_download.py`，注册进 `ADAPTER_CLASSES`；
  管理器 `config.json` 的 `projects` 增加 `"http": {"dir": "../http-download"}`。
- 适配器实现 `build_launch`（拼 CLI）、`finalize`（读 sidecar + 日志锚点判定）、
  `scan`（扫 `Download/` 的平铺文件，跳过 `.part/.seg/.corrupt/.progress/.sha256`）、
  `available_actions`（提供「续传/重下」= 重跑同一 URL）。
- `base.py` 的 `DownloadItem.to_dict()` 原本只统计目录大小，需补一个"文件条目"分支（几行）。
- 前端**零改动**（标签页/表单/列表全部由 `/api/adapters` 数据驱动）。

## 9. 已知限制

- `Content-Length` 未知的响应不支持分块（自动退回单流），仍可续传。
- 服务器不支持 Range 时无续传、单流。
- 不处理 gzip/bzip 传输编码以外的东西；不校验 TLS 证书以外的内容签名。
- HTTP→HTTPS 重定向后代理规则跟随 requests 默认行为。
