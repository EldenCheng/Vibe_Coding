# 计划书 - e-download E-Hentai 漫画下载工具

## 一、项目概述

| 项目 | 说明 |
|------|------|
| 项目名称 | e-download - E-Hentai 画廊图片下载工具 |
| 目标网站 | `https://e-hentai.org`（画廊页 /g/、查看页 /s/、MPV API /mpv/） |
| 运行环境 | Python 3.13+, 命令: `py` |
| 包管理 | `py -m pip install -r requirements.txt` |

**设计原则**: 只需提供一个画廊 URL（如 `https://e-hentai.org/g/3743290/8eee725d8c/`），脚本自动完成——解析标题、获取全部页面地址、单线程限速下载、断点续传、失败重试、文件校验。

**核心需求（来自 设计/项目提示词.txt 及用户确认）**:

1. 下载网页显示的图片（**不下载原图**，忽略 `/fullimg.php` 链接，只取 `<img id="img" src>`）
2. 图片命名 `{页码:04d}_{网页显示名}`，解决油猴脚本"原名与网页名不一致导致顺序错乱"的问题
3. 进度落盘（progress.json），**关闭窗口/崩溃后可续传**（油猴脚本不可续传是其浏览器内存存储实现限制，非网站机制）
4. 可指定下载范围，语法 `--range 1-10,20,30-40`
5. 单线程下载，每张图片前随机等待 3~5 秒
6. 配置文件支持 proxy、延迟、重试、headers、cookies
7. `--rd` 重试失败页、`--check` 校验实际文件（参考 fetech_xs 实现模式）

## 二、技术栈

| 库 | 用途 |
|----|------|
| `requests` | HTTP Session、Cookie 维持、代理、下载 |
| `beautifulsoup4` + `lxml` | 画廊页解析（标题、缩略图链接） |
| `re`、`json`、`pathlib`、`random`、`time`、`html`、`sys`、`urllib.parse` | 标准库 |

## 四、配置文件设计

### 4.1 全局配置 `e-download/config.json`

```json
{
    "proxy": "",
    "use_mpv": false,
    "request_delay": {
        "min": 3,
        "max": 5
    },
    "retry": {
        "max_attempts": 3,
        "backoff_base": 30,
        "backoff_multiplier": 2
    },
    "timeout_page": 30,
    "timeout_image": 120,
    "headers": {
        "User-Agent": "Mozilla/5.0 ... Chrome/125.0.0.0 Safari/537.36",
        "Accept-Language": "zh-CN,zh;q=0.9,en;q=0.8",
        "Referer": "https://e-hentai.org/"
    },
    "cookies": {
        "ipb_member_id": "",
        "ipb_pass_hash": ""
    }
}
```

| 字段 | 说明 |
|------|------|
| `proxy` | 如 `http://127.0.0.1:7890`，空字符串表示不使用代理（注意：requests 默认还会读 Windows 系统代理，见 5.7 图片双通道说明） |
| `use_mpv` | 是否尝试 MPV API 获取页面列表（默认 false；游客/普通会员基本用不上，关闭可省一次无效请求） |
| `request_delay` | 每页下载前的随机等待秒数（默认 3~5，勿调太小） |
| `retry` | 失败重试次数与指数退避（30s → 60s → 120s） |
| `timeout_page` | HTML 页面请求超时（秒） |
| `timeout_image` | 图片请求超时（秒，图片较大给长一些） |
| `headers` | 全局请求头，`Referer` 下载图片时会被覆盖为查看页 URL |
| `cookies` | 可选登录态（ipb_member_id / ipb_pass_hash），公开画廊留空即可 |

## 五、模块设计

### 5.1 命令行

```powershell
py download_gallery.py <画廊URL>                    # 下载全部/断点续传
py download_gallery.py --range 1-10,20,30-40 <URL>  # 只下载指定页码范围
py download_gallery.py --rd <URL>                   # 重试 progress.json 中 failed 页
py download_gallery.py --check <URL>                # 按 images/ 实际文件校正进度
```

- `--range` 与 `--rd` 可组合（--rd 时只重试 failed 中落在范围内的页）
- 页码从 1 开始计数，超出总页数的页码会被忽略并提示
- 无 `--range` 时目标 = 全部 1..total；`downloaded` 中的页自动跳过（续传/补下载）

### 5.2 主流程

```
parse_args() → (range_text, retry_failed, check_mode, [gallery_url])

main():
  1. 加载 config.json（缺失字段用内置默认值补全）
  2. 创建主 session（headers / cookies / 系统或配置代理）
     与直连 session（trust_env=False，图片下载专用通道）
  3. 解析 URL → gid、token（正则 /g/(\d+)/([0-9a-f]+)/）
  4. GET 画廊页 → fetch_gallery_info 返回完整信息字典（见 5.4）
  5. 获取页面列表 page_infos: [{key, page, nl}]：
     a. config.use_mpv=true 时尝试 MPV API（默认关闭，直接走 b）
     b. 解析画廊页 #gdt 缩略图链接，并翻页 ?p=1,2... 收集全部
  6. 按 build_dir_name 规则生成目录名（[分类][语言]前缀；旧目录存在则沿用）
  7. 每次运行刷新写入 info.md（基本信息表 + 双语标签表）
  8. 加载/初始化 progress.json（含 subtitle 字段）
  9. 计算下载目标列表（--range 过滤 − downloaded；--rd 则取 failed）
  10. 单线程逐页下载（见 5.6、5.7）
  11. 输出统计：成功 X/总数，失败 Y
```

### 5.3 页面列表获取

**方式 A — MPV API（config.use_mpv = true 时才启用）**:

```
GET {base}/mpv/{gid}/{token}/
响应 JSON: {"gid": ..., "token": ..., "imagelist": [{"k": 页key, "p": 页码, "nl": nl值}, ...]}
每页查看地址 = {base}/s/{k}/{gid}-{p}
nl 值用于访问查看页时的 ?nl= 参数（预载令牌，缺省时用逐页解析的下一个 nl）
默认关闭: 游客/普通会员访问 MPV 会得到 "eeenope"，直接走方式 B 更省事
```

**方式 B — 画廊页缩略图（回退）**:

```
解析 #gdt 内 <a href="/s/{k}/{gid}-{p}"> 链接
画廊页默认只显示前 40 张，继续 GET ?p=1、?p=2 ...
直到某页解析不出新的 key 为止（用已见 key 集合去重判定）
```

### 5.4 画廊信息解析（fetch_gallery_info）

```
输入: session, config, base, gid, token
输出: (info, error)
  前置处理 — 内容警告页（Content Warning）:
    画廊页含 "Content Warning" 或 nw=session 链接时（无 #gn/#gdt 的确认页），
    自动 GET {gallery_url}?nw=session —— 该响应即真实画廊页，服务器同时
    下发会话 Cookie（requests 自动保存），后续请求不再触发警告
  info = {
    title    主标题 <h1 id="gn">
    subtitle 副标题 <h1 id="gj">（日文原名等，可能为空）
    category 分类 #gdc（Manga/Doujinshi/Game CG...）
    uploader 上传者 #gdn
    posted   发布时间（#gdd "Posted:" 行）
    language 语言（#gdd "Language:" 行）
    file_size 文件大小（#gdd "File Size:" 行）
    length   页数文本（#gdd "Length:" 行，如 "1835 pages"）
    favorited 收藏数（#gdd "Favorited:" 行）
    rating   评分（#rating_label，去掉 "Average:" 前缀）
    tags     [(分组, [标签...]), ...] 有序列表（#taglist，保留网页分组顺序）
  }
  error = None 成功 / "not_available" 画廊 404 / "network" 网络失败
```

### 5.5 目录名规则（build_dir_name）

```
输入: title, subtitle, category, lang
规则:
  1. 前缀 = [分类][语言]（缺省省略）:
     - 分类 = 网站 Category 原样英文（Cosplay/Misc/Game CG...）
     - 语言 = 标签 language 分组中第一个实际语言值（小写，如 chinese；
       仅 translated/speechless 等非语言标签或无该分组时不加）
  2. 主体 = 主标题[+副标题]（build_base_name）:
     - 主标题 ≤ 40 字符 且有副标题 且 副标题 ≠ 主标题 → 追加副标题
       副标题以 [ 开头 → "主标题 (副标题)"（圆括号避免 [ [ 嵌套）
       否则          → "主标题 [副标题]"
     - 主标题本身 > 100 截断
  3. 整体总长 > 100 → 截断（前缀计入，截尾部并清理残留括号）
  4. 非法字符替换为空格（如 [C:drive.] → [C drive.]），合并连续空白
  5. 兼容: 旧规则目录（无前缀）已存在时沿用旧目录名，保证续传进度不丢
示例:
  [Cosplay]The little Vampyr - Ekko
  [Misc][chinese][ZONE] 校园奴隶契约 4
  [Misc][chinese][禾樱] 十二品阶（上+下）
```

### 5.6 单页解析（parse_view_page）

```
输入: 查看页 HTML（/s/{k}/{gid}-{p}）
输出: (img_url, shown_name, next_nl)

1. 图片地址（网页显示图，非原图）:
   - 主: /<img id="img" src="(\S+?)"/
   - 备: /<\/(?:script|iframe)><a[\s\S]+?><img src="(\S+?)"/
     （部分页面 preview 图没有 id="img"，移植自油猴脚本）
   相对路径用 urllib.parse.urljoin 转绝对

2. 网页显示文件名:
   - 主: /g\/l\.png"\s?\/><\/a><\/div><div>([\s\S]+?) :: /（移植自油猴脚本）
   - 备: /<div[^>]*>([^<>]{1,200}?) :: \d+x\d+/
   html.unescape 反转义；清洗非法字符；无扩展名时从图片 URL 推断

3. 下一个 nl: /return nl\('([\d\w-]+)'\)/（用于下一页的 ?nl= 参数）
```

### 5.7 图片下载（download_image_with_retry，双通道）

```
背景: 系统代理（如 Clash 127.0.0.1:7890）对部分 hath.network 图片节点
      （非标端口）会主动 RST（10053），直连反而稳定；而另一些场景图片必须走代理。
      因此采用双通道自动切换。

通道1（直连）: trust_env=False 的独立 session，绕过系统代理
  - 单次尝试，超时上限 15s（快速失败，不拖慢进度）
通道2（代理）: 主 session（系统代理 / config.proxy）
  - 完整重试 max_attempts 次 + 指数退避

两条通道均校验:
  - 状态码 200
  - 内容非空
  - Content-Length 存在时与实际大小一致（防截断）

保存: images/{页码:04d}_{显示名}
每张成功/失败后立即写 progress.json
```

### 5.8 info.md 生成（build_info_md）

```
每次运行脚本时刷新写入画廊目录下的 info.md:
  1. H1 标题 = 主标题
  2. 基本信息表（| 项目 | 内容 |）: 副标题/分类/上传者/发布时间/语言/
     文件大小/页数/收藏/评分（字段为空则省略该行）
  3. 标签表（| 分组 | 标签 |）:
     - 分组前缀双语: "female (女性)"（tag_translations.GROUP_PREFIX_TRANSLATIONS）
     - 每个标签一行，用 <br> 换行（避免单格超宽爆格）
     - 标签双语: "anal (肛交)"（tag_translations.TAG_TRANSLATIONS，
       词典未收录的保持纯英文）
     - 内容中的 | 转义为 \| 防止表格破裂
  4. 末尾附画廊链接
```

### 5.9 标签翻译词典（tag_translations.py）

```
GROUP_PREFIX_TRANSLATIONS: 分组前缀翻译（parody/character/group/artist/
  cosplayer/male/female/mixed/other/language/reclass/misc/location/temp）
TAG_TRANSLATIONS: 约 800 条高频标签英中对照（身体特征/服装/性行为/关系剧情/
  属性/多人玩法/场景/风格格式/常见原作等），可自行增补
显示规则: 有译文 → "english (中文)"；无译文 → 纯英文
```

### 5.10 重试与限速

```
页面获取失败（网络异常/非200/空内容/含 "temporarily banned" 提示）:
  attempt ∈ [1, max_attempts]:
    wait = backoff_base × (backoff_multiplier ^ (attempt-1)) 秒
    "temporarily banned" 时额外加长等待（60s 起步）

每页循环内:
  1. 随机等待 request_delay.min ~ max 秒
  2. GET 查看页（带 ?nl=）→ 解析
  3. GET 图片（带重试）→ 保存
  4. 更新 progress.json 并打印进度
```

### 5.11 进度文件 progress.json

```json
{
    "gallery_url": "https://e-hentai.org/g/3743290/8eee725d8c/",
    "gid": "3743290",
    "token": "8eee725d8c",
    "title": "画廊标题",
    "subtitle": "副标题（可能为空字符串）",
    "total": 20,
    "downloaded": [1, 2, 3],
    "failed": [],
    "status": "in_progress"
}
```

| 字段 | 说明 |
|------|------|
| `downloaded` | 已成功下载的页码列表（1 起） |
| `failed` | 下载失败的页码列表 |
| `status` | `complete`（downloaded 覆盖 1..total）/ `in_progress` |

### 5.12 --check 与 --rd

- `--check`: 扫描 images/ 中 `^\d+_` 前缀文件 → 重建 downloaded；缺失页 → failed；保存并打印差异
- `--rd`: 取 failed 中的页（可再与 --range 求交集）重新下载；全部成功且全量完成时 status → complete

## 六、运行流程总览

```
用户                                 脚本
 │                                    │
 ├─ py download_gallery.py <URL> ─────┤
 │                                    ├─ 加载 config.json
 │                                    ├─ GET 画廊页 → 标题/总页数
 │                                    ├─ MPV API → 全部页 key/nl（失败回退 #gdt 翻页）
 │                                    ├─ 创建 <标题>/images/ 目录
 │                                    ├─ 逐页下载（延迟3~5s、单线程）──→ images/0001_xxx.jpg
 │                                    │   └─ 每页即时写 progress.json（续传依据）
 │                                    └─ 完成 ──→ "成功 20/20"
 │
 ├─ （中断后）py download_gallery.py <URL> ──→ 跳过 downloaded，续传
 ├─ py download_gallery.py --range 11-20 <URL> ──→ 补下载指定范围
 ├─ py download_gallery.py --rd <URL> ──→ 重试 failed 页
 └─ py download_gallery.py --check <URL> ──→ 按实际文件校正进度
```

## 七、错误处理

| 错误 | 处理 |
|------|------|
| config.json 缺失 | 使用内置默认值 |
| URL 格式不合法 | 提示用法并退出 |
| 画廊页 GET 失败 | 重试 3 次（指数退避），仍失败退出 |
| 画廊返回 404（已删除或仅登录用户可见） | 明确提示两种可能原因与 Cookie 配置方法后退出 |
| 画廊页为内容警告页（Content Warning） | 自动 GET ?nw=session 确认（响应即真实页 + 会话 Cookie），无需人工干预 |
| 标题提取失败 | 用 `gallery_{gid}` 作目录名 |
| MPV API 失败 | 回退 #gdt 解析 + 翻页 |
| 页面/图片下载失败 | 指数退避重试 max_attempts 次，仍失败记入 failed |
| 页面含 IP 封禁提示 | 加长等待后重试 |
| 图片内容为空/大小不符 | 视为失败重试 |
| 图片直连通道失败（系统代理 RST 等） | 自动回退代理通道重试 |
| info.md 写入失败 | 打印警告，不中断下载 |
| --check 时目录不存在 | 全部页标记为缺失 |
| --rd 时 failed 为空 | 提示无需重试 |

## 八、关键机制说明（回应原始疑问）

| 疑问 | 结论 |
|------|------|
| 油猴脚本关闭浏览器不能续传 | 非网站机制，是其把数据存浏览器内存/临时文件系统的实现限制。本脚本进度落盘 progress.json，天然续传 |
| 下载图片顺序对不上 | 油猴脚本用图片原始文件名（与网页显示名不同）。本脚本统一命名 `{页码:04d}_{网页显示名}` |
| 不下载原图 | 只解析 `<img id="img" src>`（网页显示图），不触碰 `/fullimg.php` 原图链接 |
| 网站限制风险 | 单线程 + 3~5 秒随机延迟；页面带 ?nl= 预载令牌；检测 IP ban 提示自动长等待 |
| 系统代理导致图片下载 10053 | requests 默认读 Windows 系统代理，部分代理对 hath.network 图片节点（非标端口）主动 RST。图片下载采用"直连优先、代理回退"双通道解决（见 5.7） |
