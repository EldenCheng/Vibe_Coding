# sqk-automation 项目设计文档

## 1. 项目目标

通过局域网无线 ADB 控制远程电视盒子（Android TV），实现一部分重复性操作自动化。

项目形态是**一套有编号、有名称的自动化操作集合 + 一个统一命令行入口**，而不是一个个孤立的脚本。
目前已落地：连接检查、屏幕截图。

## 2. 运行环境

- 本机：Windows，Python 3.14（命令为 `py`）
- 依赖：**系统全局安装的 adb**（Android platform-tools，需在 PATH 中）
- 盒子：与本机同一局域网，已开启网络调试（`adb tcpip 5555` 或系统设置里的无线调试）
- 第三方 Python 包：无，仅用标准库

### 2.1 上手步骤

1. 安装 Android platform-tools，把目录加入 PATH，新开终端确认 `adb version` 有输出。
2. 拿到盒子的局域网 IP（设置-网络，或连着盒子时 `adb shell ip addr`），填进 `config/devices.json` 的 `host`。
3. 让盒子开放网络调试：最省事的一次性做法是 USB 连一次执行 `adb tcpip 5555`；之后拔线走无线。
4. `py main.py run connect` 验证连通，之后 `py main.py run screenshot` 或直接双击 `一键截图.bat`。
5. `py main.py list` 随时查看当前有哪些操作、编号是多少。

三层依赖方向：`automations/` → `framework/` + `adb_kit/` → 标准库。
`adb_kit/` 不知道有哪些操作，`framework/` 不知道 adb 是什么。

## 4. 统一入口 main.py

```
py main.py                      # 不带命令时等价于 list
py main.py list                 # 列出所有操作（编号 / 名称 / 一句话说明）
py main.py info 2               # 看某个操作的详细说明和它可用的参数
py main.py run screenshot       # 执行单个操作（按名称）
py main.py run 2                # 执行单个操作（按编号）
py main.py run 1-5              # 执行编号落在 1..5 区间内的所有操作
py main.py run "[1, 3, 5]"      # 执行指定的一组操作
py main.py run 1 3 5            # 同上，空格分隔写法
py main.py run all              # 全部操作，按编号升序
py main.py run all -d 书房盒子   # 全局参数写在子命令之后
```

### 4.1 全局参数（只有这三个）

| 参数 | 作用 |
| --- | --- |
| `-d` / `--device` | 指定 `devices.json` 里的设备名，默认用 `default_device` |
| `-c` / `--config` | 改用指定的 devices.json 路径 |
| `--fail-fast` | 序列中某步失败立即停止；默认是把整串跑完再汇总 |

这三个参数定义在子命令上，必须写在 `list` / `info` / `run` **之后**。
**操作自己的参数不进命令行**，一律写在 `config/params.json` 里（见 §6）。
理由：命令行传参会在"一次跑多个操作"时产生归属歧义。

### 4.2 选择器语法

| 写法 | 含义 | 解析结果 |
| --- | --- | --- |
| `3` | 编号 3 | 单个操作 |
| `screenshot` | 名称 | 单个操作 |
| `1-5` | 编号区间 | 区间内**已存在**的操作，按编号升序；区间里缺失的编号跳过不算错 |
| `[1, 3, 5]` / `1,3,5` | 显式列表 | 严格按书写顺序执行；`[]` 可省略 |
| `all` | 全部 | 按编号升序 |

- 列表项可以混用编号和名称：`[connect, 2]` 合法。
- 列表里写重复项就执行重复次数（`[2, 2]` 会截两张图），这是有意为之，便于连拍。
- 列表里的项必须能解析到具体操作，解析不到直接报错退出，不会静默跳过（与区间的宽松语义相反）。
- Windows 的 cmd 里 `[` 和 `,` 需要整体加引号：`py main.py run "[1,3,5]"`。

### 4.3 执行顺序与退出码

- 执行顺序 = 选择器解析出的顺序；区间和 `all` 是编号升序，显式列表是你写的顺序。
- 退出码：`0` 全部成功；`1` 至少一个操作失败；`2` 配置或选择器本身有问题（一个操作都没跑起来）。
- 单个操作抛异常只影响它自己的结果，默认继续跑完剩余操作。

### 4.4 自检

`py selftest.py` —— 用假 adb 覆盖 adb 封装、命名落盘、注册表校验、编号台账、选择器语法、
参数合并、序列执行，外加一次端到端 `run screenshot`。不接真机、不联网。
**改动 `framework/` 或 `adb_kit/` 后必须跑一遍**；新增操作时也建议跑，能提前发现编号/命名冲突。

## 5. 自动化操作怎么写

一个操作 = `automations/` 下的一个文件，模块级给出这些名字：

```python
number = 2                 # 永久编号，见 §5.1
name = "screenshot"         # 命令行里用的英文标识
title = "抓取盒子屏幕"       # list 里展示的一句话
description = "……"          # info 里展示的详细说明（多行）
default_params = {"open_after": False}   # 本操作可用参数及默认值


def run(ctx):
    """ctx 是 framework.context.Context。"""
    ctx.ensure_connected()
    data = adb.capture(ctx.settings, ctx.device)
    path = screen.save(ctx.settings, ctx.device, data, len(ctx.settings.devices))
    if ctx.param("open_after"):
        os.startfile(str(path))
    ctx.log(f"已保存：{path}")
```

`ctx` 提供的东西：`ctx.settings`（含设备列表与输出目录）、`ctx.device`（本次选中的设备）、
`ctx.param(key)`、`ctx.log(msg)` / `ctx.warn(msg)`、`ctx.ensure_connected()`。

发现机制：`framework/registry.py` 用 `pkgutil` 导入 `automations/` 下所有非下划线开头的模块，
读取上述模块级变量生成 `Operation`。没有 `number`/`name`/`title`/`run` 的模块不会被注册。

约束（注册时校验，违反直接报错拒绝启动）：
- `number` 是正整数且全局唯一；`name` 匹配 `^[a-z][a-z0-9_]*$` 且全局唯一。
  名称里禁止 `-` 和 `,`，否则会和选择器的区间/列表语法打架。
- `default_params` 的键名不能以 `_` 开头（保留给注释用）。

### 5.1 编号台账：编号永不复用

`config/number_ledger.json` 记录"历史上出现过的 编号 → 操作名"：

```json
{ "1": "connect", "2": "screenshot" }
```

- registry 每次加载时比对：新出现的编号会自动登记并打印一行提示。
- 已登记的编号被**另一个名字**的操作占用 → 报错。防止"昨天 3 号是截图，今天 3 号变成别的"。
- 删掉一个操作不会回收它的编号：台账里留痕，后来的人不会误用。

### 5.2 输出文件放哪

截图统一进 `screen_shot/`。新增操作要产出文件时，在项目根下建自己的目录
（例如 `logs/`、`apks/`），并在参数里给出目录名选项，不要把产物丢在根目录。

## 6. 参数文件 config/params.json

```json
{
  "_comment": "每个操作读自己那一段；键名要和 default_params 对得上",
  "connect": {},
  "screenshot": {
    "open_after": false
  }
}
```

- 操作通过 `ctx.param("键名")` 取值，未配置时用模块里的 `default_params` 默认值。
- 写了不存在的键 → 运行时打印一行警告，提示可能是拼错了，不中断执行。
- 这一段是**跨设备共用**的；以后若需要按设备区分参数，再引入 `by_device` 层，当前不做。

## 7. 关键约定

### 7.1 设备配置 config/devices.json

```json
{
  "adb_path": "adb",
  "default_device": "客厅盒子",
  "screenshot_dir": "screen_shot",
  "connect_timeout": 10,
  "devices": [
    { "name": "客厅盒子", "host": "192.168.1.100", "port": 5555, "enabled": true, "note": "备注" }
  ]
}
```

- `adb_path`：默认 `"adb"`（走 PATH）；没进 PATH 时填绝对路径。
- `connect_timeout`：`adb connect` 超时秒数，同时用于等待设备上线。
- `enabled: false`：临时停用某台设备而不删条目。

### 7.2 截图命名

`{日期}_{时间}.png`，例如 `2026-09-20_163012.png`。
配置了多台设备时自动加设备名前缀 `{设备名}_{日期}_{时间}.png`，避免同秒覆盖。

### 7.3 编码与输出

- 文件读写显式 `encoding="utf-8"`。
- `.bat` 必须 **CRLF** + `chcp 65001`（见 §8）。
- 关键步骤打印中文提示；失败时打印 adb 原始 stderr，再附一句排查方向。
- 操作内部一律用 `ctx.log()` / `ctx.warn()`，不要直接 `print`，便于以后统一改成日志文件。

### 7.4 adb 调用方式

统一 `subprocess.run(list, shell=False)` 传参数列表，不做字符串拼接，避免命令注入。
设备寻址一律 `-s <host:port>`，支持同时挂多台设备。

## 8. 已知坑

1. **`.bat` 必须是 CRLF**：编辑工具默认写 LF，LF 的批处理会被 cmd 错行解析（表现为 `'nshot.py' is not recognized...`）。已用 `.gitattributes` 固定 `*.bat text eol=crlf`；手工改完若报错乱跳先查行尾。
2. **无线 adb 会掉线**：盒子重启或空闲后 `adb connect` 会失效。入口每次运行都主动 connect，不做长连接假设。
3. **`exec-out screencap -p` 的二进制安全**：必须 `capture_output=True` 拿 bytes，文本模式会做换行转换破坏 PNG。
4. **部分旧设备 exec-out 会破坏字节流**：`_repair_png` 先按 PNG 头尾定位并还原被展开成 `\r\n` 的 `\n`；仍拿不到合法 PNG 时抛 `ScreencapUnsupported`，`capture()` 自动改用 `screencap` 落文件 + `adb pull`。
5. **Android 11+ 无线调试端口不是 5555**：配对端口与连接端口分开，且重启后连接端口会变。5555 连不上时先用 USB 连一次执行 `adb tcpip 5555`，或走配对流程。
6. **首次连接需要授权**：部分盒子要在屏幕上点"允许 USB 调试"，否则返回 `unauthorized`。
7. **cmd 里选择器要加引号**：`run [1,3,5]` 不加引号时 `[` 前后的字符处理不稳定，统一写成 `run "[1,3,5]"`。
8. **读系统属性必须用 getprop**：`adb shell ro.product.model` 不是合法命令（异常被 except 静默成"未知"），要写 `adb shell getprop ro.product.model`。
9. **PATH 里的 adb**：`adb_path` 写 `"adb"` 走 PATH；PATH 里不含 platform-tools 时改填绝对路径，例如 `C:/Users/<user>/AppData/Local/Android/Sdk/platform-tools/adb.exe`。刚改过系统 PATH 要重开终端才生效。
