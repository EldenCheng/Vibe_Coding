# 讨论记录

本项目开发过程中的需求讨论与决策记录,便于日后回顾。

## 2026-09-15

### 需求提出

用户希望建立一个脚本,用于备份 opencode 的数据:

1. 搜索 opencode 的数据目录(先搜索几个典型的);
2. 按主要数据类型(如 `opencode.jsonc`、session 记录、db)分别压缩,并移动到工作目录中对应的备份目录;
   备份目录以日期命名,下面放各个数据类型的压缩文件;
3. 在当前工作目录建立项目目录,脚本与备份都放进去,项目名由我决定;
4. 建立一个 md 文件保存讨论内容。

### 环境探索结果

- 数据目录:`C:\Users\Elden\.local\share\opencode`
  - `opencode.db` 约 714MB,WAL 约 17MB(session 记录全部存在 db 内)
  - `log/` 12 个日志文件,约 13MB
  - `snapshot/` 50 个文件,约 12.5MB
  - `auth.json`(凭证文件)、`storage/`、`tool-output/`、`repos/`(基本为空)
- 配置目录:`C:\Users\Elden\.config\opencode`
  - `opencode.jsonc`、`AGENTS.md`、`node_modules/`(插件依赖)
- `%APPDATA%\opencode`、`%LOCALAPPDATA%\opencode` 均不存在(作兜底探测)
- 已安装 7-Zip(`C:\Program Files\7-Zip\7z.exe`)、Python 3.14

### 关键决策(用户确认)

| 问题 | 决策 |
| ---- | ---- |
| `auth.json` 是否备份 | **跳过不备份**(含凭证,敏感) |
| 备份保留策略 | **保留所有**日期目录,只增不删 |
| 压缩工具 | **7z 优先,zip 兜底** |
| db 一致性处理 | **sqlite 在线备份 API**(运行时也安全) |
| 项目名 | `opencode_backup`(由我决定) |

### 需求变更

用户提出:在项目设计文档中增加**专门的备份恢复章节**,以防时间久后忘记如何恢复。
已落实为设计文档「六、备份恢复指南」,按数据类型分步说明。

### 实施与验证

- 首次运行发现两个问题并已修复:
  1. 7-Zip 输出使用系统本地代码页(GBK),按 UTF-8 解码导致 reader 线程崩溃
     → 改为按字节捕获并多编码尝试解码;
  2. 运行中的 opencode 锁定 `log/opencode.log`,7z 失败 → 自动回退 zipfile
     (共享读可读,log.zip 完整包含全部 12 个日志),并清理 7z 半成品与旧归档。
- 验证结果:日期目录 `backups/2026-09-15/` 生成 4 个包
  (`opencode.db.7z` 22MB、`opencode.jsonc.7z`、`log.zip` 0.9MB、`snapshot.7z` 12.7MB),
  `7z l` 确认 db/jsonc/snapshot 归档结构正确。

### 结论

计划获用户确认后进入实施,产出:

- `backup_opencode.py`(主脚本)
- `项目设计文档.md`(含恢复指南)
- `版本变更.md`
- `讨论记录.md`(本文件)
