# m3u-get-down 使用指南

> 版本：v0.7.1 ｜ 运行命令统一用 `py`（本机 Python 3.14；嗅探/批量/播放需用 GIL 构建，见 §1）
>
> 一个 m3u8 视频嗅探 / 下载 / 合并工具，四种入口：
>
> | 命令 | 用途 | 一句话场景 |
> |---|---|---|
> | `get` | 直接下载 m3u8 直链 | 已经拿到清单地址 |
> | `sniff` | 打开播放页自动嗅探 m3u8 并下载 | 只有播放页地址 |
> | `play` | 播放器模式：模拟在线播放缓存切片 | 页面有复杂加密/需要交互才出流 |
> | `batch` | 列表页批量下载整季 | 整季番剧一次挂机下完 |
>
> 自研引擎支持 AES-128 加密清单（自动解密）；真 DRM（Widevine/FairPlay）会明确提示并不支持。
> **B 站 / YouTube 等主流站点由 yt-dlp 引擎自动接管**（v0.7.0+，见 §5.5）：给个 URL 就能下，无需额外参数。

## 1. 环境要求与安装

```powershell
# 1) Python 3.13+（本机 3.14 已满足），安装依赖（含 yt-dlp）
pip install -r requirements.txt

# 2) Playwright 浏览器内核（嗅探/兜底渲染用）
py -m playwright install chromium

# 3) ffmpeg + ffprobe（合并与成品校验用），加入 PATH 即可
#    下载地址 https://ffmpeg.org ；也可在 config.json 的 ffmpeg_path 指定
```

> 🍎 **macOS 上把命令里的 `py` 换成 `python3`**（本篇以 Windows 的 `py` 为例）；
> 安装用 `python3 -m pip install ...` / `python3 -m playwright install chromium`，
> ffmpeg 与 node 用 `brew install ffmpeg node`。
> 完整对照见 §10「换机器 / 搬家清单」。

> ⚠️ **别用 free-threading 构建的 Python 跑嗅探/批量/播放**：
> 本机默认 `py` 是 **Python 3.14t（free-threading，无 GIL）**，Playwright 的同步 API
> （`sync_playwright`）在该构建上会直接**段错误**，而 `sniff` / `batch` / `play`
> 都依赖它。请改用同版本的**普通（GIL）构建**，例如 `py -3.14 -m m3u_down ...`。
> （`get` 直链下载不用 Playwright，不受影响；统一下载管理器已自动帮你选好 GIL 构建。）
> macOS 用 brew 装的 `python3` 就是普通构建，不用管这条。

首次运行任意命令会在项目根目录自动生成 `config.json` 默认配置。

## 2. 快速上手

```powershell
# 整季批量下载（推荐）：给番剧列表页地址，交互选集
py -m m3u_down batch "https://www.youknow.tv/d/202678/"

# 脚本化全季下载（跳过确认）
py -m m3u_down batch "https://eacg.net/voddetail/87441.html" --yes

# 只下第 3~5 集和第 12 集
py -m m3u_down batch "https://eacg.net/voddetail/87441.html" --yes --episodes 3-5,12

# 单集下载：只有播放页地址时
py -m m3u_down sniff "播放页地址"

# 单集下载：已从 F12 网络面板拿到 m3u8 直链时
py -m m3u_down get "https://example.com/hls/index.m3u8" --referer "https://example.com/"
```

成品都在 `Download\` 下（即 config.json 的 `output_dir`）：

```text
Download\
├─ 碧蓝之海第三季\            ← batch 输出（按番剧归档）
│   ├─ 第01集.mp4             ← 成品（扁平，无中间产物）
│   ├─ 简介.md                ← 剧名/封面/剧情/剧集状态 + 每集的线路·分辨率·时长
│   ├─ image\                 ← 封面图本地副本（v0.7.3，简介.md 相对引用）
│   │   └─ cover.jpg
│   └─ 批量进度.json           ← 批量断点记录（全部完成后可手动删）
├─ 番剧名 第01集.mp4           ← sniff 单集输出（自动清洗命名后扁平）
└─ ...
```

## 3. 命令详解

以下参数四个命令通用（下称"公共参数"），不再重复列出：

| 公共参数 | 说明 |
|---|---|
| `-o, --out DIR` | 输出目录（默认 `output_dir/<标题>`；指定后单集不再扁平） |
| `--concurrency N` | 并发下载线程数（默认读 config，6） |
| `--proxy URL` | 代理，如 `http://127.0.0.1:7890` / `socks5://127.0.0.1:1080`（默认读 config） |
| `--insecure / --no-insecure` | 跳过 HTTPS 证书校验（默认读 config） |
| `--keep` | 仅 get/sniff/play：保留中间产物（切片/清单/进度文件），即关闭后处理 |

> **输出根目录**由 config.json 的 `output_dir` 决定（默认 `"Download"`）。
> 相对路径一律按**项目根目录**解析，不是当前工作目录 —— 所以从任意 cwd 启动产物都落在同一处。
> `-o/--out` 指定时以它为准。

### 3.1 get — 直链下载

```powershell
py -m m3u_down get <m3u8地址> [公共参数] [--referer R] [--user-agent UA] [--cookie "k=v; k2=v2"]
                     [--quality best|worst] [--variant-index N]
```

| 参数 | 说明 |
|---|---|
| `--referer` / `--user-agent` / `--cookie` | 防盗链站点需要时手动指定请求头 |
| `--quality` | master 多码率清单选流策略，默认 `best` |
| `--variant-index` | 手动指定 master 变体序号（从 0 开始），优先于 `--quality` |

说明：成品固定叫 `output.mp4`（直链没有页面标题可取名），但同样会自动清理中间产物；想改名自己 `Rename-Item` 即可。

### 3.2 sniff — 嗅探播放页

```powershell
py -m m3u_down sniff <播放页地址> [公共参数] [--auto N] [--no-download] [--max-wait 秒]
                     [--quality best|worst] [--variant-index N]
```

工作方式：打开**有头浏览器** → 你在页面里正常点播放 → 工具监听网络捕获 m3u8 候选。

> **弹窗/广告页场景（v0.4.0+）**：部分站点点击播放后会把原页面跳转到广告页，真视频在
> 自动新开的窗口里播放。工具会自动：检测新窗口并提示 → 检测原页面跳转并提示
> （可能为广告页）→ 主页面被关闭（广告页自动关/你手动关）后**不中断**，继续监听
> 新窗口的播放请求；内嵌播放器站点（如 mvffm）的候选还会标注线路名与集名，如
> `[1] https://.../playlist.m3u8（线路: FLV 22 推薦31 · 第1集）`。

交互命令（在终端输入）：
- `数字`：选择第 N 个候选下载
- `r`：刷新候选列表
- `q`：退出

| 参数 | 说明 |
|---|---|
| `--auto N` | 非交互：出现第 N 个候选时自动选择（挂机/脚本用） |
| `--no-download` | 仅列出候选不下载（找直链用） |
| `--max-wait` | 最长等待秒数（默认 1800） |

成功后自动走与 batch 一致的后处理：按站点规则清洗页面标题命名（如"正在播放《X》第01集[日本动漫] - 某站"→ `X 第01集.mp4`）、扁平到输出根目录、清理中间产物。

### 3.3 play — 播放器兜底模式

```powershell
py -m m3u_down play <播放页地址或m3u8直链> [公共参数] [--speed 1~16] [--max-wait 秒]
```

sniff 拿不到流时的兜底：工具在页面里模拟真实播放，旁观浏览器按序接收切片并落盘，播完自动补拉缺失切片并合并。输入裸 m3u8 时会生成本地 hls.js 播放页代播（站点未开 CORS 可能失败，建议给播放页地址）。

| 参数 | 说明 |
|---|---|
| `--speed` | 播放倍速 1~16，如 `--speed 16` 可把 24 分钟的捕获时间压到约 2 分钟 |
| `--max-wait` | 最长等待秒数（默认 7200） |

> **滑动窗口（直播式）HLS（v0.4.1 修复）**：少数站点的媒体清单无 `#EXT-X-ENDLIST`、
> 只列出最近几秒的切片并实时前移（防直接下载）。play 模式会持续跟窗捕获：VOD 清单
> 捕获完自动合并；滑动窗口则等浏览器播放结束（`video.ended`）或超时/手动停止。
> 注意此类站点切片过窗即删、实时出现，捕获耗时≈视频时长。

### 3.4 batch — 列表页批量下载

```powershell
py -m m3u_down batch <列表页地址> [--interval 秒] [--episodes "1-12,15"] [--yes]
                     [--pick N] [公共参数]
```

工作流程：解析列表页 → 抓简介生成 `简介.md` → 展示剧集清单让你确认 → 逐集"嗅探→下载→合并→扁平归档"，每集之间休息 `--interval` 秒（默认 60，对站点友好）。

交互选集：`回车`=全部下载 / `1-12,15`=范围 / `q`=退出；`--yes` 跳过确认。

| 参数 | 说明 |
|---|---|
| `--episodes` | 集数范围表达式（1 基），配合 `--yes`；显式指定时优先于 `--yes` |
| `--interval` | 每集间隔秒数（默认读 config.download_interval=60） |
| `--pick` | 每集嗅探到多个 m3u8 候选时选第 N 个（默认 1）。**它不是选线路**（选线路用 `--line`）；仅对需要嗅探的非内嵌站点有意义 |
| `--line` | **内嵌播放器站点**（如 mvffm、ikanbot）的线路序号或名称；未指定时探活取
  第一条存活线路（v0.5.0+，死链多的聚合站更稳）。
  如 `--line 22` 或 `--line "FLV 22 推薦31"`（繁简/空格差异也能匹配）。
  运行时会把全部可选的线路（序号+名字）列出来 |
| `--no-adopt` | **不做外部文件纳管**（v0.8.0）。默认会扫描番剧目录顶层已有的 `*.mp4`，
  把能唯一对应到剧集的文件并入 `批量进度.json`，避免重复下载 —— 见下面「外部文件纳管」 |

> **清晰度由「线路」决定，但清单里的声明值不可信（2026-10-01 实测）**：同一集在不同线路上
> 是不同清晰度的源。实测「牙狼garo」第13集：线路1/6/8 = 640×480，**线路5/13 = 960×720**
> （该集全网最好版本）；第01集在线路5 上的真实内容是 **2880×2160**。而**所有**线路的 master
> 清单一律声明 `1080x608 / 800 kbps`，与真实内容无关（实际约 2.3 Mbps）—— 别拿声明值判断清晰度。
> 想换更清晰的源：换 `--line N` 重跑即可，**已完成的集会先自动判一次要不要重下**（v0.10.0，见下）；
> 若声明值恰好说不清（例如声明偏低），仍可用老办法：先删掉/改名那一集的文件再重跑
> —— 文件不在了就一定重下。

内置可靠性机制（无需配置）：
- **自动判定"这集要不要重下"（v0.10.0+）**：已完成的集在下载前会读一次清单，与
  `批量进度.json` 里记录的分辨率/时长/线路比对，命中任一条就**自动重下**：①清单声明更高清
  ②记录里的线路与本次 `--line` 不同 ③清单声明时长比现有明显更长（疑似缺内容）。
  重下时旧成品**改名成 `xxx.mp4.bak` 保留**（已有 `.bak` 则 `.bak2`…），不删除。
  三条保险：**只升不降**（声明明显低于现有成品就跳过）、**记忆声明值**（下次"声明比声明"，
  不会反复重下）、**探测失败即跳过**（网络挂了/站点结构变了绝不去重下）。
  判定只用清单声明值，**零额外流量**。
- **内嵌播放器站点（v0.4.0+）**：如 mvffm.net、ikanbot.com，全部线路与剧集的 m3u8 直链
  可从播放页（或其 API）解析，批量直接解析直链下载（**不需要开浏览器嗅探**）；运行时列出
  线路（序号+名字），默认探活取第一条存活线路（v0.5.0+），`--line` 指定其它线路；
  选中线路某集 CDN 挂了自动换**同集其他线路**重试
- **单集 failover**：嗅探/下载失败自动换备选线路重试（默认主线+2 备选，`sites/` 配置 `failover_max` 可调）
- **完整性自检**：切片续传校验大小防截断、合并后 ffprobe 校验成品（时长>0 且含视频流）
- **断点续跑**：`批量进度.json` 记录每集状态，**中断后重跑同一条命令**自动跳过已完成集、续传未完成集
- **外部文件纳管（v0.8.0+）**：如果你是**先用别的工具**（IDM、浏览器插件…）下过一部分，
  或者手工把视频拷进了番剧目录，重跑 batch 时下载器会**扫描番剧目录顶层**的 `*.mp4`，
  从文件名猜出"第几集"（支持 `牙狼garo-01-…mp4`、`第01集.mp4`、`S01E05`、`EP05`、
  `[01]`、`片子 05.mp4` 等常见命名），与剧集清单**唯一**对应上的就并入 `批量进度.json`，
  于是**不会再重复下载**。日志里会把"哪个文件算第几集"逐条列出来，便于核对；
  猜不出集号、有歧义（同一集号对应多个条目）、清单里没有的，**只报告不写入**。
  这条扫描**默认开启**，用 `--no-adopt` 关闭。
  想重新下载某一集：**删掉那个文件**再跑（进度里记录的文件不存在即视为要重下）。
- **封面本地化（v0.7.3+）**：列表页/详情页抓到的封面图会下载到番剧目录的 `image\cover.*`，
  `简介.md` 改用**相对路径**引用 —— 站点清理图床后（远程链接失效）简介页仍能正常显示封面。
  判定标准是 `Content-Type: image/*`（图床失效常见的"200 + HTML 错误页"不会被存成图片）；
  幂等：`image\cover.*` 已存在就复用、不再发请求；下载失败只打印一行警告，**不影响剧集下载**，
  此时简介页对应的位置留一行"未能保存到本地"的文字提示（不显示裂图）
- **视频信息回看（v0.9.0+）**：`简介.md` 的剧集清单表新增 **下载线路 / 分辨率 / 时长** 三列，
  事后翻回来看就知道每集是什么货色，不用猜：
  - **分辨率与时长**用 `ffprobe` 读**成品文件本身**（不是清单里声明的值），
    所以外部纳管进来的文件也能补录；只探测缺信息的，结果记进 `批量进度.json`，
    **第一次运行补齐、之后 0 成本**；读不出（缺 ffprobe/文件损坏）就显示 `—`，不影响下载。
  - **下载线路**只对**本下载器下载的**那集有意义（外部文件的来源无从得知，不猜，显示 `—`）。
    注意它和「链接」列的区别：链接列是**本次解析**出的线路（可能因探活/换线而不同），
    下载线路列是**这个文件实际来自哪条线**。
- 单集失败不阻塞后续集，结束打印汇总；`简介.md` 状态表随进度实时回写

## 4. 全局配置 config.json

项目根目录，首次运行自动生成；优先级：**CLI 参数 > config.json > 内置默认**。

| 字段 | 默认 | 说明 |
|---|---|---|
| `concurrency` | 6 | 下载线程数（调大提速但更易触发站点限速/封禁，不建议超过 12） |
| `proxy` | `""` | 代理地址，留空不启用；requests 与嗅探浏览器同时生效。
  出口降级（v0.5.1+）：每个站点还可在 `sites/*.json` 用 `proxy_policy` 指定出口优先顺序
  （`proxy_first` 默认推荐代理 / `direct_first` 不推荐代理）——先试优选出口，连接层失败自动切另一出口；
  浏览器无法逐请求降级，改为启动前探测取舍。代理恢复后重跑命令即回到优选出口 |
| `retry_times` | 3 | 单切片重试次数 |
| `retry_backoff` | 2 | 重试退避基数（秒），第 n 次重试等 n×backoff |
| `timeout` | 60 | 读取超时（秒），连接超时固定 15 |
| `output_dir` | `"Download"` | 输出根目录；**相对路径按项目根目录解析**（不是 cwd），绝对路径原样使用 |
| `download_interval` | 60 | batch 每集下载间隔（秒） |
| `ffmpeg_path` | `""` | ffmpeg 路径，留空从 PATH 查找（ffprobe 取同目录） |
| `insecure` | false | 跳过 HTTPS 证书校验 |

## 5. 站点配置 sites/

每个站点一个 JSON 文件（如 `sites/eacg.json`），按**域名后缀**自动匹配；没有配置的站点走内置通用解析引擎，一样能用，只是没有精修规则。所有字段均可省略。

| 字段 | 说明 |
|---|---|
| `domains` | 域名匹配列表，如 `["eacg.net"]` |
| `play_pattern` | 播放页 URL 正则，命中的链接才视为剧集页（省略则用通用模板分组） |
| `group` | 正则分组语义：`{"id":1,"line":2,"ep":3}` 指明作品ID/线路号/集位各是第几组 |
| `line_preference` | 同一集位多条线路时的选线策略：`line_asc`=线路号小者优先（默认源）；`complete_first`=集数齐全且"集名序号=集位"的线路优先（专治某条线路集表残缺错位） |
| `label_strip` | 集名尾部噪声正则，如 `"完结$"` 把"第12集完结"清洗为"第12集" |
| `title_subs` | sniff 单集命名的标题替换规则，`[[正则, 替换], ...]` 逐条执行 |
| `desc_prefix` / `desc_suffix` | 简介前后噪声正则（剥广告前缀、"剧情 \| 站名"后缀） |
| `failover_max` | 单集失败时最多尝试的线路数（默认 3 = 主线+2 备选） |
| `player_embedded` | 内嵌播放器直链解析器类型（v0.4.0+）。可用值：`dooplay_vue`（WordPress
  Dooplay 主题 Vue 播放器：全部线路/剧集的 m3u8 直链写在播放页 JS 里）、
  `ikanbot_api`（v0.5.0+：页面只藏 token 素材，解析器算 token 调站点 API 一次拿全部直链）。两种
  类型 batch 均直接解析直链下载、跳过嗅探，并支持 `--line` 选线。空=不用（旧行为） |
| `proxy_policy` | 出口偏好（v0.6.0+）：`proxy_first`=推荐代理（先试代理，连不上再直连，默认）；`direct_first`=不推荐代理（先试直连，连不上再试代理）。适用于下载/页面抓取/探活/内嵌 API，以及嗅探/播放浏览器的启动取舍。CLI 显式传 `--proxy` 时以用户指定为准 |
| `unsupported` | 不推荐用本下载器的站点标记（v0.4.1+）。`true` 时任何命令命中该域都
  打印 `unsupported_reason` 并退出（退出码 3），不执行下载；用于存档"研究过但无法/不值得支持"的站点 |
| `unsupported_reason` | 配合 `unsupported` 使用，提示给使用者的简要原因 |
| `detail` | 配置驱动的视频详情提取（v0.7.2+），见下面「视频详情配置 detail」 |

### 视频详情配置 detail（v0.7.2+）

通用提取只认 `<h1>`/`<title>`、`meta description`、`og:image` 三样；站点详情块结构
各不相同，把解析正则写进站点配置的 `detail` 键即可让简介.md带上完整信息。示例
（完整可用配置见 `sites/ikanbot.json`）：

```jsonc
"detail": {
  "title":   {"pattern": "<h2[^>]*class=\"[^\"]*\\btitle\\b[^\"]*\"[^>]*>([^<]+)</h2>"},
  "cover":   {"pattern": "class=\"cover[^\"]*\"[^>]*data-src=\"([^\"]+)\""},
  "年份":     {"pattern": "<h3[^>]*class=\"meta\"[^>]*>\\s*(\\d{4})\\s*</h3>"},
  "主演":     {"pattern": "<h3[^>]*>\\s*([^<]*/[^<]*?)\\s*</h3>", "replace": [[",,", "/"]]}
}
```

规则字段（每条）：

| 字段 | 默认 | 说明 |
|---|---|---|
| `pattern` | 必填 | Python 正则，`re.search(..., re.S)`，捕获组即值 |
| `group` | `1` | 取第几个捕获组 |
| `strip_tags` | `true` | 去内层标签 + 迭代 HTML 实体解码 |
| `replace` | `[]` | 值上的字面替换序列 `[[from, to], …]`（如 `,,` → `/`） |
| `multi` | `false` | `true` 时收集全部匹配用 "，" 连接（适配每项一个元素的站点） |

- **保留键**：`title` / `cover` / `description` 覆盖通用提取的对应结果，
  规则不中时逐字段回退原有逻辑（标题/封面/简介不受影响）；
- **附加键**：其余键名视为显示标签，原样写入简介.md 的「视频信息」小节
  （如 `- 年份：2010`）；
- 坏正则在加载期拦截并告警，不影响其它站点；匹配不到静默跳过，不报错。

### yt-dlp 引擎（B 站 / YouTube 等主流站点，v0.7.0+）

B 站等主流站点由 **yt-dlp** 接管（wbi 签名、DASH 音视频分离、清晰度鉴权都由它处理）。
**不需任何新参数**——跟平时一样给个 URL 即可：

```powershell
py -m m3u_down sniff "https://www.bilibili.com/video/BV1xx411c7mD"    # 下单个视频
py -m m3u_down batch "https://www.bilibili.com/bangumi/play/ssXXXXX"  # 整季番剧（交互选集）
py -m m3u_down sniff "https://www.bilibili.com/video/BV1xx411c7mD" --no-download  # 只看标题/条目
```

路由顺序（自动判定，无需你指定）：

```
URL → ① yt-dlp 支持该站？ → 是 → yt-dlp 引擎（B站/YouTube/…）
      → ② sites/*.json 有专用解析器？ → 是 → 自研内嵌直链（ikanbot 那套）
      → ③ 都没有 → 通用自研引擎（嗅探 / 列表页解析）
```

控制文件是项目根的 **`ytdlp_sites.json`**（首次运行自动生成）：

| 字段 | 说明 |
|---|---|
| `enabled` | 总开关（false=完全不用 yt-dlp，回到自研） |
| `mode` | `auto`=yt-dlp 有专用解析器的站都自动走它（**默认**）；`list`=只有 `sites` 列出的域名才走 |
| `cookies_from_browser` | 从哪个浏览器读 cookie（默认 `edge`）；`""`=不用。**新版 Edge/Chrome 的 cookie 是 App-Bound 加密（v20），yt-dlp 读不到**（见下），实际推荐 Firefox 或 `cookies_file` |
| `cookies_file` | cookies.txt 路径（非空则优先于浏览器读取），**最可靠的方式** |
| `format` | 清晰度选择，默认 `bestvideo[height<=720]+bestaudio/best[height<=720]/bestvideo+bestaudio/best` = **优先 ≤720P，没有 720P 则取能下到的最清晰** |
| `merge_output_format` | 合并容器（默认 `mp4`） |
| `sites` | **仅放需要覆盖默认行为的站点**（`engine`: `m3u`=强制自研 / `ytdlp`=强制 yt-dlp；还可覆盖 `format`/`cookies_*`/`proxy_policy`/`extra_opts`） |
| `extra_opts` | 透传给 yt-dlp 的原始选项（逃生舱，如 `extractor_args`）。默认已开 JS 运行时：`{"js_runtimes": {"deno": {}, "node": {}}}`（YouTube 必需，见下） |

已预置两条：**B站**（`proxy_policy: direct_first` — 国内 CDN 直连优先）与
**四个自研站点**（`engine: m3u` 守卫，保证 ikanbot/mvffm/eacg/youknow 行为不变）。
auto 模式下其余站点无需列域名；想强制某站走自研，加一条 `engine: "m3u"` 即可。

#### cookie 与清晰度（B 站重点）

- **原理**：yt-dlp 每次运行时**实时读取浏览器的 cookie 数据库**，所以只要你在该浏览器里
  登录过一次、并且保持登录态，就一直能用（cookie 到期后重新登录即可）。
- **读不到 cookie 时工具会警告一次并自动改用无 cookie 继续**（不中断下载），
  只是清晰度/会员内容受限（未登录 B 站通常只能拿到 360/480P）。
  `cookies_file` 路径写错/文件过期也一样降级，不会直接报错退出。
- ⚠️ **本机实测：新版 Edge / Chrome 的 cookie 基本读不到了。** 它们已改用
  **App-Bound 加密**（cookie 值前缀 `v20`；本机 3216 条 Edge cookie 全是 `v20`），
  解密密钥由浏览器的“提升服务”保护，第三方程序拿不到；yt-dlp 目前只支持旧的 `v10`，
  碰到 `v20` 会报 `Failed to decrypt with DPAPI`（yt-dlp issue **#10927**，仍 open）。
  这不是“浏览器没关闭”的问题（实测关掉 Edge 一样失败），修不了 → **用下面两种办法绕开**。
- 会员/番剧/4K/8K/HDR 需要**有权限的账号** cookie；港澳台限定番剧还需对应地区网络。
- 某些站的搜索类地址（如 B 站搜索）无 cookie 会 412，配好 cookie 即可。

#### cookies.txt 导出与使用（Edge / Chrome）

**方式一：装个 Firefox（最省事，推荐）**

Firefox 的 cookie 是**明文 sqlite**，没有 DPAPI / App-Bound 这套东西——**Windows 和 macOS 一样可行**。
装一个 Firefox，登录一次目标站点，然后把配置改成：

```jsonc
"cookies_from_browser": "firefox",   // 而不是 edge / chrome
"cookies_file": ""
```

yt-dlp 官方也说这个方法“对 Firefox 效果最好，对 Edge 经常出问题”。补充几点：

- cookie 库位置：Windows `%APPDATA%\Mozilla\Firefox\Profiles\`，
  macOS `~/Library/Application Support/Firefox/Profiles/`（每个 profile 一个目录，
  里面是 `cookies.sqlite`）。
- **Firefox 开着也能读**：yt-dlp 会先把库**拷到临时目录**再读，不抢锁。
- 有多个 profile 时，yt-dlp 默认取**最近更新**的那个；要指定就写
  `"cookies_from_browser": "firefox:<profile目录名>"`（如 `firefox:abcd1234.default-release`）。
- 因为是明文，理论上把 Windows 的 `cookies.sqlite` 拷到 Mac 的 profile 里也能用；
  但**不推荐**（跨设备/IP 可能反而触发风控），直接在新机器登录一次更干净。

**方式二：用扩展导出 cookies.txt（Edge / Chrome 通用）**

1. 装扩展 **`Get cookies.txt LOCALLY`**（Edge 加载项商店 / Chrome 应用商店都有）。
   - ⚠️ 只能装名字里**带 `LOCALLY`** 的那个：另一个叫 `Get cookies.txt`（没有 LOCALLY）的
     扩展已被认定为恶意软件、从 Chrome 商店下架，官方明确建议卸载。
2. 用浏览器打开并按需要登录目标站点。（YouTube 见下面的“无痕窗口”技巧。）
3. 点扩展图标 → **Export / 导出** → 得到 `cookies.txt`。
   - 必须是 **Netscape 格式**（第一行是 `# Netscape HTTP Cookie File`），
     别用 JSON 格式导出；Windows 下行尾用 **CRLF**（报 `HTTP Error 400: Bad Request`
     基本就是这个原因）。
4. 把它放到项目目录里（例：`m3u-get-down/cookies/youtube.txt`），然后配置：

```jsonc
// ytdlp_sites.json
"cookies_file": "C:/path/to/cookies/youtube.txt",   // 也可用相对项目根的路径
"cookies_from_browser": ""
```

5. 验证：`py -m m3u_down sniff "<该站 URL>" --no-download` 看能否列出标题/格式。

> 🔒 这个文件等同于账号凭证（含会话 cookie）：别外传、别提交到 git、别放进公开目录；
> 用完后可以直接删掉。

**YouTube 专属注意事项**

- YouTube 会**频繁轮换**打开着的标签页里的 cookie，导致导出的文件很快失效。官方推荐做法：
  开一个**无痕窗口**登录 YouTube → 在同一个标签页打开 `https://www.youtube.com/robots.txt`
  → 导出 `youtube.com` 的 cookie → **立即关闭该无痕窗口**（以后别再用它），这样这份 cookie 不会被轮换。
- 导出的 cookie 只针对该站点，别用“先从浏览器导出全站 cookie 再拿来用”的骚操作（官方明确不推荐）。
- ⚠️ 官方警告：**用账号给 yt-dlp 下视频有被封号的风险**（临时或永久），请控制频率，
  或使用小号。

**YouTube 要过三道关（v0.7.1 已全部实测）**

| 关卡 | 缺失时的报错 | 怎么过 |
|---|---|---|
| ① cookie | `Sign in to confirm you're not a bot` | **必须自己弄**（下面两种都实测可行） |
| ② JS 运行时 | `No supported JavaScript runtime could be found` | **已默认预置** deno/node，无需你装 deno |
| ③ EJS 挑战脚本 | `n challenge solving failed` → `The page needs to be reloaded.` | **已默认预置**（见下） |

- **① cookie**：实测 **Firefox 可行** —— `cookies_from_browser: "firefox"`（本机导出 60 条 cookie，
  能认出账号）；或用 `cookies_file` 指向导出的 cookies.txt（见上）。
  无 cookie 时实测仍然卡在 bot 校验（也与我们走代理、IP 被认作数据中心有关）。
- **② JS 运行时**：默认只启用 `deno`，v0.7.1 起预置为：
  ```jsonc
  "extra_opts": {"js_runtimes": {"deno": {}, "node": {}},
                 "remote_components": ["ejs:github"]}
  ```
  deno 优先、没装则用 node（本机用 node 24）；两个都没有只告警不报错。
- **③ EJS 挑战脚本**：yt-dlp 新版把 YouTube 的 JS 挑战交给
  [yt-dlp-ejs](https://github.com/yt-dlp/yt-dlp/wiki/EJS) 脚本解，**默认不允许联网拉取**，
  于是 `n` 签名解不出来、格式拿不到（旧版报错是 `The page needs to be reloaded`）。
  `remote_components: ["ejs:github"]` 就是开这个门（首次自动下载并缓存到
  `~/.cache/yt-dlp/challenge-solver`，以后不再拉；拉不到只告警，其它站点无关）。

**实测结果（本机，Firefox cookie + node + EJS）**：19 秒的样例视频完整下载并合并成功；
4K 源的视频能列出 2160/1440/1080/720/480… 全部清晰度，默认按设计选到 **720P**。
注意默认选到的是 **AV1 + Opus**（装进 mp4 容器合法，但部分老播放器/电视不认）；
想换成兼容性更好的 h264 + aac，改 `format` 为例如
`bestvideo[height<=720][vcodec^=avc1]+bestaudio[acodec^=mp4a]/best`。
**B 站不需要这三关里的任何一项**（②③ 预置也无影响），配 cookie 只为高清/会员内容。

#### 与自研引擎的差异

- yt-dlp 路径下 `--line` / `--pick` 不适用（会打印提示并忽略）；`--proxy` / `--insecure` /
  `--concurrency` / `-o` 照常生效。
- **单集命令**（get/sniff/play）只下 URL 指向的那一个视频（不偷偷整季下载）；
  **整季/合集用 `batch`**，同样支持交互选集与中断续跑（`简介.md` + `批量进度.json`）。
- 未安装 yt-dlp 时，命中需 yt-dlp 的站点会提示 `py -m pip install -U yt-dlp` 并退出，
  不会静默回退自研（回退也必然失败）。
- 首次分析某站点会加载 yt-dlp 解析器列表（~数秒，仅一次），结果按站点缓存到
  `.ytdlp_hosts_cache.json`；升级 yt-dlp 后自动重新分析。

## 6. 断点续传 / 续跑约定

| 场景 | 操作 |
|---|---|
| get/sniff/play 中途 Ctrl+C 或断网 | **重跑同一条命令**：已下载切片按大小校验后跳过，只补缺的 |
| batch 中途中断 | **重跑同一条命令**：已完成集自动跳过（v0.10.0 起会先判一次"要不要重下"），失败/未完成集自动续跑 |
| 某集总是失败 | 其他集照常完成；失败集保留在汇总里，修好网络后重跑即可单独补 |
| 想让某集重下 | v0.10.0 起通常**什么都不用做**：换 `--line N` 或等站点上更高清的源，重跑时自动重下（旧成品留下 `.bak`）。声明值说不清时，删掉/改名那一集的文件即可强制重下 |
| 想看下载了哪些切片 | 加 `--keep`（get/sniff/play）或看 `番剧名\_work\`（batch 进行中） |
| 全部完成后 | 中间产物已自动清理；`批量进度.json` 和 `progress.json` 可手动删 |

## 7. 常见问题

**Q：提示"检测到真 DRM 加密"？**
清单用了 Widevine/FairPlay，密钥在浏览器 CDM 内部申领、明文不经过网络，无法合规获取，工具直接退出（退出码 2）。普通 AES-128 加密不受影响，自动解密。

**Q：sniff 打开页面后一直没有候选？**
先在浏览器页面里手动点一下播放；仍没有试试 `play` 模式。也可以 `--no-download` 先看能不能捕获到直链。

**Q：下载速度忽快忽慢？**
CDN 服务端限速，正常现象。`concurrency` 可适当调大，但别太激进。

**Q：某集提示 Read timed out / 切片下载失败？**
单集瞬时网络抖动。v0.3.0 起会自动换线路重试；若该站只有一条线路，重跑同一命令续传即可。

**Q：批量下到一半 Ctrl+C 了，会白下吗？**
不会。切片级和集级进度都已落盘，重跑同一条命令接着来。

**Q：怎么换下载目录 / 用代理？**
改 `config.json`（全局生效），或单次命令加 `-o` / `--proxy`。

**Q：新出的番剧想持续追更？**
目前做法：隔几天重跑同一条 batch 命令，已完成的集会秒跳过，只下新增集。（自动追更 watch 模式在路线图 v0.4）

## 9. 已验证站点与已知边界

- **B 站 bilibili.com（v0.7.0 新增，yt-dlp 引擎）**：普通视频 / 番剧 / 直播 / 空间 /
  合集等由 yt-dlp 接管，自动路由、无需新参数；DASH 音视频分离下载后用 ffmpeg 合并。
  实测单个视频（512×384、34min）合并成功；YouTube 搜索多条目枚举（标题+条目）成功。
  未登录清晰度受限（约 360/480P），高清需 cookie（`cookies_file` 或 Firefox，见 §5.5）——
  读不到会警告并自动降级。整季用 `batch`，复用 `简介.md`/`批量进度.json` 续跑。
- **YouTube 等 1700+ 站点（v0.7.0）**：同一 yt-dlp 引擎，auto 模式自动接管；
  ⚠️ YouTube 有两道额外门槛（v0.7.1 实测）：① **JS 运行时**（已默认预置 deno/node，无需装 deno）；
  ② **cookie 必须自己导出成 `cookies.txt`**（Edge/Chrome 的 cookie 因 App-Bound 加密
  第三方读不到，见 §5.5），否则报 `Sign in to confirm you're not a bot`（走代理的
  数据中心 IP 也会加重这个判定）。请遵守各自服务条款，仅用于个人备份。
- **小红书 xiaohongshu.com（v0.7.1 实测）**：yt-dlp 从网页版的 SSR 数据
  (`window.__INITIAL_STATE__`) 里直接取 CDN 直链（明文 MP4，无加密无 DRM），
  理论上一条 `sniff` 就能下。**但网址必须带 `xsec_token`**：
  - ❌ 从 App 分享得到的 `xhslink.com` 短链**不支持**（yt-dlp 不认这种地址）。
  - ✅ 用浏览器打开该笔记（会重定向到 `www.xiaohongshu.com/explore/<id>` 或
    `/discovery/item/<id>`），从地址栏把**整条 URL（含 `?xsec_token=…`）**复制过来。
  - 实测登录且带 token 的链接：36 秒视频 720×1280 下载成功（无需 cookie）；
    去掉 token 或 token 过期 → 被重定向到 `/404/sec_…` 风控页，报 `No video formats found!`。
  - shell 里 `&` 要引号：`py -m m3u_down sniff "https://…?xsec_token=…&xsec_source=pc_feed"`。
- **youknow.tv**：`/p/{id}-{线路}-{集}/` 结构，线路1 为默认源（line_asc）；出口=代理优先
- **eacg.net**：`/vodplay/{id}-{线路}-{集}.html`，其"EDD动漫"线路集表残缺错位，
  由 `complete_first` 自动避开；简介源站自带截断属数据问题，工具只剥前缀广告；出口=代理优先
- **mvffm.net（v0.4.0 新增）**：WordPress Dooplay 主题，**内嵌播放器直链**——全部线路
  （22 条，名字如"FLV 22 推薦31"）与剧集的 m3u8 直链写在播放页 JS，batch 直接解析下载、
  无需嗅探；默认探活取第一条存活线路，`--line` 可指定序号或名字。实测第22线路第01集 203MB 下载+合并通过；出口=代理优先
- **ikanbot.com（v0.5.0 新增）**：爱看机器人，播放页隐藏域算 token 调 `/api/getResN`
  一次拿全部线路×剧集直链（token 算法已在解析器内用 Python 复现，无需浏览器）。
  VOD 无加密、切片无 Referer 校验；聚合站死链常见，默认探活取第一条存活线路，
  死链由 failover 兑底。实测《魔法师 第一季》9 条线路中 4 条失效，第01集 415MB
  下载+合并+ffprobe 校验通过；**出口=直连优先**（国内站直连稳，实测代理出口反而可能被部分 CDN 歧视）
- **javdock.com（v0.4.1，标记为不推荐）**：单视频页站点。三道防下载防护：Cloudflare
  Turnstile（有头浏览器可过）、data-ts-live AES 密文需浏览器解密、滑动窗口 HLS 只暴露
  最近约 6 秒切片且过窗即删，无法整片直下；免费流仅 240p。已配置 `unsupported`，
  任何命令命中该域会提示并退出。
- 局限：同列表页混多季且集名完全相同时只保留先出现的季，多季番剧请用各季的列表页；
  需要 JS 解密才能取出集表的站点暂不支持（可配 Python 适配器，后续版本再议）

## 10. 换机器 / 搬家清单

### 10.1 结论：项目目录是自包含的，可以整个拷走

代码、`config.json`、`ytdlp_sites.json`、`sites/*.json`、`.ytdlp_hosts_cache.json`、
`Download/` 全部在项目目录内，且**不含任何写死的绝对路径**
（`PROJECT_ROOT` 由 `__file__` 推导，见 `m3u_down/config.py`）。

搬走前检查这几项（机器相关的配置都在这里）：

| 字段 | 默认值 | 搬走后要做什么 |
|---|---|---|
| `config.json` → `proxy` | `http://127.0.0.1:10808` | 新机器的代理地址（端口/协议可能不同；留空=跟随系统代理） |
| `config.json` → `output_dir` | `Download`（相对） | 相对路径不用改；写成绝对路径了就要改 |
| `config.json` → `ffmpeg_path` | `""`（走 PATH） | 留空就行；写了绝对路径就要改 |
| `ytdlp_sites.json` → `cookies_file` | `""` | 若用了 cookies.txt，新机器要重新导出并改路径 |

### 10.2 新机器要装的（`requirements.txt` 覆盖不到的）

| 装什么 | 为什么 | Windows | macOS |
|---|---|---|---|
| Python **3.13+ 的普通（GIL）构建** | 全局 | python.org 装 3.14，命令用 `py -3.14` | 推荐 **python.org 安装包**（命令 `python3`）；用 brew 的 `python@3.14` 需注意 PEP 668，见下 |
| pip 依赖（**含 yt-dlp**） | requests / playwright / pycryptodome / pysocks / yt-dlp | `pip install -r requirements.txt` | `python3 -m pip install -r requirements.txt` |
| **Playwright 浏览器内核** | 嗅探 / 播放 / 批量 | `py -m playwright install chromium` | `python3 -m playwright install chromium` |
| **ffmpeg + ffprobe** | 切片合并、DASH 合并、成品校验 | 下载后放 PATH，或填 `ffmpeg_path` | `brew install ffmpeg` |
| **node**（仅 YouTube 需要） | YouTube 的 JS 运行时 | 装 node LTS 即可 | `brew install node` |
| Firefox（需登录的站点） | 读 cookie（Edge/Chrome 读不到） | 装 Firefox + 登录目标站 | 同左 |

实测/查证确认的几点：

- **即便你只用 yt-dlp 下 B站/YouTube，`playwright` 与 `pycryptodome` 也必须装**：
  `m3u_down/cli.py` 在模块顶层就 import 了 sniffer / player_capture / downloader。
- **Playwright 是微软的，但完全跨平台**（包元数据 `Operating System :: OS Independent`，
  官方支持 Windows / macOS / Linux，含 Apple Silicon）。macOS 用**同一条**
  `playwright install chromium` 命令，只是内核下载到
  `~/Library/Caches/ms-playwright`（Windows 是 `%LOCALAPPDATA%\ms-playwright`）。
- ⚠️ **macOS 上别用 brew 的 Python 直接 `pip install`**：brew 安装的 Python 会被标记为
  `externally-managed`，直接装包会报 `externally-managed-environment`（PEP 668）。
  两个选择：① 用 **python.org 的官方安装包**（统一下载管理器指南就是这么装的，
  没这个限制，最省事）；② 用 brew 的话先建虚拟环境：
  `python3 -m venv ~/.venv && source ~/.venv/bin/activate`，之后再 `pip install`。

### 10.3 新机器要重新“取得”的（不是安装）

| 东西 | 自动？ | 位置 / 说明 |
|---|---|---|
| Firefox 登录态 | ❌ 手动 | 浏览器登录一次即可（配置里已经是 `cookies_from_browser: "firefox"`）。**Windows / macOS 行为一致**（Firefox 的 cookie 未加密，Mac 上 profile 在 `~/Library/Application Support/Firefox/Profiles/`，开着 Firefox 也能读） |
| cookies.txt（若用这条路） | ❌ 手动 | 会话绑定，必须重新导出（步骤见 §5.5） |
| **EJS 挑战脚本**（YouTube） | ✅ **自动** | `$XDG_CACHE_HOME` 或 `~/.cache/yt-dlp/challenge-solver/`：Windows `C:\Users\<你>\.cache\...`，macOS `~/.cache/...`。首次跑自动下（需能连 GitHub；拉不到只告警，YouTube 会失败） |
| 站点解析器缓存 | ✅ 随目录 | `.ytdlp_hosts_cache.json`，按 yt-dlp 版本自动失效重建 |
| 代理客户端 | ❌ 手动 | 见 10.1 的 `proxy` |
| yt-dlp 自身 | ❌ 偶尔手动 | `pip install -U yt-dlp`（站点/算法会变，建议隔段时间更新） |

### 10.4 统一下载管理器（download-manager）

- `config.json` 里 `projects.*.dir` 是**相对**路径（`../m3u-get-down`）——
  保持三个下载器与管理器**同级**就能整体搬走，不用改任何路径。只搬 `m3u-get-down`
  单独用也没问题（它本来就是独立命令行工具）。
- Windows 双击 `start_server.bat`，macOS 双击 `start_server.command`（已提供）。
- Python 解释器自动探测（`python.python_exe` 留空即可），会自动避开 free-threading 构建。
- 搬走后**历史任务**记录里的 `cwd` / `log_file` / `target_dir` 仍是旧机器的绝对路径，
  旧任务的“看日志 / 打开产物”会失效；新任务不受影响（想干净就删掉 `data/tasks.json` 里的旧条目）。

### 10.5 macOS 差异提醒

- **命令前缀**：`py` → `python3`（如 `python3 -m m3u_down sniff ...`）。
- **特殊字符**：zsh 里 URL 的 `&`、`?` 同样要加引号。
- **文件名**：Windows 非法字符已在 `sanitize_name` 里清理，跨平台不会出问题。
- **代理**：`config.json` 的 `proxy` 留空时会跟随系统代理（macOS 用 `scutil --proxy` 读取）。
