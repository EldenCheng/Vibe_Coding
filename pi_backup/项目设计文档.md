# pi 数据备份工具 —— 项目设计文档

> 版本：v1.0.0
> 更新日期：2026-09-19

## 1. 项目背景与目标

用户正在使用 pi coding agent，已在 pi 上建立了用户设置（`settings.json`）并运行了若干 session（会话历史）。为了在数据损坏、误删或重装时能够恢复，需要一个 Python 脚本定期备份 pi 的数据。

**目标：**
- 运行一个脚本，自动备份 pi 的用户设置与会话数据；
- 备份存放在本项目 `backup/<当前日期>/` 目录下，以日期为单位管理；
- 备份文件压缩存放，尽量减少磁盘占用；
- 提供一份帮助文件，说明脚本备份与手工恢复的方法。

## 2. 需求确认记录

本次需求中的关键决定，均经用户确认：

| # | 问题 | 用户决定 |
|---|------|----------|
| 1 | `bin/fd.exe`（4MB 工具二进制）是否纳入备份？ | **排除**（pi 可自动重新获取，排除后体积减小约 70%） |
| 2 | 压缩格式选 zip 还是 tar.gz？ | **zip**（Windows 双击即可打开查看） |
| 3 | 是否自动清理旧备份？ | **不清理**。备份以日期文件夹为单位，备份太多时用户手工删除旧文件夹 |
| 4 | 项目文件夹名？ | `pi_backup` |

## 3. 数据源分析

pi 的数据存储在 `~/.pi/agent/`（即 `C:\Users\Elden\.pi\agent\`），可用环境变量 `PI_CODING_AGENT_DIR` 覆盖。

| 内容 | 大小 | 是否备份 | 理由 |
|------|------|----------|------|
| `settings.json` | ~1K | ✅ | 用户设置（主题、默认模型等） |
| `auth.json` / `auth.json.bak` | ~1K | ✅ | API 密钥配置（含敏感信息） |
| `models.json` / `models-store.json` | ~4K | ✅ | 模型配置 |
| `sessions/`（jsonl 会话文件） | ~1.6M | ✅ | 会话历史，是恢复的关键 |
| `bin/fd.exe` | ~4.0M | ❌ | pi 自动下载的工具二进制，可重新获取 |

## 4. 软件结构设计

本项目为单一脚本 + 文档结构，与仓库内其他项目风格一致（独立脚本、无共享构建工具）：

```
pi_backup/
├── backup_pi.py          # 备份脚本（唯一入口）
├── 项目设计文档.md         # 本文档
├── 版本变更.md             # 版本变更记录
├── 备份与恢复帮助.md       # 备份/恢复帮助文件
├── 讨论记录.md            # 本次需求讨论记录
└── backup/               # 运行脚本后自动生成
    └── 2026-09-19/       # 当天日期目录
        ├── pi_agent_备份_2026-09-19.zip   # 压缩备份包
        └── 备份清单.txt                    # 备份内容清单
```

### 脚本模块划分（backup_pi.py）

采用函数级模块化，各函数职责单一，便于维护：

| 函数 | 职责 |
|------|------|
| `get_source_dir()` | 定位 pi 数据源目录（环境变量优先，其次默认路径） |
| `is_excluded()` | 判断相对路径是否命中排除规则（`bin/`） |
| `collect_files()` | 遍历源目录，收集待备份文件，返回 `(绝对路径, 相对路径)` 列表 |
| `make_archive()` | 在日期目录下创建 zip 压缩包（`ZIP_DEFLATED`），同一天重复运行自动加时间后缀避免覆盖 |
| `write_manifest()` | 生成 `备份清单.txt`（备份时间、源目录、文件清单、压缩率等） |
| `main()` | 主流程编排 |

### 主流程

```
定位源目录 → 收集文件 → 建立 backup/<日期>/ 目录 → 压缩为 zip → 写清单 → 输出摘要
```

## 5. 关键设计决策

1. **压缩方案**：使用 `zipfile`（标准库）+ `ZIP_DEFLATED` 压缩。jsonl 文本压缩率很高，可显著减小体积。无需第三方依赖。
2. **归档路径**：zip 内按相对路径存放（如 `settings.json`、`sessions/.../xxx.jsonl`），解压后直接得到与源目录相同的结构，方便还原。
3. **同一天重复运行**：日期目录已存在时，第二个压缩包文件名追加时间戳（`pi_agent_备份_2026-09-19_15-30-05.zip`），不覆盖旧备份。
4. **排除规则**：`EXCLUDE_PATTERNS` 配置相对路径片段（当前为 `bin`），命中即跳过。为便于日后调整，排除逻辑独立成函数。
5. **可配置源目录**：默认 `~/.pi/agent`，若设置环境变量 `PI_CODING_AGENT_DIR` 则优先使用，适配自定义安装位置。
6. **清单文件**：每次备份生成 `备份清单.txt`（UTF-8），记录备份时间、源目录、文件清单与压缩率，便于日后核对备份完整性。
7. **单文件实现**：本项目功能简单、无共享依赖，与仓库其他项目一致采用单脚本，不拆分为多文件包。

## 6. 恢复方案概述

本工具只做备份，不做自动恢复（避免误操作覆盖正在使用的数据）。恢复采用**手工方式**：

1. 关闭所有正在运行的 pi；
2. 解压 `backup/<日期>/pi_agent_备份_<日期>.zip`；
3. 将解压出的内容复制回 `~/.pi/agent/`，覆盖同名文件；
4. 重新打开 pi，检查设置与会话是否恢复。

详细步骤见《备份与恢复帮助.md》。

## 7. 边界情况与注意事项

- **敏感信息**：`auth.json` 内为明文 API 密钥，备份包包含此信息，必须妥善保管备份目录，勿上传公开仓库或外传。
- **`bin/` 不备份**：恢复后 pi 会在需要时自动重新下载 `fd.exe`，无需担心。
- **磁盘空间**：备份以日期为目录累积，不做自动清理；用户手工删除过旧日期目录即可。
- **源目录不可用**：脚本会给出明确错误提示并退出（支持通过 `PI_CODING_AGENT_DIR` 修正路径）。
- **运行环境**：仅依赖 Python 标准库，无需 pip 安装任何包；本机使用 `py backup_pi.py` 运行。
