# 项目设计文档 — 员工通知网页自动登录助手

## 1. 项目概述

油猴（Tampermonkey）用户脚本，实现**工作日 9:00 自动打开公司内网员工通知网页（`网址`）并完成登录**。

### 1.1 运行环境限制

油猴脚本不是后台服务，只在某个匹配页面加载时才执行。`@match *://*/*` 意味着：**9:00 那一刻浏览器至少要有一个 http(s) 页面开着**，那个页面里的脚本才能轮询到 9:00 去触发。

若 9:00 时浏览器关着、或所有标签都是 `chrome://`/新标签页（不注入脚本）→ 不会触发，正好落入"错过不补"。

> **使用窍门**：上班时钉一个普通网页标签常驻（例如百度），即可保证脚本存活。

## 2. 需求

- 每天 9:00 自动打开 `网址`
- **仅工作日触发**（当前实现：跳过周六、周日；不含法定节假日/调休判定）
- 如果已有标签页在该网址上，**刷新该标签**让登录框出现
- 自动填入用户名密码并点击登录
- **当天只触发一次，错过不补**
- 触发时间可通过油猴菜单配置（方便测试）

## 3. 架构设计

### 3.1 运行环境

- Tampermonkey 4.0+（Chrome / Edge）
- 匹配规则：`*://*/*`（所有 http/https 页面）
- `@run-at document-idle`（页面加载完成后执行）
- `@noframes`（不在 iframe 中运行，避免重复注入）

### 3.2 @grant 列表

| GM API | 用途 |
|--------|------|
| `GM_openInTab` | 新开目标页标签 |
| `GM_setValue` | 存储触发日期、epoch、配置 |
| `GM_getValue` | 读取触发状态与配置 |
| `GM_deleteValue` | 重置触发状态 |
| `GM_registerMenuCommand` | 注册油猴菜单命令 |

### 3.3 GM 存储字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `lastTriggerDate` | string (`YYYY-MM-DD`) | 最近一次触发的日期；==今天 表示今天已触发 |
| `triggerEpoch` | number | 递增计数器；每次触发 +1，用于通知已存在的目标标签自刷新 |
| `claimedEpoch` | number | 目标标签认领的 epoch 值；触发页据此判断是否需要新开标签 |
| `triggerTime` | string (`HH:MM`) | 用户通过菜单设置的触发时间（覆盖 CONFIG 默认值） |

## 4. 核心逻辑

脚本按当前页面 URL 分两段运行，同一段脚本内自动分支。

### 4.1 触发调度器（所有匹配页面运行）

每 5 秒轮询一次 `checkTrigger()`：

```
setInterval(checkTrigger, 5000):

checkTrigger():
  1. 若 lastTriggerDate === today → 返回（今天已触发）
  2. 若 周六 或 周日 → 返回
  3. 若 Date.now() < todayTriggerTimestamp → 返回（还没到时间）
  4. 调用 doTrigger()

doTrigger():
  1. GM_setValue('lastTriggerDate', today)
  2. newEpoch = triggerEpoch + 1; GM_setValue('triggerEpoch', newEpoch)
  3. 若当前在目标页 → location.reload()
  4. 否则 → setTimeout(3秒):
       若 claimedEpoch === newEpoch → 已有目标标签认领，不新开
       否则 → GM_openInTab(targetUrl, {active:true})
```

**设计要点**：

- **严格错过不补**：若 9:00 时没有任何 http 页面开着，脚本不运行，当天不会触发。
- **epoch 认领机制**：解决"已有目标标签时不重复新开"的问题。触发页递增 epoch 后等 3 秒，目标标签的轮询会在 3 秒内检测到 epoch 变化、设 `claimedEpoch` 并自刷新；触发页看到 `claimedEpoch` 匹配则不新开标签。

### 4.2 目标页登录逻辑（仅 `网址` 运行）

```
页面加载时：
  loadedEpoch = GM_getValue('triggerEpoch')
  loadedTriggerDate = GM_getValue('lastTriggerDate')

  若 loadedTriggerDate === today:
    setTimeout(3秒):
      attemptLogin()  // 带 10 次重试，每次间隔 500ms

  setInterval(3秒):
    若 lastTriggerDate === today 且 triggerEpoch !== loadedEpoch:
      GM_setValue('claimedEpoch', currentEpoch)  // 认领
      location.reload()  // 自刷新

attemptLogin():
  fillLogin() 失败则 500ms 后重试，最多 10 次

fillLogin():
  1. 取 #loginScreen
  2. 若不存在 → 返回失败
  3. 若 #loginScreen 有 hidden class → 已登录，返回成功（跳过）
  4. 取 #loginUsername、#loginPassword、#loginScreen .login-box button
  5. 若任一不存在 → 返回失败
  6. 填入用户名密码 + dispatch input/change 事件
  7. click 登录按钮
  8. 返回成功
```

**设计要点**：

- **3 秒等待**：让页面的 `app.js` 先执行完，若 app.js 自动恢复了会话（`#loginScreen` 被 hidden），则跳过填表；否则在 3 秒后填表登录。
- **已登录跳过**：若 `#loginScreen` 已隐藏，说明已登录（可能 app.js 自动恢复、或之前已登录），不做事。
- **自刷新防循环**：`location.reload()` 后页面重新加载，`loadedEpoch` 重新求值为当前 epoch，轮询条件 `triggerEpoch !== loadedEpoch` 不再成立，不会再次刷新。
- **带重试的 DOM 等待**：登录表单可能异步渲染，`fillLogin()` 失败时 500ms 重试，最多 10 次（共 5 秒）。

### 4.3 登录表单选择器

依据 `page_source.txt` 第 1035-1041 行的登录表单 HTML：

```html
<div id="loginScreen" class="screen">
  <div class="login-box">
    <input type="text" id="loginUsername" placeholder="Username" autocomplete="off">
    <input type="password" id="loginPassword" placeholder="Password" autocomplete="off"
           onkeypress="if(event.key==='Enter') login()">
    <button onclick="login()">Login</button>
  </div>
</div>
```

| 元素 | 选择器 | 说明 |
|------|--------|------|
| 登录界面容器 | `#loginScreen` | 有 `hidden` class 表示已登录/隐藏 |
| 用户名输入框 | `#loginUsername` | id 级选择器，最稳定 |
| 密码输入框 | `#loginPassword` | id 级选择器，最稳定 |
| 登录按钮 | `#loginScreen .login-box button` | 容器内唯一 button |

登录框**页面加载即显示**（无 `hidden` class），`location.reload()` 天然能让它重新出现。页面的 `login()` 函数（在 `app.js` 中定义）由按钮 `onclick` 触发，脚本只需 `.click()` 登录按钮即可调用。

## 5. 油猴菜单命令

| 菜单项 | 行为 |
|--------|------|
| `⏰ 设置触发时间` | `prompt` 输入 `HH:MM`；保存后清除今日触发状态，让新时间立即生效 |
| `🧪 立即测试触发` | `confirm` 确认后直接调用 `doTrigger()`（绕过周末和时间检查）；会标记今日已触发 |
| `🔄 重置今日触发状态` | `GM_deleteValue('lastTriggerDate')`；测试后用此恢复，让真实触发重新生效 |

## 6. 配置

脚本顶部 `CONFIG` 对象（安装前手动修改）：

```javascript
const CONFIG = {
    targetUrl:   '网址',
    triggerTime: '09:00',          // 默认触发时间，可被菜单覆盖
    username:    'YOUR_USERNAME',  // ← 安装前填入
    password:    'YOUR_PASSWORD',  // ← 安装前填入
};
```

> **安全提示**：凭据以明文写在脚本源码中，安装脚本时可见。请勿将含真实凭据的脚本分享给他人。

## 8. 安装与使用

### 8.1 安装

1. 浏览器安装 Tampermonkey 扩展（Chrome / Edge）
2. 用文本编辑器打开 `auto_login_notice.user.js`
3. 修改 `CONFIG` 中的 `username` 和 `password` 为你的真实凭据
4. 将修改后的脚本内容粘贴到 Tampermonkey 的「新建脚本」编辑器中并保存

### 8.2 脚本注入时机（重要）

油猴脚本在**页面加载时**注入，不是后台常驻。理解这一点能避免很多使用误区：

| 场景 | 脚本是否注入 |
|------|-------------|
| 安装脚本后**新打开**的 http(s) 页面 | ✅ 注入 |
| 安装脚本前已打开的页面，**不刷新** | ❌ 不注入 |
| 安装脚本前已打开的页面，**按 F5 刷新一次** | ✅ 注入 |
| `edge://newtab`、`chrome://` 等浏览器内部页面 | ❌ 永不注入 |
| 浏览器扩展页面（`chrome-extension://`） | ❌ 永不注入 |

**安装脚本后的必要操作**：对之前已经打开的所有标签页按 F5 刷新一次，脚本才会注入并开始工作。之后新开的页面会自动注入。

**菜单命令的显示位置**：`GM_registerMenuCommand` 注册的命令（`⏰ 设置触发时间` / `🧪 立即测试触发` / `🔄 重置今日触发状态`）出现在 Tampermonkey 弹出菜单的**顶部**，作为独立菜单项——不是在脚本分组下方（分组下方只有 `Edit` / `Delete` 这种脚本管理操作）。**这些菜单命令只在脚本已注入的页面上显示**，在 `edge://newtab` 等不注入脚本的页面上看不到。

### 8.3 日常使用

- **保证 9:00 前有页面常驻**：上班时打开任意普通网页（如百度）并保持标签不关
- **脚本自动工作**：9:00 时脚本会自动打开/刷新目标页并填入凭据登录
- **周末不触发**：周六周日自动跳过

### 8.4 测试

1. 在任意 http(s) 网页（如 `https://www.baidu.com`）上点击 Tampermonkey 图标
   - 不要在 `edge://newtab` 或浏览器内部页面上操作（脚本未注入，菜单不会出现）
   - 若菜单顶部看不到命令，按 F5 刷新当前页面再点 Tampermonkey 图标
2. 点击弹出菜单顶部的「🧪 立即测试触发」→ 确认后会立即打开/刷新目标页并尝试登录
3. 测试完成后点击「🔄 重置今日触发状态」可恢复当天的自动触发

### 8.5 修改触发时间

点击 Tampermonkey 图标 → 「⏰ 设置触发时间」→ 输入 `HH:MM` 格式的时间（如 `08:30`）。

## 9. 已知限制

1. **必须有页面常驻**：9:00 时浏览器没有已注入脚本的 http 页面开着则不会触发（错过不补）。注意：安装脚本前已打开的页面需 F5 刷新一次才会注入脚本
2. **仅跳过周末**：不判定法定节假日和调休补班（无可靠的节假日 API）
3. **凭据明文存储**：密码以明文写在脚本源码中
4. **无法枚举/控制其他标签**：油猴脚本不能列出或关闭其他标签，依赖 epoch 认领机制间接协调
5. **3 秒认领窗口的边缘情况**：若目标标签响应慢（>3 秒），可能既刷新了旧标签又新开了一个；多余的标签需手动关闭
