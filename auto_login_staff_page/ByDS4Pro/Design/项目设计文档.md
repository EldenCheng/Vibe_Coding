# 员工通知网页自动登录助手 — 设计文档

## 1. 项目概述

油猴（Tampermonkey）用户脚本，实现**工作日 9:00 自动打开公司内网员工通知网页并完成登录**。

## 2. 需求

- 每天 9:00 自动打开 `网址`
- 仅工作日（周一至周五）触发
- 如果已有标签页在该网址上，强制刷新弹出登录框
- 自动填入用户名密码并点击登录
- 当天只触发一次，错过不补
- 触发时间可配置（方便测试）

## 3. 架构设计

### 3.1 运行环境

- Tampermonkey 4.0+（Chrome / Edge）
- 匹配规则：`*://*/*`（所有网页）

### 3.2 模块划分

| 模块 | 函数/常量 | 职责 |
|------|-----------|------|
| 排程器 | `schedule()` | 计算距下次触发时间的毫秒数，用 `setTimeout` 一次性定时（主力） |
| 兜底检查 | `startPeriodicCheck()` | 每 30 秒轮检查（保险，防止后台标签节流失效） |
| 触发器 | `doTrigger()` | 跨标签防重复 → 执行跳转或刷新 |
| 自动登录 | `autoLogin()` | MutationObserver 监听登录表单，出现即填入凭据并触发登录 |
| 登录触发 | `tryLoginNow()` | 依次尝试 `window.login()` → `btn.click()` → `dispatchEvent` → 密码框 Enter |
| 按钮选择器 | `LOGIN_BTN_SEL` | 使用 `#loginScreen button` 精准锁定 Login 按钮，排除前面 4 个 toggle 按钮 |
| 工具 | `isTargetPage()` | 判断当前标签页是否已在目标 URL |
| 工具 | `isTriggerTime()` | 判断当前小时分钟是否匹配触发时间 |
| 工具 | `isWeekend()` | 判断今天是否周末 |
| 工具 | `msToNextWeekdayTrigger()` | 计算到下一个工作日触发时间的毫秒数 |

### 3.3 执行流程

```
页面加载
  ├─ autoLogin() —— 如果已是目标页面，等登录表单出现后自动填写
  ├─ schedule()
  │    ├─ 已过 9:00 或 周末 → setTimeout 到下个工作日 9:00
  │    └─ 未到 9:00 → setTimeout 到今天 9:00
  │                        │
  │                        ▼
  │                   doTrigger()
  │                     ├─ 今天已触发过? → return
  │                     ├─ 周末? → return
  │                     ├─ 标记今天已触发
  │                     ├─ 已在目标页面 → location.reload()
  │                     └─ 不在目标页面 → location.href = TARGET_URL
  │
  └─ startPeriodicCheck()
       └─ setInterval(30 秒)
            └─ 是触发时间 && 工作日? → doTrigger()（兜底）
```

页面加载（目标页面）时也会运行一次 `autoLogin()`，保障手动打开页面时也能自动登录。

## 4. 关键设计决策

### 4.1 定时方式

- **双保险机制**：
  - **主力**：`schedule()` 每次页面加载时计算 `setTimeout` 精确到 9:00:00 触发
  - **兜底**：`startPeriodicCheck()` 每 30 秒检查一次时间，防止后台标签页节流导致 `setTimeout` 延迟或丢失
- `setInterval` 仅做时间比较 + `GM_getValue` 读取，无 DOM 操作，CPU/内存开销极低
- 页面被导航或关闭后，新页面加载时重新启动两种定时。

### 4.2 跨标签防重复

- 使用 `GM_getValue('lastTriggerDate')` 存储当天触发标记。
- 多个标签页到点后都会触发 `doTrigger()`，但只有第一个能成功标记当天已触发。
- 标记写入后才执行跳转/刷新，避免竞争条件。

### 4.3 登录表单检测与提交

- `MutationObserver` 监听 `document.body` 的 DOM 变化，等待 `#loginUsername` 和 `#loginPassword` 出现。
- 填入凭据后，依次尝试以下方式触发登录（任一成功即停，按可靠性排序）：
  1. `window.login()`—— 直接调用页面暴露的登录函数（最可靠）
  2. `btn.click()`—— 原生按钮点击
  3. `dispatchEvent(new MouseEvent('click', ...))`—— React/Vue 框架兼容
  4. 密码框模拟 Enter —— 利用 `onkeypress` 处理器
- 填入后触发 `input` 事件让前端框架感知值变化。
- 15 秒超时，避免无限等待。

## 6. 使用说明

### 安装

1. 在 Tampermonkey 中新建脚本
2. 粘贴 `通知网页自动登录助手.user.js` 全部内容
3. 保存（Ctrl+S）

### 修改配置

脚本顶部 `配置区` 中修改以下常量：

```javascript
const TRIGGER_HOUR      = 9;    // 触发小时（测试时改为当前小时）
const TRIGGER_MINUTE    = 0;    // 触发分钟（测试时改为 1 分钟后）
const USERNAME          = 'elden.zheng';
const PASSWORD          = 'password';
```

### 测试

1. 将 `TRIGGER_HOUR` 和 `TRIGGER_MINUTE` 改为当前时间 1 分钟后
2. 打开一个任意网页（如 `baidu.com`）
3. 等待 1 分钟，观察是否自动跳转到目标网址并自动填入登录信息
4. 测试恢复：改回 `9` 和 `0` 即可

## 7. 限制

- 需要浏览器在 9:00 时处于打开状态（至少一个标签页）
- 内网 `网址` 需在用户网络可达范围内
- 脚本仅自动填写凭据，不处理登录失败（密码错误、账户锁定等）的情况
