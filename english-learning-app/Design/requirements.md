# Requirements Document

## Introduction

This document defines the requirements for an interactive English learning web application designed for children in mainland China. The application generates AI-powered images, asks age-appropriate discussion questions in English, records the child's spoken answers, evaluates responses using an AI model, and produces a concise performance report. The system supports multiple child profiles across multiple devices, persists learning history, and is configured to use Google Gemini as the primary AI provider with Firebase Firestore for data synchronization.

---

## Glossary

- **App**: The interactive English learning web application described in this document.
- **User**: The parent or guardian who configures the App and manages child profiles.
- **Child**: The learner who interacts with the App to practice English.
- **Profile**: A named account representing one child, storing their grade level and learning history.
- **Session**: One complete learning unit consisting of image generation, three question-answer cycles, and a final report.
- **Round**: One question-answer cycle within a Session (there are three Rounds per Session).
- **Grade_Level**: One of three age-based learning tiers — Primary (ages 10–12), Junior (ages 13–15), or Senior (ages 16–18).
- **AI_Provider**: The external AI service used for image generation, question generation, speech evaluation, and report generation. Default provider is Google Gemini.
- **TTS_Engine**: The text-to-speech component that reads English text aloud. Implemented using the browser's built-in Web Speech API.
- **ASR_Engine**: The automatic speech recognition component that converts the child's spoken answer into text. Implemented using the browser's built-in Web Speech API.
- **Evaluator**: The AI_Provider function that scores a child's answer across four dimensions.
- **Config_File**: A user-editable configuration file that specifies the AI_Provider, API keys, model names, and application settings.
- **Score**: A numeric rating on a scale of 0–100 for a single evaluation dimension.
- **Report**: A concise AI-generated summary of a child's performance across all three Rounds in a Session.
- **Firebase**: Google Firebase platform used for cloud data storage and multi-device synchronization.

## Requirements

### Requirement 1: Child Profile Management

**User Story:** As a parent, I want to create and manage profiles for each of my children, so that each child's learning records are kept separate and accessible from any device.

#### Acceptance Criteria

1. THE App SHALL allow the User to create a Profile with a name and a Grade_Level.
2. THE App SHALL allow the User to edit the name and Grade_Level of an existing Profile.
3. THE App SHALL allow the User to delete a Profile along with all associated Session history.
4. WHEN the App is opened, THE App SHALL display all existing Profiles and allow the User to select one before starting a Session.
5. THE App SHALL store all Profile data and Session history in Firebase so that it is accessible from multiple devices.
6. IF a Profile name is empty or contains only whitespace, THEN THE App SHALL reject the input and display an error message.

---

### Requirement 2: Session Initialization

**User Story:** As a child, I want the App to start a new learning session by generating a picture and the first question, so that I have something to talk about in English.

#### Acceptance Criteria

1. WHEN a Child selects a Profile and starts a new Session, THE App SHALL send a request to the AI_Provider to generate an age-appropriate image based on the Profile's Grade_Level.
2. WHEN the AI_Provider returns an image, THE App SHALL display the image prominently on the screen.
3. WHEN an image is displayed on the screen, THE App SHALL send a request to the AI_Provider to generate the first question for Round 1, based on the image content and the Profile's Grade_Level, regardless of whether the image was generated by the AI_Provider or is a fallback.
4. THE App SHALL display the generated question as text on the screen alongside the image.
5. IF the AI_Provider fails to generate an image or a question, THEN THE App SHALL always display a user-friendly error message and offer the option to retry, even when the retry option is available.

---

### Requirement 3: Age-Appropriate Content Generation

**User Story:** As a parent, I want the image and questions to be appropriate for my child's age and English level, so that the content is neither too easy nor too difficult.

#### Acceptance Criteria

1. WHEN generating an image, THE AI_Provider SHALL produce content that is visually simple and thematically appropriate for the specified Grade_Level.
2. WHEN generating questions for a Profile with Grade_Level Primary, THE App SHALL instruct the AI_Provider to produce questions that have a clear, factual answer (e.g., "Where is the animal?").
3. WHEN generating questions for a Profile with Grade_Level Junior, THE App SHALL instruct the AI_Provider to produce open-ended guiding questions (e.g., "This is a zoo, could you tell me what is in it?").
4. WHEN generating questions for a Profile with Grade_Level Senior, THE App SHALL instruct the AI_Provider to produce reflective or analytical questions that require personal thought (e.g., "What do you feel if you were at this zoo?").
5. THE App SHALL use the average English proficiency of mainland China students as the baseline when setting vocabulary complexity, sentence structure difficulty, and answer length expectations for each Grade_Level.
6. WHEN generating Round 2 or Round 3 questions, THE AI_Provider SHALL produce questions that are thematically connected to the same image and to the previous questions in the Session.

---

### Requirement 4: Text-to-Speech Playback

**User Story:** As a child, I want to hear the question read aloud when I tap the speaker button, so that I can understand the pronunciation.

#### Acceptance Criteria

1. THE App SHALL display a speaker icon button adjacent to each question.
2. WHEN the Child taps the speaker icon, THE TTS_Engine SHALL read the question text aloud in English.
3. WHEN the TTS_Engine starts speaking from the default state, THE App SHALL visually indicate that audio is playing (e.g., animated icon).
4. WHEN the TTS_Engine finishes speaking, THE App SHALL return the speaker icon to its default state.
5. IF the TTS_Engine fails to produce audio, THEN THE App SHALL display a notification indicating that audio playback is unavailable.
6. WHEN the Child taps the speaker icon while the TTS_Engine is already speaking, THE App SHALL interrupt the current playback, begin the new playback, and restart the visual indication cycle.

---

### Requirement 5: Speech Recording and Recognition

**User Story:** As a child, I want to record my spoken English answer using a button, so that the App can hear what I said.

#### Acceptance Criteria

1. THE App SHALL display a prominent record button on the screen during each Round.
2. WHEN the Child presses the record button, THE ASR_Engine SHALL begin capturing audio from the device microphone.
3. WHILE the ASR_Engine is recording, THE App SHALL display a visual recording indicator (e.g., pulsing animation or waveform).
4. WHEN the Child releases or taps the record button to stop, THE ASR_Engine SHALL process the captured audio and convert it to text.
5. THE App SHALL display the transcribed text on screen so the Child can see what was recognized.
6. IF the ASR_Engine fails to recognize any speech or the microphone is unavailable, THEN THE App SHALL display an error message and allow the Child to attempt recording again.
7. IF the transcribed text is empty after recording ends without a technical failure, THEN THE App SHALL prompt the Child to try again without displaying an error message.

---

### Requirement 6: Answer Evaluation

**User Story:** As a child, I want the App to score my answer across multiple dimensions, so that I know what areas need improvement.

#### Acceptance Criteria

1. WHEN the ASR_Engine produces a non-empty transcription, THE App SHALL send the transcribed answer, the question, the image description, and the Profile's Grade_Level to the Evaluator.
2. THE Evaluator SHALL return a Score (0–100) for each of the following four dimensions:
   - **Vocabulary Accuracy**: whether the words used are appropriate and correctly applied.
   - **Pronunciation Accuracy**: how accurately the spoken words were pronounced, inferred from the ASR transcription quality and phonetic patterns.
   - **Grammar Correctness**: whether the sentence structure is grammatically correct, with stricter criteria applied for Junior and Senior Grade_Levels.
   - **Answer Relevance**: whether the answer addresses the question and image content, with stricter criteria applied for Junior and Senior Grade_Levels.
3. THE App SHALL display all four dimension Scores to the Child after each Round.
4. IF the Evaluator returns an error or incomplete Scores, THEN THE App SHALL display the available Scores and indicate that some dimensions could not be evaluated.

---

### Requirement 7: Encouragement Before Next Round

**User Story:** As a child, I want to receive encouragement after each answer regardless of my score, so that I stay motivated to continue.

#### Acceptance Criteria

1. AFTER displaying the Scores for a Round, THE App SHALL display an AI-generated encouragement message addressed to the Child.
2. THE AI_Provider SHALL generate the encouragement message in a warm, child-friendly tone regardless of the Scores received.
3. WHEN Round 1 or Round 2 is complete, THE App SHALL automatically proceed to the next Round after showing the encouragement message and Scores.
4. THE App SHALL NOT allow the Session to end before all three Rounds are completed, unless the User explicitly cancels.

---

### Requirement 8: Final Session Report

**User Story:** As a parent or child, I want to see a concise summary report after all three questions are answered, so that I understand the child's overall performance in the session.

#### Acceptance Criteria

1. WHEN all three Rounds in a Session are complete, THE App SHALL send all three questions, all three transcribed answers, and all individual Scores to the AI_Provider to generate a Report.
2. THE Report SHALL include an overall composite Score (0–100) derived from all dimension Scores across all three Rounds.
3. THE Report SHALL include a brief written analysis (no more than 150 words) identifying the main strengths and areas for improvement observed across the Child's three answers.
4. THE App SHALL display the Report in a clear, readable format on a dedicated summary screen.
5. THE App SHALL save the completed Session (including image description, questions, answers, individual Scores, and Report) to the Child's Profile in Firebase.
6. IF the AI_Provider fails to generate a Report, THEN THE App SHALL display the individual Round Scores and a message indicating the summary could not be generated, and SHALL still save the available data.

---

### Requirement 9: Learning History

**User Story:** As a parent, I want to review my child's past sessions and track their progress over time, so that I can see how they are improving.

#### Acceptance Criteria

1. THE App SHALL provide a history screen accessible from a Profile's home page.
2. THE App SHALL display a chronological list of past Sessions for the selected Profile, showing the session date and overall composite Score.
3. WHEN the User selects a past Session from the history list, THE App SHALL display the full Session details including all questions, transcribed answers, dimension Scores, and the Report.
4. THE App SHALL store all Session data in Firebase so that history is available on any device logged in with the same User account.
5. WHILE the App is displaying history data that has not yet fully loaded from Firebase, THE App SHALL display a loading indicator and SHALL NOT display partial history data until all data for the selected Profile has loaded.

---

### Requirement 10: Configuration File

**User Story:** As a user, I want to configure the AI provider and model settings through a configuration file, so that I can switch providers or update API keys without modifying the application code.

#### Acceptance Criteria

1. THE App SHALL read AI provider settings from a Config_File at application startup.
2. THE Config_File SHALL specify, at minimum: the AI_Provider name, the API key, the image generation model name, the text generation model name, and the TTS language/voice setting.
3. WHEN valid settings are present in the Config_File, THE App SHALL use those settings for all AI requests in the Session.
4. IF the Config_File is missing or contains invalid values, THEN THE App SHALL display a clear configuration error message on startup and SHALL NOT proceed to the main application until the issue is resolved.
5. THE App SHALL support switching to an alternative AI_Provider by updating the Config_File without requiring code changes, provided the alternative provider supports the same capabilities (image generation, text generation).

---

### Requirement 11: UI Responsiveness and Accessibility

**User Story:** As a child using a tablet, phone, or desktop browser, I want the interface to be clear and easy to use, so that I can focus on learning English rather than figuring out the app.

#### Acceptance Criteria

1. THE App SHALL function correctly on modern versions of Chrome, Firefox, Edge, and Safari browsers.
2. THE App SHALL render correctly on screen widths from 375px (mobile) to 1440px (desktop) using a responsive layout.
3. THE App SHALL use a font size of at least 16px for question text and button labels to ensure readability for children.
4. THE App SHALL provide sufficient color contrast between text and background, meeting WCAG 2.1 AA contrast ratio requirements.
5. THE App SHALL present interface elements (buttons, question text, image, score display) in a single, uncluttered layout that does not require the user to scroll during an active Round, except on very small screens where scrolling is permitted to maintain minimum readable element sizes.
