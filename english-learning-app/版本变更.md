## v0.2.7 — 2026-09-15 — STT 连续录音（停顿不断开 + 追加续录 + 清空重说）

- **背景（用户实测反馈）**：学生答复杂题（L2-L4 长答案）说话中间要想一会儿，但 STT 停顿 ~1s 即自动结束；再点录音新结果**覆盖**已录文本，复杂题无法一气呵成。根因：`asrService` 写死 `continuous=false`（Web Speech API 无静音容忍参数可调）+ `onResult` 整体替换文本
- **用户决策（详见 `讨论记录.md`）**：① 停止后再录音为**追加** + 配"🗑 清空重说"按钮（否决"无按钮纯追加"与"保持覆盖"）；② 录音中**实时上屏**（否决"结束才出文本"）
- **变更 `src/speech/asrService.ts`（核心重写）**：
  - `continuous: true` + `interimResults: true`：停顿=思考时间；仅 `isFinal` 段落累计入 `finalBase`，interim 仅用于实时显示
  - **自动重启续录**：浏览器自发 `onend`（长静音/网络抖动）时，用户未按停止（`shouldListen` 意图标记）则 250ms 后自动重启，`finalBase` 跨重启保留；连续失败 5 次才报错（成功识别即重置计数）；`not-allowed` 等致命错误不重启；旧实例回调以 `recognition !== rec` 守卫忽略，避免 abort 旧会话误触发重启
  - 新回调 `onSessionEnd({transcript, hasText})`：会话真正结束后触发（用户停止 / 重启耗尽）；`onEmptyResult/onError` 保留兼容（deprecated 旧 hook 仍可编译运行）
  - 修复边界：重启等待窗口内按停止 → `sessionActive` 标记判别无活跃会话，直接结算（否则旧实例 `stop()` 无 onend，UI 永卡 Transcribing）；`start()` 抛异常时同样走重启路径
- **变更 `src/demo/usePresetSession.ts`**：`startRecording` 快照文本框内容（`sessionBaseRef`）；`onResult` 显示 = 快照 + 会话累计（英文空格连接），录音中只更新文本不切状态；`onSessionEnd` 接管状态切换（有文本 → `ShowingTranscript`；无文本有旧文 → 直接回 `ShowingTranscript`；全空 → 重试提示）；不再注册 `onEmptyResult`；新增 `clearTranscript()`
- **变更 `src/components/AnswerEditor.tsx` + `App.css`**："🗑 清空重说 / Clear" 按钮（有内容且非录音/转换中显示）；提示改"停顿没关系，想好继续说；再次录音会接在后面"
- **兼容性**：Safari/iPad 对 continuous/interim 支持不全（只出最终文本），自动重启机制仍生效，退化为"停顿后自动续录"
- **文档**：`项目设计文档.md` §8 重写 ASR 机制、§13/§15 同步；`运行教程.md` §6/FAQ；`README.md`；新增项目级 **`讨论记录.md`**（回填 v0.1.0 起关键决策，最新在前；AGENTS.md 已登记维护惯例）
- **验证**：`tsc -b` 0 errors, `vite build` success (265kB / gzip 80.4kB)。运行时建议：Chrome 答 L2/L3 长题中途停 3-5s 确认不断开；停止→再录确认追加；清空重说；重启等待窗口内急停不卡死

  - 产物：`certs/localhost.pem`（站点证书）、`certs/localhost-key.pem`（站点私钥）、`certs/rootCA.pem`（待分发公钥）
