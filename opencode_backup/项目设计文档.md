# opencode 数据备份脚本 — 项目设计文档

## 一、项目概述

本项目提供一个小工具 `backup_opencode.py`,用于备份本机 opencode 的核心数据:

- **数据库** `opencode.db`(包含全部会话 session 记录)
- **配置文件** `opencode.jsonc`
- **日志目录** `log/`
- **快照目录** `snapshot/`

脚本自动探测 opencode 的数据目录与配置目录,按数据类型分别压缩,并放入备份根目录下**以日期命名**的子目录中,便于按天留存历史备份。

## 二、目录结构

```
opencode_backup\
├── backup_opencode.py       # 主脚本
├── 项目设计文档.md           # 本文件
├── 版本变更.md              # 版本变更记录
├── 讨论记录.md              # 开发过程讨论记录
└── backups\                 # 备份根目录
    └── YYYY-MM-DD\          # 以日期命名的备份目录
        ├── opencode.db.7z       # 数据库(含 session 记录)
        ├── opencode.jsonc.7z    # 配置文件
        ├── log.7z               # 日志目录
        └── snapshot.7z          # 快照目录
```

> 注:当 7-Zip 不可用、脚本回退为 Python zipfile 打包时,压缩文件后缀为 `.zip`。

## 三、数据源探测

脚本按以下顺序探测 opencode 的目录(只使用实际存在的):

**数据目录**(特征:包含 `opencode.db`):

1. `%USERPROFILE%\.local\share\opencode`
2. `%LOCALAPPDATA%\opencode`
3. `%APPDATA%\opencode`

**配置目录**(特征:包含 `opencode.jsonc`):

1. `%USERPROFILE%\.config\opencode`
2. `%APPDATA%\opencode`

在本机实际探测结果为:

- 数据目录:`C:\Users\Elden\.local\share\opencode`
- 配置目录:`C:\Users\Elden\.config\opencode`

`%APPDATA%` 与 `%LOCALAPPDATA%` 下的目录当前不存在,仅作兜底探测。

## 四、备份分类与流程

### 4.1 备份分类

| 类别 | 来源 | 备份内容 | 压缩包 |
| ---- | ---- | -------- | ------ |
| 数据库 | 数据目录 | `opencode.db`(一致性副本,已合并 WAL) | `opencode.db.7z` |
| 配置 | 配置目录 | `opencode.jsonc` | `opencode.jsonc.7z` |
| 日志 | 数据目录 | `log/` 整个目录 | `log.7z` |
| 快照 | 数据目录 | `snapshot/` 整个目录 | `snapshot.7z` |

**不纳入备份的内容及原因:**

- `auth.json` — 包含 API 密钥等敏感凭证,泄露风险大
- `storage/`、`tool-output/`、`repos/` — 当前几乎为空
- 配置目录下的 `node_modules/`、`package.json` 等 — 插件依赖,可随时重装

### 4.2 数据库一致性处理

`opencode.db` 是 SQLite(WAL 模式)。如果直接复制文件,而备份时 opencode 正在运行,
可能得到不一致的快照。

因此脚本使用 Python `sqlite3` 的 **在线备份 API**(`Connection.backup()`)：

1. 以只读方式打开源库,读取时会自动包含 `-wal` 中尚未落盘的内容;
2. 将合并后的数据写入一个临时一致副本(此过程对运行中的 opencode 安全);
3. 对临时副本进行压缩。

若在线备份失败(例如数据库损坏或被独占),脚本会给出提示并回退为直接复制原始文件,
同时明确警告该副本可能不一致,建议关闭 opencode 后重新备份。

### 4.3 压缩策略

- **优先使用 7-Zip**(`C:\Program Files\7-Zip\7z.exe`),压缩率高;
- 7-Zip 找不到时,自动回退 Python 标准库 `zipfile` 打包为 `.zip`;
- 压缩时工作目录定位到源文件所在目录,保证压缩包内只含裸文件名或相对目录,
  不含无关的绝对路径层级;
- **运行中 opencode 可能锁定 `log/opencode.log`**,导致 7-Zip 读取失败并自动回退
  zipfile(zipfile 对该文件采用共享读,通常仍能成功打包,故 `log` 类别常为 `.zip`);
  回退时自动删除 7-Zip 产生的半成品归档,保证目录内每种数据只保留一个最新包;
- 同一天重复运行会先清理同名旧归档(含 `.7z` 与 `.zip`),再生成新包。

### 4.4 运行流程

1. 探测 7-Zip 工具;
2. 探测数据目录与配置目录,找不到则报错退出;
3. 创建当日备份目录 `backups\YYYY-MM-DD\`;
4. 依次处理每个类别:准备源 → 压缩 → 写入日期目录;
5. 同一天重复运行会**覆盖**同名的压缩包(保持幂等);
6. 打印每个类别的结果与耗时摘要。

### 4.5 保留策略

当前策略为**保留所有日期目录**,只增不删。磁盘占用由用户自行管理。

## 五、配置与运行说明

### 5.1 运行环境

- Python 3.x(标准库即可,无第三方依赖)
- 本机 python 命令为 `py`
- 可选:7-Zip(用于高压缩率打包)

### 5.2 运行方式

在项目目录下执行:

```
py backup_opencode.py
```

### 5.3 主要可调项(脚本顶部常量)

- `BACKUP_ROOT`:备份根目录,默认为本项目下的 `backups/`
- `SEVEN_ZIP_CANDIDATES`:7-Zip 可执行文件候选路径
- `DATA_DIR_CANDIDATES` / `CONFIG_DIR_CANDIDATES`:目录探测顺序

## 六、备份恢复指南

> 时间久了容易忘记怎么恢复,本章节按数据类型给出完整恢复步骤。
> 恢复操作的基本前提:**先关闭 opencode(退出所有 TUI 会话),再动手**。

### 6.1 恢复前的通用注意事项

1. **关闭 opencode**;
2. 恢复前建议先把当前数据手动改名留存(例如给 `opencode.db` 加 `.old` 后缀),
   作为二次保险,确认恢复无误后再删除;
3. 恢复完成后启动 opencode,发一条测试消息,确认会话记录正常读取。

### 6.2 数据库 `opencode.db`(含全部 session 记录)

- 数据目录:`C:\Users\Elden\.local\share\opencode`
- 步骤:
  1. 解压备份包 `opencode.db.7z`,得到一致性拷贝的 `opencode.db`;
  2. 用该文件**覆盖**数据目录中的 `opencode.db`;
  3. **务必删除**数据目录中残留的 `opencode.db-wal` 和 `opencode.db-shm`
     (备份时已通过 sqlite 在线备份 API 把 WAL 合并进主库,
     包内不含独立的 `-wal/-shm`;若残留旧 WAL 可能与恢复的库冲突);
  4. 启动 opencode,验证会话记录。

### 6.3 配置文件 `opencode.jsonc`

- 配置目录:`C:\Users\Elden\.config\opencode`
- 步骤:
  1. 解压备份包 `opencode.jsonc.7z`;
  2. 将 `opencode.jsonc` 复制/覆盖到配置目录;
  3. 重启 opencode 生效。

### 6.4 日志目录 `log/`(可选)

- 数据目录:`C:\Users\Elden\.local\share\opencode`
- 步骤:
  1. 解压备份包 `log.7z`;
  2. 将 `log/` 目录复制到数据目录下;
  3. 日志仅用于排查历史问题,不影响运行,可选恢复。

### 6.5 快照目录 `snapshot/`

- 数据目录:`C:\Users\Elden\.local\share\opencode`
- 步骤:
  1. 解压备份包 `snapshot.7z`;
  2. 将 `snapshot/` 目录复制到数据目录下;
  3. 用于恢复 LSP 等工具的会话状态。

## 七、注意事项

- 数据库 714MB 量级,在线复制 + 压缩需要数分钟,属正常现象;
- 备份过程中请勿手动删除正在写入的临时文件;
- 压缩包命名带日期,若某天多次运行,以最后一次为准;
- `auth.json` 不备份,若需迁移凭证请手动处理。
