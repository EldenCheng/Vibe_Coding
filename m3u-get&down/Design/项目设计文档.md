# m3u-get&down 项目设计文档

> 版本：v0.1.0（初始设计）
> 日期：2026-09-24
> 本文档是项目的唯一设计权威来源，设计变更时须先更新本文档。

## 1. 项目背景与目标

用户常在动画聚合网站看片，稀有资源随时可能失效，希望把正在播放的视频保存到本地。

技术路径：网页视频多为 HLS（m3u8）分发——服务器把视频切成小切片（.ts/.m4s），
播放器按清单顺序拉取拼接播放。本工具即围绕 m3u8 做"嗅探 → 下载 → 合并"。

## 2. 需求对照

| # | 需求 | 对应设计 |
|---|------|----------|
| 1 | 从播放页嗅探 m3u8 | `sniffer.py`（Playwright 有头浏览器网络监听） |
| 2 | 流式下载切片 + ffmpeg 自动合并 | `downloader.py` + `merger.py`（断点续传，长中断可恢复） |
| 3 | 直接下载被"版权限制"拒绝时模拟播放器缓存 | `player_capture.py`（被动捕获浏览器拉取的切片） |
| 4 | 更好的想法 | 请求头自动继承（见 §8）、三种入口、DRM 边界明确化 |

## 3. 已确认的关键决策（详见 讨论记录.md）

1. 下载引擎：**纯自研 Python**（requests + ThreadPoolExecutor），不封装外部下载工具
2. 嗅探形态：**有头浏览器**（用户可手动点播放/过验证）
3. 入口范围：**第一版三种入口全做**（sniff / get / play）
4. 第一版**不集成 yt-dlp**，作为二期候选
5. 加密边界：**支持 AES-128**；检测到 Widevine/FairPlay 真 DRM 时明确报错退出

## 5. 模块设计

### 5.1 config.py — 默认参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| DEFAULT_CONCURRENCY | 6 | 切片并发下载数（过高易被站点封禁） |
| RETRY_TIMES | 3 | 单切片重试次数 |
| TIMEOUT | (15, 60) | requests 超时（连接, 读取）秒 |
| OUTPUT_DIR | downloads | 相对当前目录的输出根目录 |
| FFMPEG_PATH | shutil.which | 系统安装的 ffmpeg |

### 5.2 utils.py — 通用工具

- `sanitize_name()`：Windows 文件名非法字符清洗（输出目录名用）
- `is_m3u8_url()` / `looks_like_segment()`：按 URL 后缀 + Content-Type 判定清单/切片

### 5.3 session.py — 请求会话与请求头继承

**背景**：多数"版权限制不能下载"实为服务器校验 Referer/UA/Cookie，
带上浏览器的请求头即可直接下载，因此请求头继承是本工具的隐形主力。

- `build_session()`：构造 requests.Session，设置 UA/Referer/Cookie/verify
- `headers_from_request()`：从 Playwright 抓到的浏览器请求头中挑选
  `user-agent / referer / origin / cookie` 四个关键字段
- `set_cookies_from_playwright()`：把浏览器 context cookies 灌入 requests 会话

### 5.4 parser.py — m3u8 解析（纯手写，无第三方 m3u8 库）

解析规则：
- **master 清单**：含 `#EXT-X-STREAM-INF`，提取 BANDWIDTH/RESOLUTION/CODECS 与变体 URI
- **media 清单**：`#EXTINF` + URI 成对；相对地址用 `urljoin(清单真实URL, uri)` 解析
- **加密标签**：`#EXT-X-KEY:METHOD=AES-128,URI="key",IV=0x...`
  - IV 缺省时按 HLS 规范用切片媒体序列号（16 字节大端）
  - 引号内含逗号的属性用小型状态机切分，不能简单 split(',')
- **fMP4**：`#EXT-X-MAP`（初始化段）单独记录，合并时排在首位
- **DRM 检测**（硬边界，命中即报错退出）：
  - KEYFORMAT 含 Widevine UUID `edef8ba9-...` 或 FairPlay `com.apple.streamingkeydelivery`
  - METHOD=SAMPLE-AES（无已知可解 KEYFORMAT 时视为疑似 DRM）

数据结构（dataclass）：`Key / Segment / Variant / Playlist`

`load_playlist()`：get/sniff 的高层入口——拉清单文本（以重定向后的最终 URL 为解析基准），
若是 master 自动选码率最高变体（可 `--quality worst` 或 `--variant-index N` 覆盖），
递归跟进直到 media 清单。

### 5.5 downloader.py — 并发下载 + 断点续传 + 解密

流程：
1. 建输出目录 `downloads/<安全标题>/segments/`，原始清单存为 `playlist.m3u8`
2. 去重下载所有 KEY 文件（16 字节）
3. `progress.json` 记录已完成切片（参考 e-download 的续传模式）：
   `{segments: {序号: {file, done, size}}, finished}`
   重跑同一命令时跳过已完成切片 → 支持"长时间下载中断后恢复"
4. ThreadPoolExecutor 并发下载（默认 6），单切片失败退避重试 3 次
5. 加密切片：AES-128-CBC 解密 + PKCS7 去填充（非标填充容错处理）
6. 全部成功后调用 merger 合并；任一切片最终失败则报错并提示重跑续传

### 5.6 merger.py — ffmpeg 合并

- concat demuxer：写 `filelist.txt`（`file 'segments/000000.ts'`），首次合并失败
  自动带 `-bsf:a aac_adtstoasc` 重试（TS→MP4 的 AAC 位流问题）
- 命令：`ffmpeg -y -f concat -safe 0 -i filelist.txt -c copy -avoid_negative_ts make_zero out.mp4`
- fMP4 场景把 init 段排在 filelist 首位
- 未找到 ffmpeg 时给出安装提示

### 5.7 sniffer.py — 有头浏览器嗅探

- Playwright 启动顺序：chromium → msedge 通道 → chrome 通道（本机未装内核时自动回退 Edge）
- `context.on("response")` 被动监听：URL 后缀 `.m3u8/.m3u` 或 Content-Type 含 `mpegurl` 即捕获，
  同时记录该请求的浏览器请求头（供下载继承）
- **线程模型**：Playwright 跑在子线程，主线程做交互（input 阻塞会冻结事件分发，
  导致候选列表不刷新，故拆线程 + queue 通信）
- 交互：候选实时打印，输入编号选择 / r 刷新 / q 退出；`--auto N` 供脚本化测试
- 选择后取 `context.cookies()` 一并交给下载会话

### 5.8 player_capture.py — 播放器兜底模式（三种入口之一）

适用：直接下载被拒（真 403/盗链校验复杂），但浏览器能正常播放。

原理：**不做请求改写，纯被动旁观**——`response.body()` 在监听器里取响应体落盘，
不干扰页面播放（比 route 拦截+fulfill 兼容性好，不会破坏站点的 CORS/流式逻辑）。

流程：
1. 有头浏览器打开播放页，监听所有响应
2. 捕获 m3u8 清单并解析 → 得到"期望切片集合"（URL→序号映射）
3. 浏览器播放过程中按 Content-Type/后缀捕获切片响应体，命中期望集合的立即写盘
4. `--speed N` 每 5 秒把 video 元素 playbackRate 调到 N（最高 16），拉快切片请求
5. 结束条件：全部捕获 / 浏览器关闭 / 超时 / Ctrl+C（用户看完即停）
6. 缺失切片用继承的请求头尝试直接补拉；补不齐则合并到首个断点为止
7. 最终走同一套 merger 合并

限制：耗时≈播放时长（倍速可缩短）；输入若是裸 m3u8 则生成本地 hls.js 页面代播（CORS 不保证成功）。

### 5.9 cli.py — 命令行入口（`py -m m3u_down`）

```
py -m m3u_down sniff <播放页URL>  [--auto N] [--no-download] [--max-wait 秒] [-o DIR]
                                  [--quality best|worst] [--variant-index N]
py -m m3u_down get   <m3u8直链>   [--referer U] [--user-agent U] [--cookie "k=v; ..."]
                                  [-o DIR] [--quality ...] [--variant-index N]
py -m m3u_down play  <播放页URL>  [--speed N] [--max-wait 秒] [-o DIR]
py -m m3u_down batch <列表页URL>  [--interval 秒] [--episodes "1-12,15"] [--yes] [--pick N]
                                  [-o DIR]
通用: [--concurrency N] [--proxy U] [--insecure/--no-insecure]
（CLI 未显式给出的参数回落到 config.json，再回落内置默认）

- `get`：直链 → load_playlist → downloader（全自动）
- `sniff`：嗅探 → 选择 → 自动继承请求头 → 下载（`--no-download` 仅嗅探）
- `play`：播放页 → 被动捕获 → 补拉缺失 → 合并

## 6. 输出目录结构

```
downloads/
└── <标题 sanitized>/
    ├── playlist.m3u8     # 原始清单存档
    ├── progress.json     # 续传进度
    ├── filelist.txt      # ffmpeg concat 列表
    ├── segments/         # 切片（000000.ts ...）
    └── output.mp4        # 成品
```

## 7. 边界与限制（v1.0 明确不支持）

1. **真 DRM（Widevine/FairPlay）**：密文切片无密钥不可解，检测到即报错（详见讨论记录）
2. **直播流（LIVE）**：EVENT/VOD 之外的场景暂不处理，列入二期
3. `#EXT-X-BYTERANGE` 切片：解析时警告，暂不实现
4. DASH（.mpd）：不适用本工具

## 8. 验证方案（不依赖真实站点）

1. **全链路**：ffmpeg lavfi 生成 5 个测试切片 → 明文版 + AES-128 加密版 + master 变体版
   三套本地 m3u8，`http.server` 起本地服务，CLI 逐一下载，ffprobe 校验产物时长
2. **续传**：下载中途 Ctrl+C 后重跑，验证跳过已完成切片
3. **嗅探**：本地测试页（自动 fetch m3u8），`sniff --auto 1 --no-download` 验证捕获与选择
4. **合并**：ffprobe 校验 output.mp4 时长/编码

## 9. 二期候选（不做进 v1）

- yt-dlp 作为首选尝试（命中支持的站点最快）
- 直播录制、DASH 支持、`#EXT-X-BYTERANGE`
- GUI 包装

## 10. v0.2.0 增补设计

### 10.1 统一配置 config.json（项目根目录）

- 加载顺序：内置默认 ← config.json ← CLI 显式参数（优先级递增）
- 首次运行若不存在则自动生成（含 `_readme` 说明键，加载时被忽略）
- 字段：`concurrency`（6）、`proxy`（空=不用，支持 http/socks5）、`retry_times`（3）、
  `retry_backoff`（2）、`timeout`（60，读超时；连接超时固定 15s）、`output_dir`、
  `download_interval`（60，batch 每集间隔）、`ffmpeg_path`（空=PATH 查找）、`insecure`（false）
- 代理同时作用于 requests 会话（`session.proxies`）与 Playwright 浏览器上下文
  （`browser.new_context(proxy=...)`），保证嗅探/下载路径一致；
  requests 走 socks5 需要 pysocks（已加入 requirements）

### 10.2 下载进度条（utils.render_progress，自写无依赖）

- 单行 `\r` 刷新：`[████████░░░░] 45.2% 162/358 | 96.8MB 6.2MB/s ETA 00:31`
- 百分比按切片数、字节数与速度按已完成切片累计，主线程更新（as_completed 回调）避免并发打印错乱
- downloader（get/sniff 路径）与 player_capture（捕获计数）均接入

### 10.3 batch 命令 — 列表页批量下载（batch.py）

流程：
1. **列表页解析（两级策略）**：requests+正则收集 `<a href+文本>`，空结果回退
   Playwright `page.content()` 收集 DOM；过滤同域 → 按"路径数字替换为 {d}"的模板分组
   取最大组 → 仅保留路径中含列表页 ID 数字 token 的链接（剔除其他番剧）→
   **按"集位"（路径末段数字）去重**——聚合站每条线路重复一份完整集表
   （`/p/{id}-{线路}-{集}/`，实测 youknow 为 26 线路 × 集表），同一集位按
   **线路号升序 > 带集数文本 > 页面序** 选取（线路1 是站点默认源），
   集名取该集位任一带集数文本的候选 → 自然排序
2. **简介抓取**：`description`（剧情，`html.unescape`）、`<h1>`/`<title>`（标题清洗）、
   `og:image`（容错：取最后一个 `http(s)://` 起始，修复站点拼接出畸形 URL 的情况）
3. **简介.md**（用户确认选 Markdown）：标题/封面链接/来源列表页/剧情简介/
   剧集清单表格（#、集名、链接、状态：待下载/完成/失败/未选择），状态随下载进度回写重写
4. **选集确认**：列出全部集数 → 回车全下 / 输入 `1-12,15` 选范围 / `q` 退出；
   `--yes` 跳过确认（脚本化）；`--episodes` 等价于预填范围
5. **逐集下载**：每集独立嗅探（浏览器自动选第 N 个候选，默认 1）→ 继承请求头下载；
   工作目录 `downloads/番剧名/_work/集名/`（含 segments/progress.json，集间隔离避免
   续传串台），成功后成品**扁平**移动为 `downloads/番剧名/集名.mp4` 并删除工作目录
6. **调度与容错**：`批量进度.json` 记录每集状态，已完成集（状态 done 且成品存在）自动
   跳过 → 中断后重跑同一命令续跑；单集失败标记后继续下一集，结束打印成功/失败/跳过汇总；
   每集之间 sleep `download_interval` 秒（默认 60，最后一集不等待）

### 10.4 v0.2.0 验证方案（增补）

1. 本地假列表页（含其他番剧干扰链接、同集重复、无文本链接）直接调用解析函数，
   验证过滤/去重/排序与选集范围解析、简介.md 生成
2. 真站 youknow.tv `batch --yes --episodes 1-2 --interval 5` 实测 2 集，
   验证简介生成、成品命名、间隔等待；重跑验证已完成集跳过
3. 修改 config.json `concurrency` 验证配置生效；代理留空验证不破坏现状

## 11. v0.3.0 设计（站点配置化 + failover + 完整性自检 + 单集后处理）

> 背景：youknow 全季 18 集实测通过，但暴露三类问题——① 解析规则按站硬编码，
> 换站（eacg.net）需重写；② 单集瞬时失败（CDN 超时/坏线路）只能等下次重跑；
> ③ 单集 get/sniff 无后处理（output.mp4 + 中间产物残留）。

### 11.1 站点配置层（新模块 sites.py + 项目根 sites/ 目录）

- `sites/` 目录每站一个 JSON 文件（如 `sites/youknow.json`、`sites/eacg.json`），
  内含 `_说明` 键充当注释；`sites.py` 按播放页/列表页域名后缀匹配加载。
- 配置字段（全部可选，缺省回退通用引擎行为）：
  | 字段 | 作用 | 示例 |
  |---|---|---|
  | `domains` | 域名匹配列表 | `["eacg.net"]` |
  | `play_pattern` | 播放页 URL 正则（命中才认为是剧集页） | `/vodplay/(\d+)-(\d+)-(\d+)\.html` |
  | `group` | 正则分组语义：id/line/ep 的组号 | `{"id":1,"line":2,"ep":3}` |
  | `line_preference` | `line_asc`（线路号小者优先，youknow）或 `complete_first`（集数最多且集名序号与集位一致的线路优先，eacg——其线路1集表残缺） | `"complete_first"` |
  | `label_strip` | 集名尾部噪声正则 | `"完结$"` |
  | `title_subs` | 单集成品命名用的标题替换规则 [正则, 替换] 列表 | `[["^正在播放",""],["《",""]]` |
  | `desc_prefix` / `desc_suffix` | 简介前后噪声正则（剥离） | `"^.*?剧情[:：]\\s*"` / `"\\s*\\|.*$"` |
  | `failover_max` | 单集最多尝试线路数（默认 3） | `3` |
- **解析主流程不变**（模板分组 + ID 过滤 + 集位去重 + 自然排序），站点配置做精修：
  1. 配置了 `play_pattern` 时：只收命中正则的链接，集位/线路号直接取分组，
     跳过模板分组启发式
  2. 同集位去重的排序键由 `line_preference` 决定（默认仍为 线路号升序 >
     带集数文本 > 页面序）
  3. `complete_first` 先对每条线路打分（集表条数、集名序号与集位一致数），
     分高者先；eacg 线路1（11 条、4 处错位）输给线路2（12/12 一致）
- 每个 Episode 除主 URL 外保留**按偏好排序的备选线路列表 `alts`**，供 failover 使用。
- 未匹配域名的站点：行为与 v0.2.0 完全一致（通用引擎兜底，仅无标题/简介清洗精修）。

### 11.2 batch 单集 failover（换线路重试）

- `_download_episode` 改为按 `[主URL] + alts[:failover_max-1]` 顺序尝试：
  嗅探失败 / 清单加载失败 / 切片下载失败 → 清空该集工作目录 → 换下一条线路重试；
  全部候选失败才标记该集 failed。
- 每次换线打印 `[批量] 换线重试: <url>`；同一集的多线路尝试共享集名/成品名。
- 已下载切片按"集+线路"隔离：换线时清空工作目录，避免不同清单的进度串台。

### 11.3 下载完整性自检

- **续跑校验**：progress.json 已存每片实际字节数；续跑时文件存在但大小与记录不符
  → 视为未完成自动重下（防截断片混入合并）。
- **下载校验**：响应带 Content-Length 且与实际字节数不符 → 按失败重试。
- **合并校验**：merge 成功后用 ffprobe（与 ffmpeg 同目录或 PATH）验证：
  时长 > 0 且含视频流（音频缺失仅告警）。校验失败 → 删除坏成品、保留切片现场、
  抛错（batch 按单集失败处理，重跑续传）。

### 11.4 单集后处理（get / sniff / play 与 batch 对齐）

- 新增 CLI 公共参数 `--keep`（保留工作目录与中间产物，即 v0.2.0 及以前的行为）。
- 默认（不带 `--keep`）在合并成功后：
  1. **命名**：sniff/play 有页面标题时，按站点配置 `title_subs` 清洗
     （如"正在播放《X》第01集[日本动漫] - YouKnowTV在线视频" → "X 第01集"），
     无站点配置则用整页标题；get 纯直链无标题 → 维持 output.mp4
  2. **扁平**：成品移动为 `downloads/<清洗名>.mp4`（与 output.mp4 不同名时），删除原工作目录
  3. **清理**：segments/、filelist.txt、playlist.m3u8、progress.json 一并删除
- 只在合并成功后执行；中断续传不受影响（progress.json 保留到成功为止）。
